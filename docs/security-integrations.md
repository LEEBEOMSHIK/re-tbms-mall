# 보안·개인정보·외부 연동 검토 v0.3

운영 국가·판매 형태·결제는 미정이다. 대한민국 운영 가정에 따른 검토 항목이며 최종 법률 의견·계약 확정이 아니다. 아래 공식 자료는 2026-10-24 설계 대화에서 확인한 참고자료다. 출시 시 시행 법령과 공급자 정책을 다시 검증한다.

## 외부 연동 후보

| 영역 | 후보 | 계약·검증 전제 |
|---|---|---|
| 국내 PG | 토스페이먼츠·NHN KCP·KG이니시스 등 | 도입 결정, 사업자/업종 심사, 수수료·정산, 부분 취소·웹훅·조회·대사 지원 |
| PG 연결 방식 | 직접 연동 또는 중계 계층 비교 | 추가 비용·장애 책임·교체·이전 가능성 |
| 택배·3PL | CJ대한통운·한진·롯데글로벌로지스 등 비교 후보 | 실제 계약 자격·집하·송장·반품 API 제공 여부·지역·마감 |
| 배송 조회 | 택배사 직접 또는 스마트택배 API | 지원사·갱신·한도·상업 이용 조건 |
| 메시지 | 카카오 알림톡 공식 딜러·SMS·이메일 | 채널 미정, 발신자·템플릿 심사·비용·실패 대체·광고 규정 |
| 주소·인증 | 주소 검색, 자체/소셜 인증 후보 | 이용 조건·장애 대안·최소 정보·계정 연결/해지 |
| AI | 미정 | 비용·권리·외부 전송·학습 이용·보관·실패 대응 |

후보 언급은 해당 계약이나 기능 가용성 확인을 뜻하지 않는다. 배송 조회와 송장 발급·집하·반품 접수는 별도 검증한다. 카카오 알림톡은 공식 딜러 제공 조건을 확인한다. 가족 회계의 알림 시점·채널 정책을 적용하지 않는다.

참고: [토스페이먼츠 API](https://docs.tosspayments.com/reference), [스마트택배 API](https://tracking.sweettracker.co.kr/), [카카오 알림톡](https://business.kakao.com/info/infotalk).

## 보안 구현 기준

TLS·세션 보호·CSRF/XSS·로그인 시도 제한·관리자 MFA·최소 권한을 설계한다. 카드번호·CVC를 직접 저장하지 않는 PG 방식을 우선 검토한다. 키·토큰은 비밀 관리 기능으로 주입하고 브라우저 공개 값과 분리한다.

업로드의 실제 형식·크기·픽셀 수·파일명·악성 콘텐츠를 검사한다. SVG·문서 등 실행 가능한 콘텐츠의 허용·변환 정책을 정한다. 상품 공개 이미지와 문의·시안 비공개 자산을 분리한다. 다운로드·대량 내보내기에 권한·만료·감사 기록을 둔다.

개인정보·비밀값은 로그·분석 이벤트·프롬프트·테스트 데이터에 넣지 않는다. 개인정보 조회·환불·권한 변경·내보내기를 추적한다. 감사 로그 자체의 접근·보존·파기 정책도 정한다.

## 법규·개인정보 검토표

| 검토 | 출시 전 산출물 |
|---|---|
| 사업자 표시·통신판매 신고 적용·계약 내용 제공·청약 정정/철회 경로 | 실제 화면·사업자 확인·약관 |
| 의류 상품정보·소재·치수·제조 관련 표시·취급 주의 | 등록 필수 필드·검수표 |
| 청약철회 조건·하자/표시 불일치·제한 사유·비용 귀책 | 법규 검토된 반품·교환 조건표 |
| 환급 기산일·영업일·지연·결제 취소 | 기한 계산·알림·담당자 절차 |
| 수집 목적·근거·최소 항목·위탁/제공·국외 이전 | 데이터 흐름도·처리방침·계약 |
| 거래 안내/광고 구분·수신 동의·철회 | 메시지 유형별 조건 |
| 미성년자 거래·할인 표시·기만적 UI | 정책·화면 검토 |
| 시안 원본·폰트·로고·생성물 권리·외부 공유 | 이용 권한·보관·출력·AI 전송 조건 |

청약철회는 단순 배송 완료 후 N일로 고정하지 않고 계약 서면·공급·하자/표시 불일치 조건을 구분한다. 재화 환급 기산일과 3영업일 기준을 검토하고 내부 검수로 법정 기한을 임의 연장하지 않는다. [전자상거래법 제17조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031805931), [제18조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0018&lsiSeq=282793&urlMode=lsScJoRltInfoR).

개인정보 목적 달성·보유기간 만료 시 파기를 기본으로 하며 법정 보존 자료는 분리 관리한다. 탈퇴 후 진행 중 주문·클레임은 별도 본인 확인의 CS 경로로 이어갈 수 있게 한다. 법정 보존 자료를 마케팅에 재사용하지 않는다. [개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034516739).

## 보관표 작성 양식

각 데이터에 `항목 / 목적·법적 근거 / 처리자·수신자 / 접근 역할 / 보관기간 / 기산일 / 분리보관 / 파기 방법 / 백업·로그 처리 / 책임자`를 기록한다. 기간은 관할·법규 확인 후 확정한다.

정책 버전·동의 시각·항목·채널을 증적으로 남긴다. 백업 복원 후 파기 기록을 재적용해 삭제 정보가 다시 서비스에 활성화되지 않게 한다.

## 로컬 관리자 세션 (2026-10-26)

브라우저는 무작위 HttpOnly·SameSite=Strict 세션 ID만 보유하며 FastAPI 관리자 키는 Next 서버 메모리에 보관한다. 수명은 8시간, 로그아웃 시 서버에서 제거한다. 서버 재시작 시 로그인이 해제되는 단일 프로세스 로컬 방식이다. 변경 API는 Origin 일치를 확인한다. 작업 보드 페이지와 원문도 별도 인증 검사한다.

테스트 로그인은 개발 모드와 루프백 요청에서만 활성화한다. 운영 모드에서는 서버가 거부한다. 로컬 테스트용 키 파일은 배포 추적에서 제외하며 운영 키는 서버 환경변수 등 배포 환경에 맞춰 공급한다. 다중 계정·역할·복구·지속 세션·시도 제한 등 운영 인증 요건은 별도 결정/구현한다.

## 공급처 연락처 (WB46)

대표자·담당자·전화·이메일·주소는 관리자 인증이 필요한 공급처 조회/수정 API에서만 제공한다. 고객 화면에 공개하지 않으며 실제 연락처를 테스트·로그·작업 보드 예시로 사용하지 않는다. 테스트는 합성 데이터로 수행한다. 개인 식별이 불필요한 항목은 선택 입력으로 유지한다. 별도 사업자 인증이나 연락처 실소유 확인을 수행한 것으로 표시하지 않는다.

## 국내 주소 검색 (WB47)

[카카오 우편번호 공식 가이드](https://postcode.map.kakao.com/guide)를 2026-10-26 확인했다. 키 발급 없이 사용 가능한 공식 postcode.v2.js를 검색 버튼 클릭 시 로드하며 embed UI를 사용한다. 기존 개인정보를 자동으로 검색어에 넣지 않는다. 사용자가 검색창에서 입력한 조회어는 해당 외부 서비스로 전달된다. 외부 서비스 장애/차단에는 직접 입력 경로를 제공한다. 로고를 가리거나 공급자 스크립트를 변조하지 않는다. 상품/회원 권한이나 실제 주소인증을 이 검색으로 대체하지 않는다.


## 상품 이미지 접근 — WB61

이미지 관리 목록/업로드/삭제에는 내부 관리자 인증을 요구한다. WB62의 공장 조회는 별도 공장 인증과 배정·명시 공유 검사를 통과한 시안만 제공한다. 시안 이미지에 공개 파일 경로나 비인증 공개 API를 제공하지 않는다. 모델/의류 이미지도 실제 게시 구현 전에는 내부 관리자 자료다. 서버가 실제 이미지 디코딩, 용량·픽셀·형식 제한, 메타데이터 제거·재인코딩을 수행한다. 외부 URL/스크립트형 SVG는 받지 않는다. 변경 BFF는 same-origin 검사, 응답은 no-store. 테스트는 합성 파일·임시 DB를 사용하며 실제 인물 사진을 테스트 자료로 복사하지 않는다.


## 공장 계정 경계 — WB62

공장 로그인·세션 쿠키·BFF는 내부 관리자와 분리하며 공장 BFF에 관리자 master token을 사용하지 않는다. 서버가 활성 계정/공급처, 토큰 만료, 상품 배정, 명시 이미지 공유를 검증한다. 전체 admin catalog를 공장에 반환한 후 UI 필터링하지 않는다. 공장은 고객 정보·실제재고·다른 공급처 연락처·미공유 시안을 받지 않는다. 변경 API Origin 확인, 로그인 실패 제한, 로그아웃·계정중지·비밀번호변경 시 세션 폐기를 적용한다. 초기 비밀번호 전달은 내부 관리자가 별도로 하며 자동 메시지 발송 없음. 내부 관리자는 현재 공용 로컬 키로 인증하므로 이력은 개인을 식별하지 않는다.
