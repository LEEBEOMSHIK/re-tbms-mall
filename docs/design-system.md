# 디자인 시스템 v0.7 — 공통 기반

| 적용 범위 | 구현 기준 |
|---|---|
| 공통 토큰·접근성·기본 컴포넌트 | 이 문서 |
| 고객 홈·상품 탐색·상세 | [고객 쇼핑 디자인 시스템](design-system-customer.md) |
| 내부 관리자·공장 업무 | [관리자·공장 디자인 시스템](design-system-admin.md) |

화면 목적에 맞는 문서를 함께 읽는다. 공통 컴포넌트 사용이 고객 화면을 관리자 폼처럼 배치해야 한다는 뜻은 아니다.

디자인 시스템 구축 방향은 확정이다. 토큰 초안과 미구현 컴포넌트 목록은 제안이며, 아래 구현 기준 절은 현재 코드에 적용된 패턴이다. 브랜드 최종 승인이나 모든 화면의 적용 완료를 뜻하지 않는다. UI/UX 피드백은 문서와 공통 구현을 함께 갱신한다.

## 원칙

의류 사진·실측·옵션·가격을 이해하기 쉽게 보여준다. 고객 웹·관리자·시안 프로그램의 조작·상태 표현은 통일하고 목적에 따라 정보 밀도는 달리한다. 가족 회계의 색상·브랜드·용어를 가져오지 않는다.

## 컴포넌트와 화면 패턴

| 그룹 | 컴포넌트 | 검증 |
|---|---|---|
| 기본 | Button, Link, Input, Select, Checkbox, Dialog, Toast, Tabs | 키보드·포커스·레이블·오류·비활성 |
| 쇼핑 | ProductCard, Price, ColorOption, SizeOption, Quantity, SizeGuide, OrderSummary | 옵션명·품절·긴 상품명·할인 근거 |
| 운영 | DataTable, FilterBar, StatusBadge, BulkAction, AuditTimeline | 선택 상태·일괄 작업 확인·권한·모바일 축약 |
| 시안 | CanvasToolbar, PropertyPanel, LayerList, ColorPicker, VersionList | 드래그 대안·정밀 입력·확대/이동·저장 상태 |

모든 컴포넌트는 기본·hover·focus·pressed·disabled·loading·error 상태를 필요에 맞게 정의한다. 화면은 로딩·빈 결과·네트워크 실패·권한 없음·부분 성공을 포함한다.

상품 이미지는 일정한 카드 비율 후보(3:4)를 적용하되 중요한 옷 부분을 자르지 않는다. 실제 사진으로 crop/contain 규칙을 검증한다. 색상칩에는 색 이름, 품절에는 텍스트를 제공한다. 선택하지 않은 옵션을 임의 기본값으로 확정하지 않는다.

가격은 판매가·할인·배송비를 구분한다. 주문 확정 전 총액·반품 조건이 읽히게 한다. 선택 동의는 필수 동의와 구분하고 사전 선택하지 않는 방안을 기본으로 한다.

## 모바일·접근성

WB21 사용자 글자 크기: 헤더의 톱니바퀴 버튼으로 여는 사이트 설정 패널에서 기본(100%)·크게(112.5%)·더 크게(125%)를 선택한다. 기본을 다시 선택하면 초기화한다. 토큰은 rem이며 브라우저 기본 글꼴 크기를 존중한다. 기본 브라우저 16px에서 작은 안내문은14px, 보조문은15px이다. 공간/테두리까지 일괄 확대하는 CSS zoom은 사용하지 않는다. 크기 변경에도 입력·메뉴·옵션은 줄바꿈하고 최소 터치 영역을 유지한다.

선택은 현재 브라우저의 표시 설정으로 저장한다. 서버 계정 설정이 아니며 다른 기기와 동기화하지 않는다. 저장소가 차단되어도 현재 화면의 조절은 동작한다. 서버 렌더는 기본 크기이고 클라이언트에서 저장 크기를 복원하므로 첫 표시에서 짧은 크기 변화가 있을 수 있다. 브라우저 확대 기능을 제한하지 않는다. 전체 보조기기 인증과 동일시하지 않으며 실제 검증 범위는 docs/reviews/text-size.md에 남긴다.

글자 크기 구현은 apps/web/src/components/text-size-control.tsx·text-size-control.css이며 루트 layout.tsx에서 저장된 크기를 복원하고 고객·관리자 헤더와 로그인 화면의 톱니바퀴 버튼으로 패널을 연다. 별도 글자 크기 상단 바는 노출하지 않는다. 저장 키는 re-tbms-mall:text-size, 허용값은 default/large/larger이고 기본 선택은 키를 제거한다. 잘못된 값은 기본으로 처리하고 같은 브라우저의 다른 탭 변경도 반영한다. 글자 크기 선택 버튼은 aria-pressed로 선택 상태를 알린다. 새로운 화면은 --text-* 토큰을 사용하며 고정 px 글자 크기로 확대 기능을 우회하지 않는다.

고객 웹은 모바일 우선이다. 검색 조건·스크롤·입력을 복원한다. 하단 CTA는 화면·오류·키보드 포커스를 가리지 않아야 한다. 시안의 손가락 조작과 정밀 작업을 구분하고 모바일에서 불가능한 기능은 명확하게 안내한다.

접근성 목표는 WCAG 2.2 AA 제안이다. 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1, 의미 있는 비텍스트 UI 대비, 대체 텍스트, 포커스 이동·복귀, 오류 요약, 키보드·스크린리더를 확인한다. 기준과 법적 적용은 출시 시 재확인한다. [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## 운영·버전 관리

디자인 담당이 토큰·컴포넌트 카탈로그를 유지한다. 새 패턴은 기존 요소 재사용 검토 → 사용 사례·상태·접근성 명세 → 구현 → 대표 화면 검증 → 변경 기록 순서로 추가한다.

구현 시 Storybook 등 독립 컴포넌트 문서 도구를 비교해 선택한다. 시각 회귀는 상품 상세·옵션·주문서(해당 시)·관리자 표·시안 편집기를 대표로 한다. 공통 요소 변경은 모든 소비 화면을 확인한다. 예외는 사유·유효 범위·재검토 조건을 기록한다.

## 상품 중심 홈 적용

고객 홈은 얇은 브랜드 헤더·회사소개 링크, 상품 분류 탐색, 상품 그리드·맞춤 섹션을 우선한다. 큰 개발 소개 히어로·API 연결 상태·진행 단계는 노출하지 않는다. 상품 이미지는 로컬 샘플 일러스트이며 실물 사진으로 오인시키지 않는다.

관리 화면은 제목/설명 입력·상품 선택·노출 토글·위/아래 순서 버튼을 제공한다. 드래그만으로 순서를 바꾸지 않는다. 저장 중 조작을 제한하고 저장 성공·실패·버전 충돌을 상태 영역으로 알린다. 상품 상세는 키보드 접근과 닫기·포커스 복귀를 검증한다.

## 자동 슬라이드 및 푸터

카드 디자인을 유지하고 섹션 안에서만 가로 이동한다. 상품 수가 가시 범위 안에 있으면 자동 이동하지 않는다. 이동 버튼·정지/재생은 44px 조작 영역과 명확한 이름을 제공한다. 사용자 포커스를 자동 이동하지 않고 hover/focus 및 동작 줄이기 설정을 고려한다.
푸터는 회사 정보, 탐색 메뉴, 정책 안내를 구분하고 모바일에서는 세로 배치한다. 미제공 사업 정보는 등록 예정으로 표시한다. 개발 작업 보드는 고객 메뉴에서 분리한다.

## 관리자 홈·로그인 패턴

/admin 홈은 진열 관리·작업 보드 메뉴를 카드와 공통 탐색으로 제공한다. 미구현 메뉴는 준비 중으로 표시한다. 로그인 화면에는 관리자 키와 로컬 개발 전용 바로 로그인 버튼, 처리 중/실패 상태를 제공한다. 공통 헤더는 관리자 홈·로그아웃·고객 화면 이동을 제공하고 모바일에서 줄바꿈한다. 고객 화면에는 관리자 메뉴를 노출하지 않는다.

## 관리자 대시보드

/admin은 운영 업무를 확인하는 홈이다. 상단 요약 → 우선 처리 업무 → Q&A·입고·배송·재고 목록 순서로 구성한다. 상태는 텍스트와 색상을 함께 표시하고 요약 카드는 해당 영역으로 이동한다. 모바일에서는 각 영역을 세로로 배치하고 표는 영역 내부에서만 가로 스크롤한다. 샘플 기준 시각을 명시하며 실제 연동/실시간 갱신으로 표현하지 않는다. 연동되지 않은 업무에 가짜 처리 완료 버튼을 제공하지 않는다.

## 상품·재고 입력 화면

/admin/catalog는 기존 색상·간격 토큰과 버튼을 재사용한다. 상품 초안과 SKU 등록을 구분하고 재고 변경은 증감 수량과 사유를 명시적으로 입력한다. 저장 중 양식 중복 제출을 막고 오류 시 입력값을 보존한다. 성공 알림은 상태 영역, 실패는 alert로 전달한다. 충돌 시 최신 정보를 확인해 새 요청을 준비한다. 모바일 양식은 한 열, 긴 표는 이름이 있는 스크롤 영역으로 표시한다. 재고 확인 필요 상태는 색상과 텍스트를 함께 사용한다.

목록은 조회와 이동에 집중하고 상품 등록·색상/사이즈 등록·상품 수정·재고 변경은 별도 페이지에 배치한다. 각 양식에 목록 복귀 경로와 성공/실패 안내를 제공한다. 화면에서 SKU는 색상·사이즈 또는 옵션 관리 코드로 표현하며 버전 번호 같은 구현 정보는 숨긴다. 미게시 상품이라는 상태는 쉬운 문장으로 설명한다.

상품명 입력은 고객 표시명과 내부 관리명으로 구분한다. 내부 관리명은 생성 전에는 선택한 카테고리의 코드와 자동 생성 안내만 표시하며 실제 순번은 저장 성공 후 읽기 전용으로 보여준다. 카테고리는 레이블이 연결된 공통 FormSelect를 사용한다. 목록·수정 화면은 두 이름을 구분하고 색상/사이즈·재고 대상 선택에는 내부명과 표시명을 함께 제공한다. 내부명은 수정할 수 없고 분류 변경 후에도 유지된다는 안내를 제공한다.

## 분류·계절 입력

대분류와 세부 카테고리 select를 순서대로 배치하고 대분류를 바꾸면 세부 선택을 초기화한다. 계절은 이름 있는 fieldset/legend와 checkbox로 복수 선택하고 사계절은 개별 계절과 배타적으로 선택한다. 내부명 미리보기는 발급 형식만 보여주며 실제 번호로 오인되지 않게 한다. 미지정·사용 중지 기존 값은 텍스트로 구분하고 강제로 다른 값으로 바꾸지 않는다. 카테고리 관리의 이름/정렬/사용 여부는 레이블과 저장 상태·충돌 안내를 제공한다.

## 공통 폼 구현 기준 — WB18

입력창만 각지고 선택창만 둥근 혼합을 허용하지 않는다. 동일 폼 안 text/number/password 입력, select, textarea, 읽기 전용 필드는 같은 모서리·간격·포커스 기준을 사용한다. 단일 행 최소 높이는52px, 모서리는12px다. textarea는 내용에 맞춰 높이가 늘지만 모서리는 같다. 오류는 aria-invalid와 안내 문구, disabled와 readonly는 별도 표현을 사용한다.

계절은 선택 카드다. 선택 전 빈 체크박스 테두리를 반복하지 않으며, 선택 시 체크 원·강조 테두리·절제된 배경으로 구분한다. 어두운 큰 타일만으로 선택을 표현하지 않는다. native checkbox는 키보드와 보조기기에 노출하고 label 전체를 클릭 대상으로 사용한다. 포커스는 카드 외곽에 표시한다. 계절의 의미·사계절 배타 규칙은 UI 컴포넌트가 임의로 바꾸지 않는다.

### 공통 구현과 적용법

- apps/web/src/components/ui/form-controls.tsx: 재사용 선택 컴포넌트 FormChoice.
- apps/web/src/components/ui/form-controls.css: ds-form 범위의 입력·select·textarea·선택 카드·상태 스타일과 폼 토큰.
- 새 폼은 공통 CSS를 import하고 폼 영역에 ds-form을 적용한다. 선택 UI는 FormChoice를 사용한다. 페이지마다 input/select의 radius를 새로 지정하거나 CSS 덮어쓰기를 누적하지 않는다.
- label 연결, id, checked, onChange, disabled를 소비 화면이 전달한다. fieldset/legend로 선택 그룹에 이름을 제공한다.
- 현재 적용: 상품 등록/수정, 색상·사이즈 등록, 재고 변경, 카테고리 관리. 기존 로그인·진열·고객 화면 전체를 이번에 교체했다고 간주하지 않는다. 후속 수정 시 공통 패턴을 적용한다.
- WB19부터 펼친 목록도 공통 FormSelect의 listbox로 표시한다. reduced-motion·forced-colors에서 사용성을 보존한다.

### 피드백 기록

WB17에서 select와 checkbox만 다듬어 다른 입력과 모서리가 달라졌고, 큰 선택 칩 안에 작은 체크박스가 반복되어 투박하다는 사용자 피드백을 받았다. WB18은 전체 폼 일관성과 선택 카드 공통화를 적용한다. 개발 절차의 UI/UX 피드백 반영 절에 따라 이후 화면도 같은 기준으로 검토한다. 실제 검증 범위는 docs/reviews/form-design-system.md에 기록한다.

공통 폼 토큰은 --form-control-radius(12px), --form-control-height(52px), --form-control-padding-inline, --form-control-border, --form-control-surface, --form-control-muted-surface, --form-control-selected-border, --form-control-focus다. 색상은 기존 color 토큰을 참조한다. ds-form-action은 폼 내부 링크형 버튼에 같은 모서리/높이를 적용한다. 선택 카드는 ds-choice-grid로 배치하며 ds-choice-wide는 모바일 전체 너비, ds-choice-compact는 짧은 사용 여부 선택에 사용한다.

```tsx
import { FormChoice } from '@/components/ui/form-controls';
import '@/components/ui/form-controls.css';

<form className="ds-form">
  <label htmlFor="display-name">고객 표시명</label>
  <input id="display-name" name="name" />
  <FormChoice id="enabled" label="사용 중" checked={enabled}
    onChange={event => setEnabled(event.target.checked)} />
</form>
```

새 적용 시 기존 global/page CSS가 공통 입력 높이·모서리·readonly·disabled·동작 줄이기를 덮어쓰지 않는지 실제 계산 스타일로 확인한다. 컴포넌트 코드가 존재한다는 것만으로 시각 일관성이 보장되지 않는다.

## 필수 표시와 선택 목록 — WB19

공통 FormLabel은 필수 항목에 텍스트 대신 별표(*)를 표시하고 선택/자동 생성 상태는 짧은 텍스트로 표시한다. 각 폼 상단에는 FormRequiredHint로 “* 필수 입력” 안내를 한 번만 배치한다. 별표는 aria-hidden으로 접근성 이름에서 제외하고 required/aria-required 의미는 유지한다. 색상만으로 필수 여부를 표현하지 않는다. 장식 상태는 실제 필드 접근성 이름과 분리하고, required/aria-required는 실제 검증 조건과 일치시킨다. 신규 상품의 분류·계절은 필수이며 기존 미지정 상품을 그대로 유지하는 이름 수정은 별도 안내한다. 설명은 선택, 내부 관리명은 자동 생성, 카테고리 부모 없음은 대분류 생성의 정상 선택이다.

FormSelect는 단일 선택용 combobox와 listbox를 제공한다. 닫힌 입력과 열린 목록의 모서리·테두리·색상은 폼 토큰을 사용한다. 활성 옵션과 확정 선택을 구분하고 선택 항목에 체크 표시를 제공한다. 비활성 옵션은 선택할 수 없으며 빈 목록은 안내한다. 긴 목록은 스크롤하고 화면 아래 공간이 부족하면 위쪽으로 열거나 가용 높이 안에 제한한다.

키보드 화살표/Home/End로 이동, Enter/Space로 선택, Escape로 취소·닫기, Tab으로 정상 이동, 바깥 클릭으로 닫기를 지원한다. 버튼은 form 제출을 일으키지 않는다. 빈 필수 선택을 제출하면 오류를 표시하고 해당 선택 컨트롤로 포커스를 이동한다. disabled/상위 fieldset disabled 상태는 팝업 옵션에도 적용한다. native 검증 연결 요소가 있다면 접근성 트리에 중복 노출하지 않는다.

catalog의 상품·옵션·재고·카테고리 양식은 같은 공통 컴포넌트를 사용한다. 앞으로 새 관리자 폼에서는 페이지별 select 팝업을 따로 구현하지 않는다. 실제 확인 범위는 docs/reviews/required-select.md를 따른다.

FormLabel/FormSelect의 구현 위치는 apps/web/src/components/ui/form-controls.tsx이며 스타일은 같은 디렉터리의 form-controls.css다. FormLabel의 htmlFor와 FormSelect의 id를 같게 두어야 한다. options는 {value,label,disabled?} 배열이고 value/onChange는 제어형 상태다. required는 실제 필수 조건, disabled는 처리 중/수정 불가 조건, describedBy는 도움말 ID를 전달한다.

```tsx
<FormLabel htmlFor="category" required>카테고리</FormLabel>
<FormSelect id="category" required value={categoryId}
  options={categoryOptions} onChange={setCategoryId}
  placeholder="카테고리 선택" />
```

실제 option UI와 native 검증용 select를 중복 노출하지 않는다. 외부 페이지 스크롤 시 열려 있는 목록을 닫고 목록 내부 스크롤은 유지한다. 옵션/현재값이 바뀌면 이전 팝업 상태를 재사용하지 않는다. 여러 항목이 비어 있으면 첫 오류 필드로 포커스를 이동한다.

## 사이트 설정 패널 — WB22·WB23

사용자 표시 설정은 헤더의 톱니바퀴 진입점에 모은다. 버튼은 최소44px 클릭 영역과 “사이트 설정 열기” 접근성 이름을 가진다. 패널은 사이트 설정 → 화면 및 접근성 → 글자 크기 계층으로 구성한다. 공통 설정 셸과 분류 컴포넌트는 개별 설정과 분리한다. 현재 구현 항목은 글자 크기이며 다른 분류·항목은 기능 구현 후 추가한다. 모달은 제목·닫기 버튼, Escape, 배경 클릭 닫기와 트리거 포커스 복귀를 제공한다. 모바일·최대 글자 크기에서도 화면 안에서 스크롤하도록 한다. 새 표시 설정이 생기면 같은 패널에 통합하고 상시 노출 도구를 중복하지 않는다.


확장 후보, 저장·권한 경계와 설정 추가 절차는 [사이트 설정 설계](site-settings.md)를 따른다. 톱니바퀴를 글자 크기 전용 기능으로 구현하지 않는다.

공통 셸·분류는 apps/web/src/components/site-settings.tsx와 site-settings.css, 실제 항목 조합은 site-settings-content.tsx에 있다. SettingsSection의 제목/설명/children으로 확장하며 현재 글자 크기는 TextSizeSetting으로 조합한다.

## 등록 완료와 다음 단계 — WB24

신규 상품 등록 성공은 작은 상단 안내만으로 끝내지 않는다. 폼을 명확한 완료 화면으로 전환하고 완료 제목에 포커스를 옮겨 모바일 하단에서 제출한 사용자도 결과를 확인하게 한다. 서버 응답의 표시명·내부명을 보여주고 주 동작은 해당 상품의 색상·사이즈 등록, 보조 동작은 상품 목록으로 제공한다. 다른 상품 등록은 명시적 버튼으로 시작한다. 처리 중에는 등록 중 표시/비활성으로 중복 제출을 막는다.

상품 기본 정보 → 색상·사이즈 → 옵션별 재고의 후속 작업을 안내하되 모든 단계가 완료된 것처럼 표시하지 않는다. 저장 실패/불확실 응답을 완료 화면으로 처리하지 않으며 입력을 유지한다. 수정 화면의 저장 흐름은 기존 동작을 유지한다. 신규 데이터 생성 화면은 이후 이 완료/후속 작업 패턴을 기준으로 설계한다.

## 목록 작업과 삭제 — WB25

행 작업은 아이콘+짧은 라벨의44px 이상 라운드 버튼으로 묶고 삭제 휴지통은 별도 위험 작업으로 구분한다. 상품명을 포함한 접근성 이름을 제공하며 장식 SVG는 숨긴다. 수정·색상/사이즈는 동일한 중립 스타일, 삭제만 위험 색을 사용한다. 관리자 테이블은 모바일에서 이름 있는 영역 안에서 가로 스크롤하며 페이지 전체가 넘치지 않도록 한다.

상품·옵션·기준정보 관리 표는 th/td 기본값을 vertical-align:middle로 설정한다. 특정 상품 행에만 한정하지 않고 입력창·버튼을 포함한 신규 표에도 적용한다. 긴 내용은 줄바꿈하되 행 전체 높이를 기준으로 정렬한다. 재고 변경 이력(#movement-history)만 긴 사유 가독성을 위한 상단 정렬 예외다. 옵션 수량 입력은 열 제목으로 의미를 전달하고 행별 접근성 라벨은 화면에서 숨겨 입력 위 중복 문구로 중심이 달라지지 않게 한다.

WB27: 완료 화면의 다른 상품 등록도 동일 작업 그룹 안에 두고 별도 행을 강제하는 여백을 제거한다. 넓은 화면에서는 세 동작을 나란히, 작은 화면에서는 자연스럽게 줄바꿈한다. 상품 목록의 준비 상태는 색상과 텍스트 배지, 옵션 수와 수량으로 표시한다. 상태는 색상·사이즈 등록 필요/재고 입고 필요/일부 옵션 재고 없음/재고 준비됨이다. 고객 화면 미게시를 별도로 표시하며 재고 준비됨을 판매 중으로 표시하지 않는다.

WB28 공통 StatusBadge(components/ui/status-badge.tsx·css)는 아이콘+라벨+배경색으로 상태를 구분한다. 옵션 등록은 파랑/추가, 입고는 주황/입고 화살표, 일부 재고 없음은 호박색/주의 삼각형, 준비됨은 초록/체크다. 미게시(눈가림)와 미확인(물음표)은 중립 회색이다. --status-* 토큰을 사용하며 색상만으로 의미를 전달하지 않는다. 장식 SVG는 aria-hidden이고 비대화형 span으로 버튼과 구분한다. 미게시 배지는 재고 배지와 분리하고 수량은 보조 텍스트로 유지한다. 강제색상에서는 시스템색과 아이콘·라벨을 유지한다.

WB29: 게시 배지를 준비 상태 셀에서 빼고 별도 게시 상태 컬럼에 배치한다. 배지와 짧은 사유는 항상 읽을 수 있고 상세 설명은 hover·focus·tap으로 연다. 상세에는 확인된 옵션/재고 현황과 고객게시 미연결을 구분한다. 툴팁은 색상/hover에만 의존하지 않으며 Escape·바깥 클릭으로 닫고, 포인터를 툴팁으로 옮겨도 읽을 수 있어야 한다. 테이블의 overflow에 잘리지 않게 뷰포트 내에 표시한다. 상품명을 포함한 진입 접근성 이름과 aria-describedby를 연결하고 native title에만 의존하지 않는다.

공통 Tooltip은 components/ui/tooltip.tsx·css에 있으며 label/trigger/children을 받는다. 설명은 비대화형 내용으로 제한한다. 접근성 이름에 화면에 보이는 배지와 사유도 포함한다. 긴 설명이 넘치면 트리거 포커스 상태에서 화살표·PageUp/Down·Home/End로 읽을 수 있다. 포인터를 설명으로 옮기는 간격에는 닫힘 유예를 두고, 실제 앵커 이동/화면 크기 변경 시 닫아 잘못된 위치를 유지하지 않는다.

삭제는 native dialog에서 상품 표시명·내부명을 확인하며 취소에 초기 포커스를 준다. 연결된 옵션이 있으면 이유를 표시하고 삭제를 비활성화한다. 진행 중 중복·Escape·배경 닫기를 막고, 실패는 행을 유지한다. 불확실 응답은 최신 목록 확인 전 재삭제를 막는다. 성공한 삭제와 이후 조회 실패를 혼동하지 않게 안내하며 사라진 행의 버튼 대신 목록 제목으로 포커스를 옮긴다. 관련 코드는 catalog-list.tsx·catalog.css이고 서버 제약은 API 계약을 따른다.

## 색상·사이즈 기준정보와 옵션 코드 — WB30

관리자가 등록한 활성 색상·사이즈는 공통 FormSelect 콤보박스로 선택한다. 이름과 코드를 함께 표시하며 미등록 상태에는 기준정보 관리와 빠른 추가 경로를 안내한다. 옵션 관리 코드(SKU)는 개별 조합 식별자이므로 선택 목록으로 제공하지 않고 상품·색상·사이즈 선택에 따른 읽기 전용 미리보기로 제공한다. 서버 저장 응답이 최종 코드다.

빠른 추가는 기존 등록 폼과 중첩하지 않는 별도 폼으로 제공한다. 성공한 항목을 바로 선택하며 기존 상품·반대쪽 옵션·입고 확인 기준 수량은 보존한다. 실패 시 입력을 유지하고 재시도할 수 있다. 창 복귀 시 최신 기준정보를 조회하되 작성 중 값을 초기화하지 않는다. 사용 중지 항목은 새 선택에서 제외하며 이미 선택한 값이 중지되면 저장을 막고 다시 선택하도록 안내한다. 기존 SKU의 이름과 코드는 기준정보 수정으로 소급 변경하지 않는다.

## 다중 선택 및 일괄 작업 완료 — WB31

상품 옵션은 여러 색상과 여러 사이즈를 공통 FormChoice 선택 카드로 고른다. 이는 WB30 단일 콤보박스를 확장한 사용자 요청이다. 상품 선택은 콤보박스를 유지한다. 선택 수·조합 수·신규/기존 구분과 자동 코드 미리보기를 저장 전에 제공한다. 작은 화면에서 선택 카드는 줄바꿈하고 조합 표는 이름 있는 내부 스크롤 영역으로 제공한다.

일괄 저장 성공은 폼 아래 알림만으로 끝내지 않는다. 서버 확인 후 완료 패널로 전환하고 제목에 포커스를 옮긴다. 신규 등록 개수·기존 제외 개수·실제 등록 조합을 표시하며 주 동작은 재고 입고, 보조 동작은 목록 및 추가 등록이다. 신규0개는 새 등록 없음으로 표시한다. 저장 실패는 입력을 유지하며 저장 중 중복 제출을 막는다. 재고0인 새 옵션을 입고/판매 완료로 표현하지 않는다.

## 조합 편집과 초기 재고 — WB32

'조합 미리보기'는 '등록할 옵션과 초기 재고' 편집 영역으로 확장한다. 각 신규 행에 초기 입고 수량(기본0)과 제외·복원 동작을 제공한다. 제외는 아직 저장하지 않은 조합의 등록 대상 제외이며 기존 SKU 삭제가 아니다. 제외한 행의 수량은 비활성화하고 복원 시 작성값을 유지한다. 기존 옵션은 현재고만 표시하고 재고관리 경로를 제공한다.

등록 대상 개수·제외 개수·기존 개수와 초기 입고 합계를 명확히 보여준다. 제외된 행은 검증/전송하지 않는다. 상품을 바꾸면 조합별 입력을 초기화해 다른 상품 수량 혼입을 막는다. 같은 상품의 기준정보 새로고침/색상·사이즈 변경은 남은 조합 입력을 보존한다. 완료 화면은 실제 저장된 조합별 수량과 초기 입고 합계를 표시하고0재고 옵션은 후속 입고 대상으로 안내한다. 재고 입력을 실제 고객 게시 완료로 표현하지 않는다.


## 조합별 기준과 공통 적용 — WB34

재고 부족 표시 기준은 신규 조합 행의 독립 입력 필드다. 각 입력은 색상/사이즈를 포함한 접근성 이름을 갖고 셀 세로 중앙 정렬을 따른다. 기존 조합은 저장된 기준을 읽기 전용으로 표시한다.

공통값 입력은 일괄 편집 도구이며 저장할 행 데이터와 구분한다. 버튼을 눌렀을 때 현재 등록 대상 신규 조합에만 적용하고 적용 개수를 안내한다. 제외/기존/현재 선택 외 행은 바꾸지 않는다. 공통값 변경만으로 행을 덮어쓰지 않으며 공통값이 잘못되어도 적용하지 않았다면 유효한 개별 행 저장을 막지 않는다. 나중에 추가한 조합은 기본0임을 안내한다. 적용 후 개별 수정·제외/복원·초기 입고값 보존을 검증한다. 상품 변경은 행/공통 도구를 초기화한다.

## 저장·수정 완료 피드백 필수 규칙 — WB35

신규 등록뿐 아니라 수정·입고·조정 등 모든 쓰기 화면에 적용한다. 값만 초기화하거나 작은 상단 메시지만 바꾸는 것으로 완료 처리하지 않는다. 작업 명세에서 저장 중/성공/실패/응답 불확실/성공 후 조회 실패의 화면 상태를 정의해야 한다.

- 저장 중: 진행 문구와 중복 제출 방지.
- 확정 성공: 사용자 시야 안의 완료 패널 또는 명확히 갱신된 결과 영역, 대상·변경 내용·다음 동작을 제공한다. 수량/금액 변경은 전·후와 증감을 구분한다. 재시도 결과도 서버 확정값을 사용한다.
- 포커스/스크롤: 완료 제목으로 이동해 긴 모바일 폼에서도 결과를 인지할 수 있어야 한다. 공통 SaveResult(components/ui/save-result.tsx)를 우선 사용한다.
- 실패/불확실: 입력과 필요한 재시도 정보를 유지하고 성공으로 표시하지 않는다.
- 저장 성공 후 조회 실패: 저장은 완료되었음을 유지하고 조회 오류를 별도 안내한다. 최신 상태가 필요한 후속 수정은 재조회 성공 전 막는다.
- 다음 동작: 다시 입력/목록/관련 후속 작업을 명시적으로 제공한다. 다시 입력은 중복 저장을 일으키지 않아야 한다.

적용: WB35 재고 입고·조정은 공통 SaveResult 사용. 기존 상품/옵션 등록은 자체 완료 패널을 유지하며 모든 기존 편집 화면을 소급 전환한 것은 아니다. 향후 추가·수정하는 쓰기 화면은 이 규칙과 검증표를 반드시 따른다. 인라인 저장 등 예외는 동등한 성공 인지/접근성 증거와 이유를 기록한다.

## 목록·등록·수정 화면 분리 필수 규칙 — WB36

관리 화면은 조회 목적의 목록과 작성 목적의 등록·수정을 별도 URL/화면으로 분리한다. 목록 위·아래에 등록 폼을 붙이거나 입력 화면 하단에 전체 이력 목록을 붙이지 않는다. 목록에는 등록 진입과 행별 수정 진입, 입력에는 해당 목록 복귀, 완료에는 목록 확인 및 명시적 추가 작업을 제공한다. 입력 검토에 필요한 해당 대상 요약/선택 조합은 허용하되 전체 관리 목록을 대신 붙이지 않는다.

신규·수정 작업의 수용 기준에는 목록에 작성 폼이 없는지, 입력에 전체 목록이 없는지, 등록→완료→목록 경로, 직접 URL 인증, 모바일 화면을 포함한다. 공통 기준정보 빠른 추가 등 다른 구조가 필요하면 이유와 적용 범위를 작업 명세에 먼저 기록한다. 편의상 합치는 것을 기본 선택으로 삼지 않는다.

적용: 재고 변경 이력 /admin/catalog/inventory, 입력·완료 /admin/catalog/inventory/new. 기존 상품 등록/목록 분리와 같은 기준이다. 이번 수정은 재고 화면이며 기존 기준정보 관리 화면 전체를 소급 분리했다고 표현하지 않는다.

## 관리자 전체 감사 적용 — WB37

카테고리 /admin/catalog/categories, 색상·사이즈 기준정보 /admin/catalog/option-values, 진열 /admin/merchandising는 목록으로 사용하며 각 /new 및 /[id]/edit 입력·완료 화면을 분리한다. 카테고리 신규는 대분류/세부분류 유형을 명시하고 대분류는 상위 없음, 세부분류는 활성 대분류 선택을 요구한다. 코드와 부모는 저장 후 고정이라는 기존 서버 계약을 유지한다.

상품 수정도 SaveResult로 완료 전환한다. 카테고리/기준정보/진열의 등록·수정은 같은 완료 패턴을 사용한다. 상품/옵션 등록의 기존 완료 패널은 동등한 포커스·확정 결과·후속 동작을 제공하므로 유지한다. 재고 입고/조정은 기존 SaveResult를 유지한다.

검토한 예외: 대시보드·작업 보드는 읽기 전용, 로그인/로그아웃은 인증 및 이동, 글자 크기는 로컬 즉시 적용 개인설정으로 목록/등록 CRUD가 아니다. 옵션 등록 중 빠른 색상/사이즈 추가는 해당 폼의 선택값 보완 동작이며 전체 관리 목록을 섞지 않는다. 성공한 값의 자동 선택·패널 닫기·포커스 복귀가 완료 피드백이다. 상품 삭제는 확인 후 행 제거·목록 제목 포커스·삭제 결과 안내를 유지한다.

## 실제 재고와 부족 표시 기준 구분 — WB38

초기 입고와 부족 표시 기준은 각각 별도 영역·제목·공통 입력·적용 버튼·피드백을 사용한다. 초기 입고는 실제 수량(예:3조합×10개=30개), 부족 기준은 상태 표시 조건이다. 한쪽 적용은 다른 필드를 바꾸지 않는다. 입고 공통 적용은 덧셈이 아닌 각 행 값 대체임을 명시하고 적용 당시 개수·합계·아직 저장 전임을 안내한다. 기존/제외 조합 미적용, 추가조합기본0, 개별수정 가능을 설명한다. 도구의 입력 검증 소유권을 최종 제출폼과 분리해 미적용 오류가 유효한 행 저장을 막지 않게 한다. 실제 저장과 완료는 기존 등록 흐름을 따른다.

## 선행 선택과 상세 도움말 — WB39

선택한 대상에 적용하는 일괄 도구는 대상 선택 다음에 배치한다. 옵션 등록은 상품→색상·사이즈→공통 적용→조합별 수량·기준→저장 순서다. 상세 설명은 제목 옆 공통 Tooltip의 물음표 버튼으로 제공하며 hover/focus/tap·Escape를 지원한다. 버튼 접근성 이름은 해당 기능+도움말, 터치 영역은44px이상이다. 적용 대상 개수·오류·결과는 숨기지 않는다. 공통값 입력의 HTML form 소유권을 별도 폼으로 분리해 미적용 오류가 최종저장을막지않게한다(중첩form금지). WB38의 제출폼밖 배치 대신 검증 소유권 분리를 사용한다.


## 재고 이동 입력과 사유 — WB40

수량의 양수/음수를 직접 판단하게 하지 않고 입고/출고/조정 유형을 먼저 선택한다. 출고는 판매/증정(지인 제공 포함)/불량·폐기/기타로 구분하고 조정은 증가/감소를 선택한다. 수량은 양수이며 현재 재고와 예상 변경 후 수량을 함께 보여준다. 상세 사유는 선택 자유 메모이며 개인정보 입력을 유도하지 않는다. 서버에서 저장을 확인한 뒤 별도 이력 목록으로 이동하고, 조회된 기록으로 유형·증감·전후 수량을 안내한다(WB41). 이력은 분류 필터와 일치 건수를 제공한다. 기존 미분류 기록은 부호로 판매/증정을 추정하지 않는다.

## 재고 흐름과 저장 후 목록 — WB41

사용자 지시로 재고 등록은 완료 패널을 유지하지 않고 확정 성공 후 이력 목록으로 자동 이동한다. 목록에서 실제 조회된 해당 원장의 유형·증감·전후 수량을 안내하고 포커스를 옮긴다. 조회 실패는 저장 실패와 혼동하지 않으며 URL의 saved 값만으로 성공을 주장하지 않는다. 이는 재고 화면의 명시적 완료 UX이며 다른 화면 완료 패널을 일괄 제거하지 않는다. 상세사유는 선택으로 표시하며 빈칸은 목록에서 없음으로 표시한다.

입고/고객판매출고/기타출고·조정/기존미분류 조회 구분은 실제 거래처나 배송 위치를 추정하지 않는 업무용 필터다. 증정·폐기를 고객판매와 합치지 않는다. 큰 흐름 선택과 세부 사유 필터의 적용 관계를 명확히 보여준다.

## 업무 흐름별 재고 작업 — WB42

이력 화면에는 입고(공장·공급처 → 보유 재고), 고객 판매 출고(보유 재고 → 고객), 기타 출고·조정의 작업 진입을 제공한다. 입력 화면은 선택한 업무의 제목·처리 사유·수량 라벨·저장 버튼을 일치시킨다. 업무 선택은 색만으로 구분하지 않고 텍스트와 선택 상태를 함께 제공한다. 현재 수량 → 증감 → 예상 결과를 명확하게 표시하고 서버 저장 전에는 예상임을 구분한다. 긴 설명은 접근 가능한 물음표 도움말을 사용하며 오류와 필수 안내는 숨기지 않는다. 작은 화면에서는 작업 카드와 수량 요약을 자연스럽게 줄바꿈한다.

필터는 현재 업무에 해당하는 사유만 제공하고 업무 변경 시 세부 필터를 초기화한다. 등록과 이력은 별도 화면이며 완료 후 실제 원장 안내 원칙을 유지한다.

## 재고 현황과 입고처 — WB43

재고 관리 진입 시 현재 보유량을 먼저 제시한다. 입고·출고·조정 내역은 별도 보기로 나누며 상품명과 색상·사이즈를 항상 표시한다. 옵션 코드만으로 상품을 식별하게 하지 않는다. 현재 수량은 서버의 보유량을 사용하고 누계는 전체 기록 기준임을 표시한다. 초기 입고 포함 여부와 기존 미분류 제외를 명시하며 입고누계에서 출고만 빼서 현재 재고라고 단정하지 않는다.

공장·공급처 목록/등록/수정은 별도 URL로 분리한다. 신규 입고는 활성 공급처 선택이 필수이며 공급처 등록 후 목록 갱신으로 즉시 선택할 수 있다. 과거 공급처 미기록은 그대로 표시한다. 공급처별 입고 조회에서는 상품 옵션과 조회 수량 합계를 함께 보여준다. 저장 완료와 오류 안내는 기존 디자인 시스템을 따른다.

## 목록 그룹 간격 — WB44

목록의 작업 버튼, 안내문, 조회 결과/빈 상태는 독립된 세로 그룹이다. catalog-list-stack으로 그룹 사이 space-4를 적용한다. catalog-actions의 gap은 내부 버튼 간격만 제공하므로 그룹 사이 여백의 대체가 아니다. 빈 상태는 catalog-empty-state의 space-6 안쪽 여백과 배경으로 안내문과 구분한다. 빈 목록과 데이터가 있는 목록을 각각 검증하고 모바일 및 확대 글꼴에서 실제 그룹 간격·가로 넘침을 확인한다. 폼의 fieldset 간격을 일괄 덮어쓰지 않는다.

## 테마 — WB45

공통 semantic 색상 토큰은 라이트/다크 쌍으로 관리한다. 배경뿐 아니라 기본/보조 텍스트·버튼·오류·성공·포커스·상태 배지도 함께 전환한다. 입력·드롭다운·툴팁·대화상자는 공통 surface/text를 상속한다. 이미지와 실제 상품색을 반전하거나 밝기를 바꾸지 않는다. color-scheme으로 네이티브 컨트롤도 맞춘다. 선택 UI는 사이트 설정 내에 두고 선택 상태를 aria-pressed와 텍스트로 제공한다. 저장값은 명시 선택이 OS보다 우선하며 기본은 시스템이다. 텍스트/표/폼/팝업의 대비와 모바일·확대 글꼴을 함께 확인한다.

## 공급처 상세 정보 — WB46

공급처 폼은 기본정보/연락처/주소·메모 그룹을 구분한다. 그룹 사이 space-6, 독립 필드 사이 space-4, 라벨과 입력 사이 space-2를 기준으로 공통 토큰을 사용한다. 모바일은 한 열, 넓은 화면은 관련 항목 두 열을 사용할 수 있다. 필수는 기존 * 표시이며 추가 항목은 선택임을 그룹 안내로 설명한다. 목록은 공급처명·영문명·대표자·전화·담당자 요약 중심으로 두고 상세 주소/메모까지 표를 과도하게 늘리지 않는다. 저장 완료·오류 보존·목록/등록 분리와 다크 토큰 기준을 유지한다.

## 국가별 주소 UI — WB47

주소 그룹 맨 앞에 국가 선택을 제공한다. 미지정은 임의 국가로 바꾸지 않으며 기존값이 유지된다는 안내를 표시한다. 국내에는 검색 버튼과 직접 입력을 함께 제공하고 해외는 지역·도시·주소1/2를 표시한다. 국가전환 시 입력값을 삭제하지 않는다. 검색이 실패해도 직접 입력과 저장이 가능해야 한다. 검색 결과 적용 후 상세주소로 포커스를 이동하고 변경된 항목을 안내한다. 외부 검색 화면은 본문 삽입 영역과 닫기 버튼을 제공하고 요청 중 상태·오류를 명시한다. 기존 그룹 space-6/필드 space-4/label space-2 및 모바일1열/다크 기준 유지.

## 폼 규모별 너비·배치 — WB48

- 복합 등록·수정(상품, 옵션 조합, 재고, 공급처, 진열)은 본문폭을 사용한다. 본문 최대폭 1320px을 따르며 폼에 760px 상한을 일괄 적용하지 않는다.
- 짧은 카테고리·색상/사이즈 기준정보는 compact(최대760px), 로그인은 기존 인증폼 폭을 유지한다. 모든 경우 화면보다 커지지 않는다.
- 관련 입력은 넓은 화면에서 2열로 묶는다. 설명·주소·선택조합표·오류·저장버튼은 필요에 따라 전체열을 사용한다. 외곽만 넓히고 모든 짧은 입력을 무조건 긴 한 줄로 늘리지 않는다.
- 모바일<=767px은 입력/선택 그룹 1열이다. 조합/이력 등의 데이터 표는 내부 가로스크롤을 유지하며 문서 전체 가로넘침은 허용하지 않는다.
- 그룹간 space-6, 독립필드간 space-4, 라벨-입력 space-2, 저장행 앞 space-6. 기존 목록간격과 폼간격을 혼동하지 않는다.
- 화면 추가 시 폭 유형과 근거를 명시하고 등록/수정/완료, 모바일·다크·확대 글꼴을 검증한다. 브라우저 bounding box와 실제 렌더링을 확인하여 CSS 선언만으로 통과하지 않는다.

## 공급처 저장 이동과 전화 입력 — WB49

공급처 등록/수정은 서버 성공 후 목록으로 자동 이동한다. 별도 완료 화면 대신 목록의 포커스 가능한 결과 안내로 확인하며 실제 조회 id/version을 대조한다. 조회실패·불일치는 별도로 안내한다. 오류 시 폼과 입력을 유지한다. 전화는 tel 입력과 짧은 형식 도움말, 항목별 오류·aria-invalid/설명 연결을 제공한다. 국내 최대11/선두+ 국제 최대15는 숫자 기준이며 하이픈 포함 문자열에 maxLength=11을 걸지 않는다. 붙여넣기를 조용히 잘라 다른 번호로 만들지 않는다. 기존 간격·모바일1열 기준을 유지한다.

저장 확정 응답의 최소 정보(id/version/name/is_active)는 일시적인 메모리 영수증으로만 유지한다. 목록 조회 실패 시 저장 성공과 조회 실패를 구분한다. URL만으로 새 저장이 확정되었다고 판단하지 않는다. 조회 대조는 동일 id 및 version 이상이며 더 최근 수정이 있으면 최신 목록 내용을 표시한다.

## 전화 입력 제한 보완 — WB50

오류 문구만 표시하는 것은 입력 제한의 대체가 아니다. 전화 입력은 허용 길이·문자 범위를 벗어난 편집을 거절하며 기존값을 보존한다. 붙여넣기 자동절단 금지. 거절 안내는 입력 옆 live 영역과 설명 연결로 제공하고 사용자가 해결하기 전 저장을 막는다. + 입력 중 상태/삭제/선택교체를 지원하며 실제 타이핑과 붙여넣기 브라우저 검증을 별도로 수행한다.

## 폼 보조작업·긴 선택값 — WB51

같은 작업행의 링크형 버튼과 button은 공통 클래스와 컨트롤 높이/라운드/패딩/중앙정렬을 함께 적용한다. 포커스 링은 제거하지 않는다. 필드는 라벨·컨트롤·설명·보조작업 단위로 묶어 라벨-컨트롤 space-2, 그룹 space-6을 유지한다. 긴 선택값 때문에 옆 입력 높이가 달라지지 않도록 선택 표시와 전체정보 영역을 분리할 수 있다. 생략된 전체정보는 모바일에서도 확인 가능해야 하며 title만으로 대체하지 않는다.

## 요약카드와 보기 전환 통합 — WB52

같은 내용을 조회하는 요약카드와 탭을 중복 제공하지 않는다. 카드 전체를 native button으로 만들고 aria-pressed·테두리/배경·선택문구로 현재 보기를 표시한다. 포커스링/Enter/Space를 지원한다. 건수와 수량 단위를 구분하며 보기전환이 요약 통계의 집계범위를 바꾸지 않는다. 작은 화면 카드열을 줄이고 확대글꼴에서 텍스트 넘침을 검증한다.

## 상품·재고 업무 분리 — WB53

전역 메뉴는 상품 관리/재고 관리로 분리하고 한 화면에서는 하나의 메뉴만 활성표시한다. 공급처는 재고관리, 카테고리·옵션은 상품관리 소속이다. 상품목록의 재고는 요약과 명확한 재고보기 링크로 연결하며 수량조작·전체원장을 섞지 않는다. 특정상품으로 이동하면 상품명/내부명과 필터해제 경로를 보이고 모든 재고카드·목록의 범위가 일치해야 한다. 모바일에서도 메뉴와 현재범위가 잘리지 않도록 검증한다.

## 목록 검색·필터 도구영역 — WB54

목록앞에 검색/설명/필터를 독립 세로블록으로 반복하지 않는다. 제목과 도움말, 통합검색필터, 결과요약, 표 순서로 묶는다. 데스크톱은 검색칸을 넓게 하고 선택필터를 같은 행에, 모바일은1열로 배치한다. 라벨-입력 space-2, 필드사이 space-4, 그룹사이 space-6, 결과요약-표 space-4 이상. 긴설명은 키보드/터치로 열리는 공통 도움말을 사용하고 표/등록작업영역 간 space-6 확보. 필터 초기화는 상품조회범위를 임의 해제하지 않는다.

## 목록 등록작업 위치·업무 분류 — WB55

목록 길이에 따라 필수 등록작업이 밀리지 않도록 상단 도구영역에 컴팩트 버튼으로 제공하며 목록아래 중복카드는 제거한다. 같은업무의 하위종류는 진입메뉴로 늘리지 않고 해당폼의 명시적 선택항목으로 제공한다. 재고업무는 입고/출고/조정, 출고는 판매·증정·폐기·기타 사유 선택. 모바일 버튼 줄바꿈·키보드·선택상태 유지.

## 목록 페이지네이션 — WB56

페이지당개수 선택은 결과요약 가까이에 두고 현재표시범위/전체건수를 명시한다. 이전/다음과 제한된 페이지버튼으로 무제한행/버튼나열을 피한다. 현재페이지 aria-current, 불가능한 이동 disabled, 키보드포커스와 모바일줄바꿈을 제공한다. 조건/표시개수 변경시첫페이지로 돌아가고 데이터축소·0건에서 유효범위를 표시한다. 페이지별행수와 전체필터합계를 혼동하지 않도록 안내한다.

## 관리자 전체 목록 공통 페이지 UI — WB57

재고뿐 아니라 관리자 탐색목록은 공통 useListPagination과 ds-list-pagination 스타일을 사용한다. 여러목록이 있는 대시보드/보드는 각목록별로 독립된 상태와 고유한 라벨/ID를 제공한다. 집계는페이지전전체값, 진열순번은전체배열순서다. 필터resetKey를 명시하며 카테고리상위이름/편집대상/삭제판단은 전체데이터를 참조한다. 원문/입력용선택목록/조합미리보기는 탐색표와구분해 원래기능을 보존한다. 좁은패널에서도 컨트롤줄바꿈과44px터치영역을 검증한다.

## 재고 부족 상태 색상 — WB58

현재재고가 옵션별 기준 이하이면 low_stock 빨간배경/테두리/텍스트와 경고아이콘·부족 문구, 기준초과이면 stock_healthy 초록배경/테두리/텍스트와 확인아이콘·양호 문구를 사용한다. 기준수량은 배지 아래 유지한다. 색만으로 의미를 전달하지 않으며 라이트/다크 토큰과 강제색상모드 가독성을 유지한다. 상품의 게시준비 상태와 부족기준 판정은 구분한다.


## 재고에서 상품 상세로 이동 — WB59

관리자 목록의 상품명 등 상세 이동 링크에는 상시·호버 밑줄을 사용하지 않는다. 적절한 굵기와 작은 이동 아이콘, 은은한 호버 배경으로 클릭 가능함을 표현한다. 정확한 상품 ID로 이동하고 키보드 포커스와 44px 터치 영역을 확보한다. 정보가 없는 상품은 비활성 링크 대신 일반 안내 문구를 사용한다. 상세 조회와 수정은 구분하고 상세에서 기존 작업으로 연결한다.


## 상품 이미지 용도 구분 — WB61

시안/모델 착용/의류 단독은 독립 제목·설명·빈 상태·등록 진입을 가진 갤러리로 제공한다. 시안에는 관리자용 표기를 하고 고객용 이미지와 혼합하지 않는다. 이미지 비율을 왜곡하거나 자르지 않도록 contain 미리보기를 사용한다. 등록은 별도 화면에서 용도·파일 미리보기·필수 대체텍스트를 입력한다. 저장 중 중복 제출을 막고 실패 시 입력을 보존한다. 저장 성공은 실제 조회된 이미지와 대조해 상세에서 표시한다. 삭제는 대상 확인과 결과 안내를 제공한다. 모바일은 한 열, 테마·키보드·터치영역은 기존 공통 기준을 따른다.


## 공장 협업 화면 — WB62

내부 관리자 메뉴는 공장 협업, 공장 사용자는 별도 공장 포털을 사용한다. 공장 화면에 내부 관리자 메뉴를 표시하지 않는다. 상품 상세에서 담당 공장/시안 공유 설정과 추가 제작 요청을 연결한다. 계정·요청 목록과 발급·요청 등록은 별도 화면이며 기존 페이지네이션/검색초기화/저장완료 기준을 따른다. 공유 대상과 메모 공개 범위를 입력 가까이에 명시한다. 요청 수량과 보유재고를 혼동하지 않도록 구분하며 제작 완료를 입고 완료로 표시하지 않는다. 순차 상태 변경은 현재 상태·다음 동작·완료 안내를 함께 제공한다. 계정 비밀번호는 마스킹하고 저장된 비밀번호를 조회하거나 목록에 노출하지 않는다.


## 시안·샘플 진행 상태 — WB63

담당 공장과 작업 상태를 가까이 배치한다. 작업대기 회색, 시안확인중 파랑, 샘플작업중 노랑, 시안완료 초록의 공통 상태토큰과 명확한 문구를 함께 사용한다. 상세 상태 동작과 추가 제작 요청의 상태를 구분하고 시안 완료를 승인/게시/입고로 표현하지 않는다. 상품 상세는 상태 요약과 업무 진입만 제공한다. 전용 관리 상세는 조회·이력, 별도 변경 화면은 상태/공장공유메모 입력으로 분리한다. 저장 후 관리 상세로 복귀하며 큰 완료 안내·포커스 제공, 실패 시 입력 보존과 재조회 경로를 제공한다. 변경 이력은 시간·공장·행위자 구분·상태·메모와 공통 페이지네이션을 적용한다.


## 업무 요약·조회·변경의 분리 — WB64

상품 상세에 관련 업무의 전체 폼과 이력을 중첩하지 않는다. 담당자/현재상태/최근변경/업무 링크만 요약하고 실제관리는 전용메뉴에서 수행한다. 조회와 변경폼은 서로 다른화면으로 제공한다. 긴설명은 공통?도움말, 라벨-입력 space-2/필드 space-4/그룹및작업영역 space-6을 사용한다. 저장버튼은 desktop 내용폭의 주행동, mobile1열로 표시하고 전역width100%를 무조건 사용하지 않는다. 빈목록은 빈상태문구만 표시하며 의미없는0/0페이지·표시개수·이전다음은 숨긴다. 상태배지색을 timestamp 같은 포괄적인마지막자식선택자로 덮어쓰지 않는다.


## 모서리 형태 통일 — WB65 / R77

버튼(링크형 포함), 입력창·선택창·텍스트영역은 --radius-control(12px), 카드·패널·다이얼로그는 --radius-panel(12px)을 사용한다. 기본 button과 .button, .catalog-link-button, .catalog-panel부터 적용해 새 화면도 같은 기본값을 상속한다. 화면별 12px 하드코딩이나 space 토큰의 반경 사용을 피한다.

상태 배지·카테고리 칩은 --radius-pill(999px), 원형 도움말·선택 표시만 --radius-circle(50%)를 사용한다. 이미지·내부 보조 영역은 --radius-md(8px). 테이블 셀과 구분선은 직선 구조를 유지하며, 패널을 둥글게 만들기 위해 overflow:hidden을 일괄 적용해 포커스/선택 목록을 자르지 않는다. 라이트·다크·모바일에서도 같은 매핑을 적용하고 포커스 시 반경을 바꾸지 않는다.

검증 시 일반 button뿐 아니라 a 링크형 버튼, 폼 밖 조작부, 빈 상태·로그인·대시보드·작업 보드·공장 패널까지 계산 스타일을 확인한다. 근거: docs/reviews/radius-consistency.md.


## 목록 행의 관리 작업 — WB66 / R78

관리 열은 대표 작업 한 개(상품은 수정)와 더보기로 한 줄을 유지한다. 보조 작업(색상·사이즈 등록)은 더보기에 모으고 삭제는 구분선·위험 색·텍스트를 함께 사용한다. 아이콘만 반복하거나 좁은 열에서 버튼 라벨을 여러 줄로 줄바꿈하지 않는다. 재고 보기는 재고 요약 열에 유지한다.

작업별 최소44px, 상품 이름을 포함한 접근성 이름, 키보드 Tab/Enter/Space/Escape 및 외부클릭 닫힘을 제공한다. 더보기는 표 스크롤 영역에 잘리지 않는 top-layer popover이며 뷰포트 안에 배치한다. 스크롤·창 크기 변경 시 닫고 삭제 확인 취소는 더보기로 포커스를 돌린다. role=menu의 화살표 키 계약을 사용하지 않는 일반 링크/버튼 묶음은 role=group으로 제공한다. 삭제 확인과 서버 검증을 생략하지 않는다.

## 상품 요약과 시안 상세 — WB67

상품 상세 공장 요약은 이름+이동 표시+현재 상태로 구성한다. 공장명은 44px 이상, 밑줄 없이 파란색 동작 전용 토큰(--color-link-action 및 surface/border/hover), ‘시안 상세’ 동작 문구와 화살표로 링크를 구별한다. 최소48px의 둥근 직사각형 버튼 형태를 사용하고 작업대기 배지는 중립색 pill로 분리하고 나머지 진행 상태의 기존 의미 색상은 유지한다. 색상만으로 동작을 구분하지 않는다. 키보드 focus를 유지하고 라이트·다크 모두 같은 의미 토큰을 사용한다(WB69, WB68의 중립 배경 대체). 요약에 시안관리·공장설정·추가요청 버튼을 중복 배치하지 않는다. 공장 미배정도 시안 상세 링크로 설정 경로를 제공한다.

내부 시안 이미지 등록·목록·삭제는 시안 상세에 두고 모델/의류 고객용 이미지는 상품 상세에 둔다. 등록 화면의 종류 선택도 범위에 맞게 제한하며 저장 완료와 취소는 해당 이미지가 보이는 상세로 복귀한다. 기존 관리자 인증 및 공장별 명시적 이미지 공유 정책은 동일하다. WB64의 상품상세 이미지/공장버튼 배치는 이 규칙으로 대체한다.


## 상품 정보의 공장·시안과 이미지 입력 — WB70 / R80

공장·시안 요약은 별도 카드 대신 상품 정보 dl에 ‘담당 공장’과 ‘시안 진행 상태’ 두 항목으로 통합한다. 공장명+시안 상세 동작 버튼은 유지하고 상태 배지와 라벨을 구분한다. 미배정/조회 실패를 작업대기로 오인하게 표시하지 않는다. 모바일은 다른 정보와 같은 1열이다. 이 규칙은 WB67~69 별도 요약 카드 배치를 대체한다.

모든 이미지 종류(design/model/garment)의 등록 파일 입력은 드롭 영역과 네이티브 파일 선택을 함께 제공한다. 드래그 진입을 테두리·배경·문구로 표시하며, 파일선택과 drop을 같은 검증 경로로 처리한다. 현재 단일 등록 계약에 맞춰 여러 파일은 오류로 안내하고 임의로 첫 파일만 사용하지 않는다. PNG/JPEG/WebP·2MB 제한 및 서버 검증을 유지한다. 잘못된 선택은 기존 미리보기를 보존하되 유효한 재선택 전 저장을 막는다. 저장 중 drop을 차단하고 늦게 완료된 이전 읽기로 최신 선택을 덮어쓰지 않는다. 드롭은 자동 저장·이미지 순서 변경이 아니며 미리보기 후 등록한다. 키보드와 모바일 파일선택을 유지한다.

## 상품명과 운영 상태 — WB71

상품 상세 제목행은 왼쪽 상품명, 오른쪽 ‘상품 운영 상태’ 라벨과 아이콘·텍스트 배지를 배치한다. 좁은 모바일과 긴 이름에서는 자연스럽게 다음 줄로 배치하고 가로넘침을 방지한다. 시안 진행 상태는 상품정보 항목으로 유지하며 운영 상태와 합치지 않는다. 현재 미게시 표시의 사유는 키보드/터치로 여는 공통 도움말에 제공한다. 시안완료나 재고보유를 판매가능 배지로 바꾸지 않는다.

## 공장 협업 진입 — WB72

공장협업의 기본 화면은 시안 관리 목록이다. 관리 메뉴와 목록명은 시안 관리, 조회는 시안 상세, 상태 표시는 시안 진행 상태로 통일한다. 샘플 작업이라는 업무 단계 자체는 유지한다. 공통 하위메뉴에서 제작 요청 목록·추가 제작 요청·계정·공급처에 접근한다.

## 이미지 필수 입력 — WB73

시안 등록은 kind=design 고정이므로 종류 선택을 노출하지 않는다. 고객용은 model/garment 선택을 유지한다. 이미지 이름은 필수·최대120자, 설명은 선택·최대240자이며 선택 표기와 required 속성을 일치시킨다. 설명이 없을 때 목록/공장공유/미리보기의 이미지 대체텍스트는 이름으로 제공한다. 저장 데이터 alt는 빈 문자열을 유지해 사용자가 입력한 설명과 구별한다.

## 기존 옵션 기준 수정 — WB74

신규등록의 공통적용 입력은 기존옵션 수정이 아니다. 대상0개면 공통입력을 비활성화하고 기존옵션은 재고현황에서 수정하도록 명시한다. 재고현황의 각 옵션 부족상태 옆에 부족 기준 수정 진입을 제공한다. 수정 URL은 대상요약/현재재고/기준입력만 두고 전체 목록·이력을 넣지 않는다. 저장 확정 후 SaveResult로 대상·전후 기준·실제재고 불변과 목록으로 돌아가기를 제공한다. 버전충돌/불확실 실패는 입력을 유지하고 최신조회 전 재저장을 차단한다. 성공 뒤 조회 실패는 저장 실패로 표현하지 않는다.


## 상품 상세 중심 작업 — WB75

상세는 기본정보·색상/사이즈·재고 구역으로 나누고 구역 제목과 대표 작업을 같은 행에 둔다. 모바일에서는 1열로 배치한다. 옵션은 공통 페이지네이션을 사용하고 부족/양호 배지를 유지한다. 신규 옵션 추가와 기존 부족기준 수정을 구별하며 실제 수량은 입출고·조정 화면에서 변경한다.

상품 등록/수정·옵션 등록·기준 수정의 저장 완료 기본 동작은 ‘상품 상세로’다. 상품 상세에서 시작한 재고 변경도 동일하게 적용한다. 대상 상품은 URL의 식별자와 서버 결과로 결정하며 임의 return URL은 받지 않는다. 재고 메뉴에서 직접 시작한 등록은 기존 이력 복귀를 유지한다. 저장 전 취소는 상품 상세로 돌아간다. 완료 결과와 초점·실패 입력 보존 규칙은 그대로 유지한다. 상세에서 입력폼이나 전체 입출고 이력을 중복 제공하지 않는다. WB74의 부족기준 저장 후 기본 복귀를 상품 상세로 대체한다.

상품 문맥에서 진입한 옵션 등록은 대상 상품을 고정하고 상품명·내부 관리명을 표시한다. 일반 옵션 등록 진입만 상품을 선택한다. 추가등록 초점은 비활성 선택기가 아니라 색상 선택 영역으로 이동한다.


## 옵션 사용 상태 — WB76 / R86

상품 상세 색상·사이즈 표는 사용 상태 열과 재고 상태 열을 분리한다. 사용 중은 동작 계열의 연한 파란 배경, 사용 안 함은 중립 배경의 텍스트 배지로 표시하고 부족/양호의 빨강/초록과 혼동하지 않는다. 사용 안 함 옵션도 표와 재고 합계에 포함한다.

행의 ‘옵션 수정’은 별도 URL로 이동한다. 색상·사이즈·현재 수량은 대상 요약으로 표시하고 사용 여부와 부족 기준만 편집한다. 완료 결과는 두 항목의 전후값·실제재고불변·상품상세복귀를 제공한다. 실패 때 두 입력을 보존하고 최신 버전 조회 전 재저장을 차단한다. 저장완료 후 조회실패는 완료결과를 지우지 않는다. 과거 부족기준 수정 URL은 옵션 수정으로 연결한다.


## 핵심 값의 시각적 위계 — WB77 / R87

중요한 판단값(사용상태·현재수량·부족기준·확정변경값)은 라벨·설명과 같은 본문 줄에 묻지 않는다. 공통 KeyFacts로 라벨/값/보조설명을 분리하고 핵심 값은 text-2xl·굵기750·tabular 숫자로 강조한다. 상품명·선택옵션은 식별 제목, 관리코드와 긴 설명은 text-sm·secondary로 낮추되 숨기지 않는다. 표의 수량은 text-lg·굵게, 상태는 텍스트 배지로 유지한다.

한 구역 핵심값은 2~3개로 제한하고 모두 같은 강도로 강조하지 않는다. 저장결과는 ‘변경 전’과 ‘저장 후’를 명시하며 확정된 새 값을 우선 강조한다. 실제재고 불변은 별도 카드와 ‘변경 없음’ 설명으로 구분한다. 배경/테두리·24px 간격으로 묶고 모바일은 1열, 다크 테마는 의미 토큰을 사용한다. 상태의 색상만으로 의미를 전달하지 않는다. 금액·주문상태 등 향후 중요한 값에도 동일한 기준을 적용하되 화면별 우선순위를 정한다.


## 관리자 전체 적용 기준 — WB78 / R88

화면을 만들거나 수정할 때 먼저 핵심 판단값 2~3개와 보조정보를 명세에 적는다. 조회 요약/확정 결과는 KeyFacts, 작은 행 상태는 ValueStatus 또는 기존 업무별 StatusBadge/ProgressBadge를 사용한다. 값 없는 화면에 숫자 카드를 억지로 추가하지 않는다.

- 대시보드: 업무량·지연·부족은 큰 요약값, 표에서는 입고량/가용수량 강조. 샘플 표시 유지.
- 상품/재고: 상품명·현재수량·증감/확정수량·준비/사용상태 우선. 변경 미리보기는 ‘입력/예상’, 완료는 ‘확정/저장 후’로 구별한다.
- 분류/기준정보/공급처/계정: 이름과 사용상태를 먼저 표시, 코드·버전·설명은 보조. 연락처 등 긴 값은 줄바꿈을 보장하고 불필요한 거대카드로 만들지 않는다.
- 공장협업: 대상상품·담당공장·진행상태·제작수량/희망일 중 해당화면 핵심만 강조. 시안 상태와 제작요청 상태 및 입고를 혼합하지 않는다.
- 이미지: 이미지 자체와 이름이 주정보, 설명/종류/코드는 보조. 업로드 입력·저장완료 구별 유지.
- 진열: 공개설정·선택상품수·진열순서 강조. 공개로 설정해도 상품0이면 실제노출 안 된다는 설명을 유지한다.
- 작업보드: 상태별건수·우선순위·작업제목 우선, 검증근거/담당/ID는 보조. 링크형요약의 이동기능은 유지한다.

목적 배지(샘플/완제품)와 진행 상태를 분리해 표시한다. 목록은 상품/공장·목적·핵심 수량·현재 단계 중심으로 묶고 코드/긴 메모는 상세에 둔다. 발송/실수령/합격/불량/누락 수량은 단위와 라벨을 함께 표현한다. 샘플에는 판매 재고 미반영, 완제품에는 입고 확정 전 미반영을 명확히 표시한다. 목록/등록/수령입력/검수입력은 별도 URL이며 상세에서 현재 단계의 다음 동작만 강조한다. 입고 확정은 반영할 SKU별 합격 수량을 확인할 수 있어야 하고 중복 클릭을 차단한다. 성공은 서버 확정 상세로 복귀하여 결과를 표시하고 실패는 입력을 보존한다. 검색·필터 변경시 첫페이지, 모바일1열, 상태색+텍스트, 다크/확대와 세로중앙정렬 기준을 준수한다.

## 관리자 홈 실제 재고 — WB13
실제 재고 요약은 샘플 운영 영역 앞에 독립 구역으로 제공한다. 핵심 값은 보유 총수량(개), 부족 옵션(개 조합), 전체 옵션 수이며 각 값의 단위를 구분한다. 보유 수량을 가용/판매 가능으로 바꾸어 부르지 않는다. 조회 시각과 새로 조회 동작을 제공하고 로딩·조회 실패를 0으로 대체하지 않는다.

요약 카드 전체가 해당 재고 목록으로 이동하는 링크이며 방향 표시·hover 배경·키보드 포커스로 클릭 가능성을 나타낸다. 부족은 빨강과 명시적 문구, 부족 없음은 초록과 문구를 함께 사용한다. 부족 옵션 미리보기는 최대5개로 제한하고 전체 목록은 별도 URL로 연결한다. 상품명·현재 수량·부족 기준을 먼저, 내부코드와 사용 여부는 보조 정보로 표시한다. 모바일1열·다크·확대에서도 간격/단위/포커스를 확인한다. 샘플 운영 현황의 재고 숫자·표·재고 업무를 중복 제공하지 않는다.

## 실제 고객 상품 탐색·게시 — WB87
고객 화면은 의류 이미지·상품명·가격(입력된 경우)·품절 상태가 우선이다. 관리자 코드·공장·시안 진행·정확한 잔고·개발 상태를 고객에게 노출하지 않는다. 상품 카드 전체를 상세 링크로 만들고 이미지 비율을 통일한다. 모바일에서는 글자 확대 시 카드와 필터가 줄바꿈하며 읽을 수 있는 폭을 유지한다. 이름은 잘라 숨기지 않고 필요한 줄바꿈을 허용한다.

검색/카테고리/색상/사이즈/재고 조건은 URL에 유지하고 조건 변경은 첫 페이지부터 보여준다. 적용된 필터와 초기화 동작을 명확히 구분한다. 색상·사이즈 복합 필터는 실제 같은 옵션 조합에 해당해야 한다. 없는 조합과 품절은 명시적 문구로 구분하고 색만으로 표현하지 않는다. 미입력 가격을0원으로 표시하거나 구매 기능이 없는 버튼을 노출하지 않는다.

상세는 상품 이미지와 정보/옵션 영역을 나누고 모바일1열로 배치한다. 썸네일 선택은 이름·선택상태·키보드 포커스를 제공한다. 이미지 대체텍스트는 이름/설명에서 제공하며 내부 시안은 고객 갤러리에 섞이지 않는다. 목록 복귀 시 기존 검색 조건을 유지한다. 빈 결과와 상품 없음/게시중지, 조회 실패를 구분한다. 홈은 기존 시즌/커스텀 진열 설정을 따르되 실제 공개 상품만 보여준다.

관리자는 상품 타이틀 옆 게시 상태를 확인하고 별도 게시 설정 화면에서 저장한다. 게시 조건과 차단 사유, 고객 노출 여부를 짧고 구체적으로 제공한다. 저장 후 서버 확정 결과를 표시하며 상품 상세로 복귀하고, 실패/버전충돌 시 입력을 보존한다. 시안 상태·재고 상태·게시 상태를 같은 상태값으로 합치지 않는다.

WB87 실제 검증 보완: FormSelect를 사용하는 고객 필터와 페이지 크기 컨트롤도 공통 `ds-form` 범위 안에 배치한다. 컴포넌트 import만으로 스타일 적용을 가정하지 않는다. 기본 select와 커스텀 trigger가 동시에 노출되지 않는지 실제 렌더에서 검사하고, 기본 select는 접근성/폼 동작을 보존한 숨김 상태여야 한다. 옵션 팝업·포커스·모바일 확대를 함께 확인한다.

고객 FormSelect의 라벨도 FormLabel을 사용하거나 컴포넌트의 aria-labelledby가 가리키는 실제 라벨 ID를 제공한다. 화면에 글자가 보이는 것만으로 접근성 이름이 연결되었다고 판단하지 않는다. 각 combobox의 라벨 대상 존재와 접근성 이름을 실제 DOM에서 검증한다.

## 화면 목적별 디자인 기준 — WB89
공통 토큰·접근성·기본 컴포넌트 계약은 본 문서에서 공유한다. 고객 쇼핑의 시각적 표현과 탐색 배치는 [고객 디자인 시스템](design-system-customer.md), 내부/공장 업무 화면의 정보 밀도와 처리 흐름은 [관리자 디자인 시스템](design-system-admin.md)을 기준으로 구현한다. 과거 고객/관리자 혼합 표현과 충돌하면 최신 목적별 기준을 우선한다. 고객 상세 필터 기본 펼침은 WB89의 기본 닫힘 토글 규칙으로 대체한다.

## 상품 상세 편집 통합 — WB95
최신 사용자 지시에 따라 상품 상세 /admin/catalog/{id}는 기본정보·가격·할인·공개 설정의 편집 화면을 겸한다. WB75의 '상세에서 입력폼 없음'과 WB87의 '별도 게시 설정 화면'은 이 두 구역에 한해 대체된다. 목록/신규 등록은 계속 별도 URL이다. 상세의 해당 상품 옵션·재고 요약·고객 이미지는 대상 문맥이며 전체 상품 목록·원장 이력을 붙이지 않는다.
각 구역은 자체 저장 버튼과 SaveResult로 저장 대상·확정 결과·계속 수정/목록 이동을 표시한다. 저장 시 다른 구역의 미저장 입력을 보존하며 부모 요약 갱신으로 폼을 재생성하지 않는다. 기본정보 저장은 확정 응답으로 제목을 갱신한다. 가격 저장 뒤 요약 조회 실패는 완료 결과를 유지하고 별도 재조회 버튼으로 복구한다. 409/불확실 응답은 입력 보존 및 최신 상태 확인 후 재저장한다. 기존 두 수정 URL은 상세의 기본정보/가격 앵커로 연결한다. 상세에는 상품별 리뷰 관리·가격 이력 접근을 유지한다.

## 상품 상세 활성 탭 — WB96
WB95의 통합 편집은 기본정보·가격/할인·색상/사이즈·재고·리뷰 관리 탭으로 구분하며 한 패널만 표시한다. 활성 탭의 현재 시각 기준은 WB97의 은은한 배경·짧은 하단선이며, 초기 강한 반전 배경과 문자 밑줄은 대체되었다. tablist/tab/tabpanel, aria-selected/controls/labelledby와 roving tabindex, 좌우/Home/End 키를 지원한다. 숨김 패널은 상태를 보존하되 접근성 트리/탭 순서에서 제외한다. hash 직접 진입/가격 바로가기도 활성 선택과 일치한다. 고객 이미지는 기본정보, 현재 상품 리뷰 목록은 리뷰 패널에 포함하며 개별 리뷰 처리/원장 입력 업무는 기존 경로를 유지한다.

## 상품 상세 탭 시각 보완 — WB97
사용자 피드백에 따라 WB96의 강한 반전 배경/문자 밑줄 대신 테두리 없는 탭, subtle 배경, 2px 하단 표시, 500/600 글자 굵기를 사용한다. 포커스는 탭 버튼 내부 focus-visible 테두리로 제공한다. 패널의 불필요한 tabIndex는 제거하고 내부 입력/링크로 순차 이동한다. 모바일에서는 버튼 전체 너비 강제를 해제해 자연스럽게 줄바꿈한다. 동작 줄이기 설정에서는 색상 전환을 제거한다.

## 관리 목록 짝수 행 배경 — WB98
모든 관리 표는 관리 레이아웃에 연결된 공통 management-lists.css를 사용한다. tbody에서 표시 중인 2·4·6·8번째 행에 --management-row-stripe(subtle70% + surface30%) 배경을 적용하고 홀수 행은 유지한다. 헤더는 WB99의 전용 배경과 구분선을 사용한다. 필터·페이지 변경 후 표시 순서 기준으로 재계산한다. 경고·선택 행 및 셀의 명시적 배경은 우선한다. 관리자/공장 대시보드 세로 목록과 작업 보드 작업 카드도 짝수 항목을 구분한다. 사진 격자·요약 카드·폼 선택지는 행 목록이 아니므로 제외한다. 고객 화면에는 적용하지 않는다. 새 관리 표는 같은 범위에서 자동 적용되며 새로운 비표형 세로 목록은 공통 스타일의 대상에 추가한다.

## 관리 표 헤더·행 위계 — WB99
공통 management-lists.css에 헤더/짝수행 토큰을 분리한다. --management-table-header는 text10%+surface90%, --management-row-stripe는 subtle70%+surface30%다. thead 셀에는 헤더 배경·텍스트색·600 굵기·2px 하단선을 사용하여 행 줄무늬와 구분한다. --management-table-header-border는 text25%+line75%다. 관리자·공장 양 테마에 공통 적용하고 페이지별 헤더 색상으로 덮어쓰지 않는다. 상세 업무 기준은 design-system-admin.md에도 동일하게 반영한다.

## 상품 상세 정보 입력·표시 — WB88
관리자 기본정보 탭/상품 등록에서 소재·혼용률, 세탁·관리, 실측 반복 행, 측정 참고사항을 입력한다. 선택 입력임을 명시하고 실측 행을 추가한 경우 사이즈/측정부위/cm 값은 필수다. 행 추가 시 첫 입력에 포커스, 삭제 시 추가 버튼으로 복귀한다. 일반 상품 저장 버튼으로 함께 저장하며 SaveResult에 확정 상세정보를 표시한다. 초안은 탭 왕복/409 재조회에서 보존한다. 재고/가격 입력과 분리한다.
고객 상품 상세에는 값 있는 섹션만 표시한다. 실측은 사이즈×측정부위 표, cm 단위와 행/열 헤더, 미측정 조합 —, 모바일 가로 스크롤을 제공한다. 자유 입력은 plain text로 렌더링하고 줄바꿈/긴문자 넘침을 처리한다. 허위 기본 안내는 넣지 않는다.

## 고객 소셜 인증·장바구니 완료 피드백 — WB100
고객 쓰기 화면도 공통 SaveResult와 서버 확정값·후속 동작·모바일 포커스를 따른다. 로그인은 공급자 미설정/조회실패/동의취소를 성공으로 보이지 않게 한다. 고객 장바구니의 수량/삭제는 쇼핑 목록 내 직접 조작이며 관리자 화면 분리 규칙과 구분한다. 상세 UX는 design-system-customer.md, 보안·API 계약은 contracts/customer-shopping.md.


## 고객 모바일 변형 — WB103
고객 헤더/nav·하단 설정 패널·본문 글자/간격은 [고객 모바일 기준](design-system-customer.md#모바일-화면-기준--wb103--r106)을 따른다. 공통 space/색상/포커스 토큰을 유지하며 `.customer-*`/`.shop-*` 범위로 분리한다. 관리자/공장의 밀도와 모달 기본 크기를 변경하지 않는다.

WB105 고객 계정 disclosure 및 빈 장바구니 기준은 docs/design-system-customer.md에 기록한다. 고객 범위 CSS와 의미 토큰을 재사용하며 관리자 화면에는 적용하지 않는다.

WB108 브랜드 소개의 고객 스토리·예시 caption과 관리자 상태/편집/미리보기/게시·SaveResult 기준은 design-system-customer.md 및 design-system-admin.md에 기록한다.

## 관리자 메뉴 그룹/표시 설정 (WB112)
사이드바 그룹 제목은44px disclosure 버튼과16px chevron, aria-expanded/controls로 상태를 표시한다. 숨긴 그룹/메뉴와 보이는 자식이 없는 그룹은 탐색에서 제외한다. 현재 경로는 기존 active 표시를 유지하고 경로 이동 시 그룹을 펼쳐 현재 위치를 찾도록 한다. 고정 '메뉴 관리'는 표시 설정 밖에 둔다. 조회 실패는 기본/마지막 확인 메뉴와 오류·재시도를 명시한다.
메뉴 관리 상태 URL과 편집 URL은 분리한다. 편집의 그룹/메뉴 항목은 단일설정 입력 대상이며 별도 업무목록이 아니다. 그룹명/표시 체크·순서 위아래·메뉴 이동 select는 키보드로 조작할 수 있어야 한다. 숨김은 권한 차단이 아님을 안내한다. SaveResult에는 서버 확정버전/그룹수/표시메뉴수와 상태·계속편집 링크를 제공하고 모바일 포커스를 옮긴다. 409/불확실응답은 입력을 보존하고 최신버전 확인 전 저장을 막는다. 자동 기본복원/자동덮어쓰기는 금지한다.


WB113 GNB 위계: 그룹은 primary/650 굵기, 하위 링크는 그룹보다 약21px 들여쓰기와 1px 세로 가이드선, secondary/400 굵기로 구분한다. 활성 하위항목만 primary/650·subtle 배경·안쪽2px 표시를 사용한다. 조작영역44px와 접기/키보드·모바일 구조는 유지하며 하위 사이 간격은2px로 정리한다.

## 관리자 사용 가이드 (WB114)

가이드 원문은 apps/web/src/lib/admin-guide.ts 단일관리. 읽기전용 관리자 화면에서 검색→업무별 목차→준비→번호순서→완료확인→주의사항으로 표시한다. 단계 링크는 실제 관리화면으로 연결하며 URL 직접입력도 인증한다. 관련 기능 수정 시 가이드 동기화와 검증 기록을 완료조건에 포함한다. 세부 화면 기준은 관리자 디자인 시스템을 따른다.

WB116: 캡처 미리보기는 원본보다 확대하지 않고 높이520px 및 본문 가용폭 이내에서 종횡비를 유지한다. 이미지 실제 치수를 manifest와 img에 명시하고 표식은 여백 없는 동일 이미지 래퍼 기준으로 배치한다. 확대 창은 원본 해상도 스크롤을 유지한다.

WB118: 고객 상품 상세 미선택 옵션 CTA는 클릭 가능한 안내 동작으로 유지한다. 첫 누락 옵션에 인라인 오류·포커스·스크롤을 제공하며 유효하지 않은 복귀 옵션도 재선택 안내한다. 상세 docs/design-system-customer.md.

WB119 관리자 PG 도입 준비: 읽기전용 자료와 문의문 복사. 저장·견적발송 기능이 아니며 복사 결과/수동복사 복구를 명시. 디자인 기준 docs/design-system-admin.md.

## WB137 색상칩·옵션 미리보기
공통 ColorChip은 고객·관리자 모두26px 원형, 표면색2px 간격·테마 기반1px 외곽링·약한 그림자로 통일한다. 고객 카드 칩 간격은10px이다. 현재 색상명 기준 대표색이며 실물 색상 보장이 아니다. 알려진 이름만 매핑하고 미지정은 사선 칩과 이름을 표시한다. 관리자에서는 색상명을 항상 병기한다. 고객 홈/목록 카드에는 가격 아래 등록 색상과 중복 제거한 사이즈를 표시하며 구매 가능한 조합/품절은 상세에서 확인한다. 색상칩 자체는 선택/재고 변경 동작이 아니다.

WB137 최신 카드 옵션 기준(사용자 참고 이미지 반영): 고객 카드 색상칩26px·표면색2px 간격·1px 외곽링·약한 그림자, 아래12px 영문 색상명. 알려진 대표색만 영문명을 표시하며 사용자 정의 이름은 보존한다. 사이즈는 S/M/L 등 알파벳을30px 사각 배지에 표시한다. 적은 옵션은 한 줄에 배치해 카드 높이를 줄이고 옵션이 많으면 줄바꿈한다. 관리자도 같은26px 링 칩을 사용하고 옆에 기존 색상명을 병기한다.

WB137 모바일 검증: 기본 글자 크기의 상품 목록은 2열을 유지하여 상품1개가 전체 너비로 확대되지 않게 한다. 큰 글자 설정의1열 예외는 유지한다. 색상·사이즈는 flex wrap으로 넘침 없이 표시하며 다수 옵션의 추가 높이는 자연 줄바꿈으로 허용한다.

## WB142 상품 상세 선택 옵션
상품 상세도 공통26px ColorChip과 카드의 사이즈 표시 helper를 사용한다. 칩 아래 영문 대표색, 사이즈는 S/M/L 등34px 사각 배지(표시전용 카드30px보다 큰 선택용), 버튼 터치영역 최소44px. 선택 색상은 바깥 링과 굵은 이름, 선택 사이즈는 반전 채움, 키보드 포커스는 별도 outline. 품절은 점선·취소선·품절 문구로 구분하고 선택하여 안내를 읽을 수 있지만 구매/담기는 기존 검증으로 차단한다. SKU 선택·OAuth 복귀에는 원래 색상/사이즈 값을 유지한다. 미지정 색상/사용자 사이즈는 임의 번역하지 않는다. 현재 고객 상세만 변경하여 관리자 가이드 영향 없음.
# 주문 조회 화면 (WB143, 2026-11-01)

WB148 검색 폼의 공통 컨트롤 높이는44px로 범위 제한하여 통일한다. 모바일390px에서는 검색대상·액션을 첫줄, 검색어를 둘째줄로 배치한다. 선택 문구는 한줄 유지, 입력16px. 359px 미만은 대상/검색어/액션3줄로 전환한다. 반응형 검증 후 viewport 해제 호출뿐 아니라 사용자 PC의 실제 너비와 배치까지 확인한다.

WB147 기본 검색은 검색대상·검색어·상세 필터 아이콘·초기화·검색을 PC 한 줄/모바일 두 줄로 배치한다. 영역 패딩12px·간격8px. 아이콘은 슬라이더 형태, 최소44px 터치영역, title/접근성 이름·펼침 상태 및 적용 개수 숫자 배지를 제공한다. 검색 입력의 시각 라벨은 생략하되 접근성 label은 유지한다. 날짜와 상태의 라벨은 펼친 영역에 유지한다.

WB146 상세 필터는 기본 접힘. 기본 검색은 항상 표시하고 기간/상태 조건만 펼친다. 버튼의 방향 아이콘·aria-expanded·적용 개수로 상태를 알린다. 접어도 조건은 유지하며 초기화로 해제한다. 입력 오류가 숨겨진 영역에 있으면 펼쳐 안내한다.

고객과 관리자 주문 목록·상세는 `SalesOrders`를 공유한다. 목록과 상세는 별도 URL이며 목록 짝수 행은 옅은 배경으로 구분한다. 상태는 문구와 배지로 표시하고 주문·결제·배송 상태를 상세에서 분리한다. 필터는 FormSelect, 이동·재조회 버튼은 동일한 44px 이상 규격을 사용한다. 상세는 PC 2열, 작은 화면 1열이며 금액은 줄바꿈하지 않는다. 옵션은 공통 ColorChip과 알파벳 크기 배지로 표시한다. 빈 목록·조회 실패·로딩은 서로 구별하며 합성 주문을 명시한다. 조회 전용이므로 저장 완료 패턴은 적용하지 않는다.

WB145 관리자 상세 검색: 목록 위 별도 테두리 영역에 검색 대상·검색어, 주문일 기간, 주문·결제·배송 상태를 묶는다. 입력은 공통 색상 토큰과 FormSelect, 검색은 강조 버튼/초기화는 보조 버튼. PC 다열·모바일 1열로 배치하고 입력 높이 최소48px, 버튼44px 이상. 검색 버튼/Enter로 조건을 적용하며 초기화 시 첫 페이지 전체 결과로 돌아간다. 목록 표시 건수는 전체 합계가 아닌 현재 페이지 건수임을 명시한다. 개인정보 검색어를 페이지 URL이나 영구 저장소에 유지하지 않는다.
