# 관리자·공장 업무 디자인 시스템

적용: `/admin`, `/factory`의 로그인·대시보드·목록·등록·수정·상세. 공통 토큰과 저장 규칙은 [공통 디자인 시스템](design-system.md)에 정의되어 있으며 본 문서는 업무 화면 적용 기준이다. 고객 쇼핑 화면은 [고객 디자인 시스템](design-system-customer.md)을 따른다.

## 목적과 정보 위계
정확한 업무 판단과 처리 속도를 우선한다. 상품명/대상·현재 상태·수량·처리 기한을 먼저 보여주고 기술 코드·긴 메모·변경 이력은 보조 정보로 묶는다. 화면별 핵심값은2~3개를 선정해 굵기·단위·의미 색상으로 강조한다. 재고 부족은 빨강+문구, 양호는 초록+문구다.

## 업무 화면 구성
- 대시보드는 실제 집계·현재 업무·정확한 상세 링크를 제공한다. 샘플과 실제 데이터는 명확히 구분한다.
- 목록·등록·수정은 별도 URL이다. 목록은 검색/필터·요약·페이지당 개수·페이지 이동을 지원하며 필터 변경시 첫 페이지로 이동한다.
- 표의 텍스트·수량·행 버튼은 세로 중앙 정렬한다. 코드/설명 때문에 중요한 상태와 동작이 밀리지 않도록 한다.
- 항목이 많은 폼은 본문 폭을 활용하고 연관 필드를 구역으로 묶는다. 모바일은1열이다. 필수값은 별표와 접근성 정보를 제공한다.
- 주요 작업은 목록 위나 상세의 명확한 동작 영역에 둔다. 긴 목록 아래까지 내려가야만 등록할 수 있게 하지 않는다.
- 고객용 이미지 중심 배치와 장식 효과를 업무 폼·재고 표에 그대로 적용하지 않는다.

## 저장·권한
공통 디자인 시스템의 서버 확정 결과·실패 입력 보존·중복 저장 차단·충돌 재조회 규칙을 따른다. 저장 완료 후 업무 문맥에 맞는 상세/목록으로 복귀하고 결과를 명확히 표시한다. 별도 완료 화면은 사용자 승인된 흐름에만 유지한다. 공장 역할은 본인 범위만 제공하고 실제 권한은 서버에서 검증한다.

## 공통 컴포넌트와 검증
KeyFacts·StatusBadge·FormLabel·FormSelect·SaveResult 등 기존 공통 컴포넌트를 우선 사용한다. 라운드·간격·입력 높이·아이콘 크기는 공통 토큰을 사용한다. 고객 화면 전용 CSS가 관리자/공장 화면에 누출되지 않는지 확인한다. 저장/오류/직접URL인증·키보드·모바일·다크·확대 검증과 독립 검증 근거를 남긴다.

## 가격·리뷰 관리 — WB91
상품 상세에서 가격과 가격/이력 관리 경로를 명확히 표시한다. 리뷰 목록은 상품·별점·공개상태를 우선하고 긴 본문/이력은 별도 수정 화면에서 확인한다. 숨김/복원·답변 저장에는 사유를 기록하고 저장 후 목록으로 복귀해 일회성 결과를 표시한다. 실패 입력 보존·버전 충돌 재조회·고객 삭제 리뷰 변경 금지를 적용한다. 리뷰 평균을 직접 수정하는 입력은 만들지 않는다.

## 할인 가격 설정 — WB92
기본 판매가격과 할인 판매가격 입력을 구분하고, 할인 적용은 토글로 명시한다. 입력 옆 고객표시 미리보기에 기본가·할인율·최종 판매가격을 보여준다. 서버 검증 전 미리보기는 저장결과가 아니다. 저장 후 상품상세에서 확정 가격을 확인하고 이력은 별도화면에 기본/할인/최종값을 표시한다. 오류/충돌 시 입력은 보존한다.

## 상품 상세 통합 편집·탭 — WB95~97
상품 상세에서 기본정보·가격/할인·공개 설정을 직접 수정한다. 기본정보·가격/할인·색상/사이즈·재고·리뷰 탭 중 하나만 표시하며 다른 탭의 초안/저장 결과를 보존한다. 각 구역은 자체 저장 버튼과 SaveResult를 사용한다. 구 수정 URL은 해당 상세 탭으로 연결한다. 목록·신규 등록/재고 원장은 별도 유지한다.
탭은 테두리 없는 버튼, subtle 선택 배경·2px 짧은 하단 표시·500/600 굵기를 사용한다. 흰 반전 버튼과 문자 밑줄을 겹치지 않는다. ARIA 탭/키보드 이동·버튼 내부 focus-visible·모바일 줄바꿈을 유지한다.

## 관리 목록 표·세로 목록 — WB98~99
관리자·공장 레이아웃의 `components/ui/management-lists.css`가 공통 구현이다.
- 홀수 행: 기존 기본 배경.
- 짝수 행(2·4·6·8…): `--management-row-stripe` = subtle70% + surface30%, 행 간격은 변경하지 않음.
- 헤더: `--management-table-header` = text10% + surface90%, 본문보다 뚜렷한 배경과 600 굵기. 하단2px 선은 `--management-table-header-border` = text25% + line75%.
- 헤더/홀수/짝수 배경은 light/dark 모두 구분되어야 한다. 경고·선택 행/셀의 명시적 상태 배경은 유지한다.
- 필터/페이지의 표시 순서 기준으로 계산한다. 공통 표 외 대시보드 업무/문의/배송/부족재고·공장 업무·발송/공장/리뷰 이력·작업 보드 세로 목록도 짝수 항목 배경 적용.
- 사진 격자·요약 카드·입력 선택지는 행 목록이 아니므로 제외한다. 고객 화면에는 스타일 범위를 적용하지 않는다.
- 새 관리 표는 자동 적용된다. 새 비표형 목록은 공통 CSS의 범위에 등록한다. 개별 CSS로 독자적인 줄무늬/헤더 색상을 만들지 않는다.

## 고객용 의류 상세 입력 — WB88
상품 기본정보 탭과 등록 폼에서 소재·혼용률/세탁·관리/실측(cm)/측정 참고사항을 선택 입력한다. 사이즈·측정부위·값 반복 입력은 모바일2열/필드별 레이블을 사용하고 추가/삭제 포커스를 유지한다. 저장은 기본정보와 함께, 완료 결과에 서버 확정 정보를 표시한다. 새 입력은 SKU/가격/재고를 변경하지 않는다. 경계/실패/409 입력 보존 기준은 docs/contracts/product-details.md와 공통 저장UX를 따른다.

## 시안 미리보기 연결 복구 — WB83
관리자 스튜디오의 WebGL 연결 손실은 저장 실패와 구분한다. 입력·나염·서버 저장 기능을 유지하고 같은 화면에서 미리보기 복구 버튼을 제공한다. 연결이 끊긴 동안 다른 입력이 오류 안내를 덮지 않으며, 복구 성공/실패를 상태 영역에 표시한다. 드래그 중 손실은 드래그를 종료해 입력 잠김을 방지한다. 기존 schema1의 다시 시작과 schema2의 미리보기 복구는 문서 초안을 초기화하지 않는다.

## 브랜드 소개 편집/게시 (WB108)
사이트관리 진입→브랜드소개 상태→편집→SaveResult→상태/저장된초안미리보기→게시→SaveResult. 단일콘텐츠로 신규등록/전체목록은 없고 상태/입력은 별도 URL. 현재 저장버전과 게시버전을 구별하며 미리보기는 초안 표시를 명시. 이미지업로드 완료는 '초안 저장 필요'로 구분. 초안저장/게시 성공은 서버응답의 제목/버전과 다음행동을 공통 SaveResult로 표시, 모바일 제목focus. 실패/충돌/불확실시 입력 보존 및 최신버전 확인 후 재시도. 공개/초안 이미지는 각각 권한 경로를 사용.

## 관리자 왼쪽 탐색 (WB111)
인증된 관리자 화면만 240px 왼쪽 사이드바에 브랜드·관리자 세션·설정·주메뉴·쇼핑몰/로그아웃을 배치한다. 현재 메뉴는 subtle 배경/왼쪽 선/굵기로 표시. 1023px 이하에서는 상단 메뉴 버튼으로 펼치는 본문 흐름형 패널. 제목 기본28px/구역20px, 대시보드 패널20px 여백, 조작 최소44px. 글자 크기는 rem으로 확대설정 유지. 관리자 이름/이메일은 현재 인증 계약에 없으므로 임의 생성하지 않는다.

## 관리자 메뉴 그룹/표시 설정 (WB112)
사이드바 그룹 제목은44px disclosure 버튼과16px chevron, aria-expanded/controls로 상태를 표시한다. 숨긴 그룹/메뉴와 보이는 자식이 없는 그룹은 탐색에서 제외한다. 현재 경로는 기존 active 표시를 유지하고 경로 이동 시 그룹을 펼쳐 현재 위치를 찾도록 한다. 고정 '메뉴 관리'는 표시 설정 밖에 둔다. 조회 실패는 기본/마지막 확인 메뉴와 오류·재시도를 명시한다.
메뉴 관리 상태 URL과 편집 URL은 분리한다. 편집의 그룹/메뉴 항목은 단일설정 입력 대상이며 별도 업무목록이 아니다. 그룹명/표시 체크·순서 위아래·메뉴 이동 select는 키보드로 조작할 수 있어야 한다. 숨김은 권한 차단이 아님을 안내한다. SaveResult에는 서버 확정버전/그룹수/표시메뉴수와 상태·계속편집 링크를 제공하고 모바일 포커스를 옮긴다. 409/불확실응답은 입력을 보존하고 최신버전 확인 전 저장을 막는다. 자동 기본복원/자동덮어쓰기는 금지한다.


WB113 GNB 위계: 그룹은 primary/650 굵기, 하위 링크는 그룹보다 약21px 들여쓰기와 1px 세로 가이드선, secondary/400 굵기로 구분한다. 활성 하위항목만 primary/650·subtle 배경·안쪽2px 표시를 사용한다. 조작영역44px와 접기/키보드·모바일 구조는 유지하며 하위 사이 간격은2px로 정리한다.

## 사용 가이드 (WB114)
sidebar 하단에 고정 '사용 가이드' 링크를 두고 현재페이지 active를 표시한다. 본문은 검색·목차·번호목록·완료확인 순서이며 변경되지 않는 준비사항을 먼저 둔다. 데스크톱 목차+본문, 좁은화면1열. 제목/본문 토큰과44px 링크·버튼을 사용한다. 검색0건 안내와 초기화를 제공하고 주의사항은 native details로 펼친다. 안내 단계는 업무목록이 아니므로 행줄무늬를 적용하지 않는다. 쓰기 동작이 없는 화면이라 SaveResult는 적용대상이 아니다.

## PG 도입 준비 (WB119)
관리자 프로젝트 그룹의 읽기 전용 안내. 문의문→업체별 추가 요청→준비정보→결제수단 설명. 목차 앵커·원문 읽기전용 textarea·복사 결과 role=status. 실패 시 원문 선택과 수동복사 안내. 기본 테마 surface/text/border 토큰, 모바일 단일열. 서버 저장폼이 아니므로 SaveResult 대신 복사 결과를 명시한다. 진행 상태는 작업 보드 링크로만 제공.

WB119 업체별 결제수단 안내는 공통 pg-cards 2열/모바일1열과 dl 일반결제→간편결제→신청조건으로 구성. 공식출처·자료기준을 업체별 표시, 지원여부와 실제서비스연동 상태를 구분한다.

## WB137 색상칩·옵션 미리보기
공통 ColorChip은 고객·관리자 모두26px 원형, 표면색2px 간격·테마 기반1px 외곽링·약한 그림자로 통일한다. 고객 카드 칩 간격은10px이다. 현재 색상명 기준 대표색이며 실물 색상 보장이 아니다. 알려진 이름만 매핑하고 미지정은 사선 칩과 이름을 표시한다. 관리자에서는 색상명을 항상 병기한다. 고객 홈/목록 카드에는 가격 아래 등록 색상과 중복 제거한 사이즈를 표시하며 구매 가능한 조합/품절은 상세에서 확인한다. 색상칩 자체는 선택/재고 변경 동작이 아니다.

WB137 모바일 검증: 기본 글자 크기의 상품 목록은 2열을 유지하여 상품1개가 전체 너비로 확대되지 않게 한다. 큰 글자 설정의1열 예외는 유지한다. 색상·사이즈는 flex wrap으로 넘침 없이 표시하며 다수 옵션의 추가 높이는 자연 줄바꿈으로 허용한다.
