# 결정 기록 v0.3

작성일: 2026-10-25. 이 파일은 합의 상태의 기준이다. 다른 문서는 이 파일과 충돌하지 않아야 한다.

## 상태 정의

- 확정: 사용자의 명시적 지시.
- 가정: 초안 설명을 위한 임시 사업 전제.
- 제안: 검토 가능한 설계안. 구현·계약 승인과 다름.
- 미정: 사업 책임자 또는 기술 책임자의 선택이 필요함.

## 사업 가정과 설계 제안

| 항목 | 가정/제안 | 변경 영향 |
|---|---|---|
| 시장 | 한국어·대한민국·KRW 가정 | 관할법·통화·세금·배송 재설계 |
| 고객 | 모바일 의류 구매자 가정 | 상품 분류·가격대·브랜드 미정 |
| 판매 | 단일 판매자 B2C 가정 | 입점형이면 판매자·수수료·지급 구조 추가 |
| 조달·출고 | 자체 보유 의류·단일 출고지 가정 | 위탁·직배송·3PL이면 재고 소유권·연동 변경 |
| 구매 자격 | 회원 구매 우선 제안 | 비회원 주문 인증·조회 정책 추가 가능 |
| 서버 구조 | 모듈형 모놀리스·관계형 DB 제안 | 실제 DB·운영 환경은 ADR로 결정 |
| 시안 | 내부용 2D 편집을 초기 후보로 제안 | 고객용·3D·AI·생산 CAD는 다른 범위 |

## 우선 결정 5개

| ID | 질문 | 책임·결정 시점 |
|---|---|---|
| Q01 | 대상 고객·의류군·운영 국가·판매 형태·조달·배송 방식은? | 사업 책임자, 거래 데이터 모델 확정 전 |
| Q02 | 시안은 내부용/고객용인가? 2D/3D/AI/생산용 중 어디까지인가? | 사업·디자인 책임자, 편집기 상세설계 전 |
| Q03 | 초기 서비스는 상품 전시/문의/주문 접수 중 어디까지인가? 실제 결제는 도입하는가? | 사업 책임자, 판매 흐름 구현 전 |
| Q04 | 배송비·취소·교환·반품·쿠폰·회원/비회원 정책과 외부 계약은? | 사업·운영 책임자, 거래·연동 구현 전 |
| Q05 | 출시 일정·예산·운영 인력·DB·운영 호스트/오케스트레이션·브랜드 방향은? | 사업·기술·디자인 책임자, 개발 환경·시각 디자인 확정 전 |

결정 기록 형식: ID / 상태 / 날짜 / 결정자 / 내용 / 근거·대안 / 영향 문서·요구 ID / 재검토 조건. 미정은 마감 시점 경과만으로 승인되지 않는다.

## 변경 이력

- v0.1: 의류몰 일반 거래 흐름과 기본설계 초안. 기술·결제는 제안.
- v0.2: Next.js·Python, 재고·시안, 모바일·향후 앱·AI, 개발 운영 반영. PG의 MVP 필수 제안을 해제.
- v0.3: FastAPI 확정, 저장소 문서화. 미정 판매 흐름과 조건부 결제·환불 요구를 구분.
- v0.3 환경 보완: 로컬 비컨테이너 직접 실행·운영 Docker 기반 배포 확정(D11·D12).
