# 단계별 범위·운영 대응 v0.3

## 개발 순서 제안

| 단계 | 범위 | 진입·완료 조건 |
|---|---|---|
| 0 문서 | 현재 설계·지침·절차·디자인 시스템 | 문서 참조·ID·확정/미정 일관성 검토 |
| 1 환경·계약 | 로컬 직접 실행 Next.js·FastAPI 환경, 인증·DB 선택, 운영 Docker 배포 설계, API·토큰 | Q05 및 해당 ADR, 실제 실행 명령·검증 마련 |
| 2 기반 | 상품·SKU·재고·관리자·권한·감사·공통 UI | R01–R05·R07의 관리자 인증·R16–R18 수용 기준. 고객 가입 여부와 무관하게 관리자 인증 필수 |
| 3 시안 | 프로젝트·자산·버전·편집·출력·상품 연결 | Q02 결정 후 R19–R21 상세 계약·검증 |
| 4 판매 | 장바구니·주문·출고·CS·클레임·혜택 | Q01·Q03·Q04 결정, 비PG 주문이면 별도 확정 조건 필요 |
| 5 결제 선택 시 | PG·취소·환불·대사·알림 | 계약·법규·장애 복구·운영 리허설 |
| 후속 | 앱·AI·리뷰·추천·다중창고·해외·입점 | 실제 수요·비용·별도 승인 |

단계는 의존 순서 제안이며 일정 약속이 아니다. 독립 작업은 계약과 소유권을 정한 뒤 병렬화한다. 모바일·접근성·보안은 각 단계의 완료 기준이며 마지막에 몰아서 추가하지 않는다.

## 운영 대응 초안

실제 담당자·연락 수단·시간 기준은 운영 준비 때 채운다. 실서비스 전에 모의 리허설을 수행한다.

| 상황 | 탐지·초기 대응 | 복구·종료 증거 |
|---|---|---|
| 재고 불일치 | SKU별 원장·잔고·예약/할당 비교, 영향 SKU 판매 보류 | 근거 있는 조정 원장·영향 주문 확인·중복 차감 없음 |
| 결제 미확정 | UNKNOWN 경과 알림, 추가 결제 유도/출고 보류, PG 조회 | 유효 승인 1건·주문/할당 복구 또는 취소·대사 |
| 환불 미확정·기한 임박 | 중복 환불 차단, PG 조회·담당자 우선 처리 | 외부 결과·내부 금액·고객 안내 일치 |
| 출고/취소 경합 | 실제 인계 여부·품목 잠금·현재 상태 확인 | 취소 또는 회수 절차로 일관되게 정리 |
| 웹훅·큐 장애 | 적체·실패 알림, 원본 이벤트 보관 | 멱등 재처리·대사·격리 건 해소 |
| 메시지 실패 | 상태 기록·재시도, 승인된 대체 채널만 사용 | 중복 발송 없음·실패 담당자 확인 |
| 시안 저장/출력 실패 | 원본·편집 입력 보존, 버전 충돌 확인 | 이전 버전 복구·자산 참조·출력 비교 |
| 데이터 복원 | 승인된 복구 실행, 쓰기·연동 재개 시점 통제 | 복원 시점·원장/주문 대사·파기 재적용·RPO/RTO 측정 |
| 정보 노출 의심 | 접근 차단·키 회전 필요성 평가·증거 보존 | 영향 범위·법적 통지 의무 검토·재발 방지 |

외부 결과가 불명확한 작업은 단순 재호출보다 조회를 우선한다. 수동 재처리는 권한·이유·멱등키·결과를 감사 기록에 남긴다.

대사는 일일 수행을 초기 제안으로 하고 미확정 결제/환불은 더 짧은 조회 주기를 설정한다. 구체 주기·최대 유예·재시도 횟수·담당자 응답 시간은 공급자 계약과 운영시간으로 정한다.

## 범위 변경

DB·API·브랜드·사업 정책 변경은 결정 ID와 영향 요구·테스트·문서를 갱신한다. 입점형 정산, 생산 자재 재고, 방송, AI 패턴 생성 등을 일반 의류몰의 당연한 기능으로 추가하지 않는다.
