## 계층

- 단위: 금액·수량·상태 전이·권한 판단의 경계값.
- DB 통합: 제약·트랜잭션·경합·마이그레이션.
- API 계약: 요청/응답·오류·멱등·권한·페이지 처리.
- 외부 연동: 공식 샌드박스·모의 장애. 실환경 검증은 승인된 별도 절차.
- E2E: 상품 탐색·운영 재고·시안 기본 흐름, 거래 도입 시 주문부터 사후 처리.
- 시각·접근성: 대표 화면·상태·브레이크포인트와 수동 보조기술 확인.

자동 테스트만으로 실제 PG·물류 계약·접근성 준수·복구 가능성을 보장하지 않는다. 테스트 데이터는 합성 자료다.

## 출시 판정

활성 단계의 요구별 증거, 중대 결함 해소, 정책·계약·보관표, 운영 담당자 리허설, 백업 복원·배포 실패 대응이 필요하다. 미선택 결제·AI·앱 기능을 미구현 결함으로 취급하지 않는다. 주문을 선택하면 취소·반품·교환과 재고 복구를 검증한다. 실제 결제를 선택하면 금전 환불·PG 대사와 결제 장애 복구도 필수 검증한다.
