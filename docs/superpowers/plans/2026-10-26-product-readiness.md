# 상품 재고 준비 상태와 완료 버튼 배치

WB27 / R38 / 2026-10-26

완료 화면의 다른 상품 등록 버튼을 기존 두 버튼과 같은 catalog-actions 컨테이너에 넣고 별도 상단여백을 제거한다. 넓은 화면은 같은 행, 모바일은 자연스러운 줄바꿈을 유지한다.

등록 상품 목록에 준비 상태를 추가한다. 서버 GET catalog는 product_readiness:[{product_id,status,sku_count,stocked_sku_count,total_on_hand}]를 같은 트랜잭션에서 산출한다. status는 no_options(SKU0),no_stock(SKU있고양수재고0),partial_stock(일부만양수),in_stock(모든등록SKU양수). 조회값이며 DB저장/발행정책이 아니다. 실제 입고 이력 유무 대신 현재고를 사용하고0으로소진되면 다시입고필요로 표시한다. 클라이언트는 서버값을 표시하며 필드가없는이전응답은 상태확인필요로 처리한다. 공개판매상품은 아직별도샘플이므로 perrow미게시를 명시한다. 재고준비가판매가능/자동게시를 의미하지 않는다.

API 담당은 aggregate와임시DB테스트, UI담당은 완료버튼/목록상태/CSS, 조정담당은 TS계약/문서/브라우저, 독립검증자는 통합검토. UI label은 색상·사이즈 등록 필요/재고 입고 필요/일부 옵션 재고 없음/재고 준비됨, 수량과 x/y옵션을 함께 보여준다. 수용기준:4상태/소진/다른상품독립/원장불변,행중앙정렬과모바일,완료버튼같은행/초기화유지. API쓰기계약/DB스키마변경없음. 복구는코드문서만되돌린다. 선행WB26.
