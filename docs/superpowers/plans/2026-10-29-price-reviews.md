# 가격·리뷰·평점 구현 계획 — WB91

**Goal:** 상품 가격 관리 경로와 구매 고객 리뷰 관리, 공개 리뷰 기반 평점/개수를 제공한다.
**Architecture:** 기존 게시 가격/이력 계약을 유지하고 리뷰 저장소·관리 API·공개 조회를 추가한다. 고객 인증/구매 판정은 신뢰 서버 인터페이스로 분리하며 현재 운영 연결은 차단 상태다.
**Tech Stack:** Next.js, FastAPI, SQLite. 새 외부 의존성 없음.

## 요구·범위·담당
- R05/R96/R98. 사용자 승인: 가격·리뷰·평점 관리, 0건 압축표시, 해당 상품 구매자만 작성.
- root: 계약 조율·문서·작업 보드·통합. public_catalog_api: services/api/**. public_catalog_web: apps/web/**. public_catalog_review: 독립 검증.
- 가격: 기존 정수 원화 선택 입력/변경 이력/낙관 버전 사용. 임의 샘플 가격·할인·옵션 추가금은 넣지 않는다.
- 리뷰: 1~5 정수 별점·텍스트, 공개/숨김·관리자 답변·변경 이력. 사진 첨부는 별도 후속이며 이번 구현에 포함하지 않는다.
- 고객 목록·상세 상단: 리뷰0건, 평균 없음. 상세 하단은 긴 빈상태 문구 허용. 조회 실패를0건으로 바꾸지 않는다.
- 평점: 공개된 삭제되지 않은 리뷰만 집계. 관리자에 의한 별점/고객 본문 대필 금지.
- 구매 확인: 클라이언트가 보낸 고객/구매 주장을 신뢰하지 않는다. 고객 회원/주문 연동 전에는 쓰기를 거부한다. 테스트에서만 서버 제공자를 주입해 구매자/타인/비구매자 검증.
- 리뷰 중복 기준과 결제/배송/환불 상태별 구매 인정 정책은 운영 연동 시 확정한다. 현재 안전한 동일 고객·상품 중복 차단은 기술 기본값으로 기록한다.

- [x] 백엔드: 저장·수정·삭제 소유권, 구매확인 실패 차단, 공개집계와 관리 숨김/복원/답변, 가격 경계값 회귀.

- [x] 검증: 백엔드 권한·상태·금액 경계/실패, 프론트 타입/lint/관련 테스트, 실제 로컬0건, 별도 합성데이터의 리뷰 관리/집계, PC/모바일·다크·확대.

## 복구·보존
기존 상품/옵션/재고/이미지와 게시 가격을 유지한다. 스키마 백업 위치와 버전은 검증 보고서에 기록하며, 새 버전 이후 쓰기 보존 없이 DB를 과거로 덮어쓰지 않는다. 실제 리뷰를 임의로 샘플 생성하지 않는다. 커밋·푸시·배포는 이번 범위가 아니다.
