# 상품 게시·실제 고객 쇼핑 화면 — WB87 / R96

**Goal:** 상품 등록 → 재고 확보 → 명시적 게시 → 고객 탐색/상세 확인의 흐름을 연결한다.
**Architecture:** FastAPI가 게시 상태와 공개 DTO를 검증하며 Next.js는 고객 탐색/관리자 별도 게시 수정 화면을 제공한다. 기존 홈 진열 설정을 실제 상품 ID에 연결한다.
**Tech Stack:** 기존 Next.js/FastAPI/SQLite, 로컬 Docker 없음.
**Spec:** 최신 사용자 승인, docs/requirements.md R96, docs/contracts/public-catalog.md.

## 범위·담당
- public_catalog_api: services/api 코드·테스트·공개 계약 문서. 게시/중지·공개 이미지·실제 상품/진열 API와 추가형 DB 변경.
- public_catalog_web: apps/web 코드·테스트. 게시 수정/상태/진열 연결·고객 홈/목록/상세/옵션/품절/검색필터.
- public_catalog_review: 독립 검증과 docs/reviews/public-catalog.md. 격리 테스트 DB와 모의 브라우저를 사용하고 원본 업무 쓰기는 하지 않는다.
- root: 문서·작업 보드·통합 확인. 기존 미커밋 및 WB83 별도 시안 작업 보존.

## 설계 결정과 경계
- 상품은 준비 중(draft)/게시(published)/게시 중지(paused). 기존 상품을 자동 게시하지 않는다. 재고와 시안 상태는 별도 유지한다.
- 게시하려면 고객용 이미지(model/garment), 고객 설명, 유효 카테고리, 사용 중이며 재고 있는 옵션이 필요하다. 게시 후 재고0은 품절로 유지한다.
- 가격은 기존 고객 화면의 원화 표시 관례를 이어받는 선택 입력이다. 미입력 가격을0으로 꾸미지 않는다. 통화/판매 정책 최종 확정이나 구매 가능 선언이 아니다.
- 공개 API는 고객 상품명/설명/분류/고객 이미지/색상/사이즈/재고 있음 여부만 허용한다. 내부명·공장·시안·원장·정확한 잔고·관리 이력은 공개하지 않는다.
- 홈 시즌/커스텀 진열은 기존 설정을 보존하며 공개 응답에서 미게시/과거 샘플 참조를 제외한다. 관리자는 실제 상품을 선택해 구성한다.
- 목록은 검색·분류·색상·사이즈·재고 조건과 페이지 이동을 제공한다. 색상+사이즈 조합은 같은 사용 중 SKU를 만족해야 한다. 상세 복귀에 조회 조건을 보존한다.
- 상세는 이미지 탐색·사용 중 옵션 선택·품절/없는 조합 안내를 제공한다. 주문/결제/장바구니/고객가입/실배송 기능은 확정하거나 가짜 동작으로 넣지 않는다.
- 이번 사이트는 상품 전시·탐색 기반이다. 법정 판매 고지/배송반품 정책·사업자 정보 확정 및 운영 공개 점검은 후속 과제이며 법규 충족을 주장하지 않는다.

## 복구와 제한
추가형 마이그레이션 전 SQLite 백업을 남기고 기존 상품/SKU/원장/이미지/계정을 보존한다. 구버전 앱으로 단순 코드 복귀가 가능한지 실제 버전 검사를 확인하고, 불가하면 호환 코드 유지 또는 백업 복원(후속 데이터 보존 포함) 절차를 기록한다. 실제 상품 게시나 운영 배포는 테스트를 위해 수행하지 않는다.
