# 샘플·완제품 발송 Implementation Plan

**Goal:** R94/WB86 샘플과 완제품의 발송/내부 수령/검수를 추적하고 완제품 합격 수량만 입고 확정 시 재고 원장에 반영한다.
**Architecture:** 기존 FastAPI 공장 인증·내부 관리자 인증 및 SQLite CatalogStore 트랜잭션을 사용한다. 발송 테이블을 비파괴적으로 추가하고 원장 갱신과 입고 완료를 하나의 트랜잭션으로 처리한다. Next BFF가 역할·Origin을 검증하며 목록/등록/수정/상세를 분리한다.
**Tech Stack:** 기존 Next.js/TypeScript, Python/FastAPI/SQLite. 신규 외부 서비스·Docker·의존성 없음.
**Spec:** 사용자 승인한 샘플/완제품 발송 구분, 내부 수령·검수 및 완제품 입고 확정. 정확 계약은 docs/contracts/shipments.md.

## 범위·판단
- 샘플: 상품/시안 식별 설명과 색상·사이즈/수량을 기록한다. 수령·검수 승인/수정요청은 기록하되 상품 시안 상태를 자동 완료하지 않는다. 판매 재고 전환/샘플 판매는 미구현 별도 정책이다.
- 완제품: 기존 제작 요청과 SKU별 수량을 연결한다. 제작 완료된 요청에서 발송하며 누적 발송량이 요청량을 초과하지 않는다. 분할 발송은 별도 발송 건으로 생성한다.
- 내부 단계: 발송→수령(실수령/누락)→검수(합격/불량)→입고 확정(완제품만). 각 발송 건은 실수령 확정과 최종검수 한 번으로 처리한다. 누락 후 지연 도착 재처리/반품은 별도 후속 범위이며 수령 확정 전 실제 도착분 확인 안내를 둔다.
- 운송 정보는 입력 기록이며 택배사 자동 조회·실메시지 연동 없음. 시안 버전 모델은 없으므로 시안 버전/설명 텍스트 참조이며 자동 버전 관리로 표현하지 않는다.

## 검증과 복구
테스트는 합성자료/임시DB로 수행하며 실제 원본재고·공장자료에 테스트 쓰기하지 않는다. 마이그레이션은 추가테이블 중심으로 기존 값과 원장을 보존한다. schema13 이후 schema12 전용 구버전 앱으로 단순 복귀할 수 없다. v13 호환 코드를 유지하며 수정 배포하고 새 테이블을 보존한다. 이전 백업 복원은 이후 업무/원장을 별도 보존·대조한 뒤 수행하는 복구 절차로 취급한다. 확정된 입고를 소스복구로 취소하지 않으며 재고 정정은 기존 감사 가능한 조정 절차를 사용한다. 배포·커밋·푸시 없음.
