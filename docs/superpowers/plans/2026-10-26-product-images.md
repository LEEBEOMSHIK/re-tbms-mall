# WB61 / R70 상품 이미지 구분

## 목적과 수용 기준
상품 상세에서 내부 시안, 고객용 모델 착용, 고객용 의류 단독 이미지를 독립 영역으로 확인한다. 상세와 이미지 등록 화면을 분리한다. 로컬 파일 선택 → 미리보기/설명 → 저장 → 해당 상품 상세의 저장 확인으로 연결한다. 삭제에는 확인과 성공/실패 피드백을 제공한다.

## 계약과 구현 분담
- supplier_api: FastAPI 관리자 전용 이미지 GET/POST/DELETE, SQLite 비파괴 테이블 추가, Pillow 디코딩·재인코딩 및 테스트.
- supplier_ui: 상세 갤러리/독립 등록 폼/업로드 미리보기/완료·오류 처리. 디자인 토큰·반응형 사용.
- 조정: Next BFF·타입/응답 검증·문서·작업 보드·브라우저 통합.
- supplier_review: 실제 변경과 실행 근거 독립 검토.
- 선행 계약: kind design/model/garment. 별도 이미지 엔티티, 상품 기본정보 및 SKU/재고 수정 안 함. admin 상품 API 하위 images 경로. JSON data URL은 로컬 전송 방식이며 공개 URL이 아니다.

## 구현 선택 및 한계
단일 파일 2MiB, 종류별 10개, PNG/JPEG/WebP, 최대4096px/16MP. 구현 초기 제한이며 사업 정책 확정이 아니다. 대체텍스트 필수. 파일 확장자만 신뢰하지 않고 서버에서 실제 디코딩 후 메타데이터 제거·재인코딩한다. 외부 URL은 받지 않는다. SQLite에 이미지 데이터를 저장하는 로컬 구현이며 운영 객체저장소·CDN·대표이미지/순서정책은 후속 결정이다. 고객용 분류가 자동 게시를 의미하지 않는다. 시안은 관리자 전용이다.

## 검증/복구
합성 이미지와 임시 DB로 형식·크기·손상·권한·상품관계·재시도·삭제·영속성·기존 스키마 업그레이드를 확인한다. 브라우저는 테스트 응답으로 업로드/상세/실패·재시도/모바일을 검증하고 실제 업무 데이터에 테스트 업로드하지 않는다. API/웹 테스트·타입·린트를 수행하고 미실행은 기록한다. 기존 DB 백업 후 추가 테이블 마이그레이션; 롤백 시 이미지 데이터를 보존하고 테이블을 임의 삭제하지 않는다.
