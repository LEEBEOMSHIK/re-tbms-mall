# WB212 / R107 할인 기준 선택 구현 계획

사용자가 승인한 할인율/판매가 선택, 기본가 변경 시 선택 기준 유지, 원 미만 버림을 구현한다. root 구현, 별도 검증 역할이 API·UI 결과를 확인한다.

1. 서버: public_catalog.py에 discount_mode(price/percent), discount_percent(정수1~100)를 추가. v18 추가 컬럼 마이그레이션은 사전 백업하며 기존 값은 price로 유지. 할인율의 판매가=기본가*(100-비율)//100. 명시적 판매가 입력은 기존 API 호환, 모든 할인 입력 생략은 기존 기준 유지. 충돌 가격은 거절. 기본가 null/0과 할인 조합 거절. 가격 이력에 기준/비율 저장.
2. 웹: pricing.ts 계산 도우미와 publication.ts 기준 검증. publication-editor.tsx에서 기준 선택/단일 입력/판매가 미리보기. 할인 해제·실패 입력 유지, 서버 확정 기준 검증. 가격 이력에 기준 표시.
3. 테스트: 기존 할인 회귀, 1/100%, 소수·문자·범위오류, 원 미만, 기본가 변경, 방식 전환, 버전충돌·권한, v17 보존/백업. 프론트 동일 계산·응답 불일치 검증.
4. UI: 합성 데이터 PC1440/390/320, 모드 전환·미리보기·저장/실패/요약 실패·포커스 검증. 가이드 catalog:3 캡처/표식 교체, 원문·디자인시스템·API문서·보드 갱신.

새 패키지 없음. 가격 계산은 서버에서 확정, 고객 가격 DTO는 기존 유지. 할인율은 초기 정수만 지원. 복구는 서버 중단 후 pre-v18 백업 복원 및 해당 변경 복원(백업 이후 쓰기는 별도 보존). PG/재고/주문 계약 변경 없음. 커밋/푸시 범위 아님.
