# WB62 / R71–R74 공장 협업

## 확정 요구
사용자는 상품당 담당 공장 한 곳, 내부 관리자에 의한 공장 계정 발급, 배정 상품 확인 및 추가 제작 요청을 승인했다. 기존 공장·공급처 식별자를 재사용하고 과거 입고처를 담당 공장으로 추정하지 않는다. 계정은 한 공급처에 소속되고 상품은 한 공장에 배정된다.

## 책임과 계약
- supplier_api: schema10 추가 테이블, 계정/로그인/세션/권한, 상품 배정/명시 시안 공유, 제작 요청·상태 이력·실패/경계 테스트. services/api 소유.
- supplier_ui: /factory 별도 로그인·세션 쿠키·BFF·공장 포털. 내부 관리자 master token으로 공장 요청을 대리하지 않음.
- 조정: 공통 타입/내부 BFF/공장 관리 목록·등록·설정·상세 및 문서/작업 보드/브라우저.
- supplier_review: 별도 검토와 실제 명령 실행.

## 구현 기준과 미정
계정은 내부 관리자가 ID/표시명/초기 비밀번호를 설정하고 직접 전달한다. 자동 문자/메일 발송 없음. 로그인 비밀번호12~128자와 PBKDF2/무작위 세션8시간/로그인 실패 제한은 구현 기준. 공용 내부 관리자 키는 개인별 내부 관리자 계정 구현을 의미하지 않는다. 작업 이력 내부 행위자는 local-admin으로 표시한다.

상품 배정은 최대 한 곳. 진행 중인 제작 요청(submitted/accepted/in_production)이 있는 공장 배정을 해제·변경하면409. 기존 요청·상품/SKU/공장 표시값은 스냅샷으로 유지한다. 공유 시안은 관리자 명시 선택한 design 자료만, 고객 이미지와 미선택 시안은 비공개다. 공장 계정/소속 공급처 중지와 배정 해제는 매 요청 서버에서 반영한다.

초기 제작 흐름은 요청됨→접수됨→제작 중→제작 완료. 내부 관리자는 접수 전 취소 가능, 공장은 자신의 요청만 순서대로 처리한다. 버전 충돌과 중복 요청ID를 검사한다. 작성 중 서버 저장·거절/접수 후 취소 협상·부분 제작·발주 금액·납기 확약·완제품 검수 제출 기능은 추후 결정이다. 요청 메모는 공장에 공개됨을 명시한다.

제작 요청·완료는 실제 재고를 변경하지 않는다. 실제 수령 후 기존 재고 입고 기능으로 처리한다. 요청별 입고 연결·부분입고/초과입고 정책은 후속이며 현재 자동 연동하지 않는다.

## 검증·복구
합성 계정/이미지/상품과 임시 DB로 타공장 직접 ID 조회, 위조 supplier_id, 내부 API 접근, 만료/중지/비밀번호 초기화, 미공유 이미지, 요청 재시도·상태충돌·수량 경계·재고 불변 검증. UI는 목록/등록 분리, 공통 페이지네이션, 입력 보존/결과 피드백, 모바일/테마 확인. 실제 업무 DB의 계정/배정/요청을 테스트로 만들지 않음. schema10 추가 테이블만 적용한다. 실제 로컬 백업 시점/스키마는 검증 기록에 구분해 기록한다. 복구는 이후 업무 변경 여부를 확인하고 별도 백업에서 복원, 테이블 임의 삭제 금지.
