# 슬라이드·푸터·공동 작업 보드 구현 계획

Goal: 상품이 많은 섹션의 자동 슬라이드, 기본 쇼핑몰 푸터, 공유 가능한 내부 작업 현황 제공.
Architecture: 기존 Next.js와 디자인 토큰 유지. 상품 API 계약 변경 없음. 작업 보드는 저장소 JSON을 단일 원본으로 사용하는 읽기 전용 내부 경로이며 채팅에서 합의한 작업을 갱신한다.
Tech Stack: Next.js / React / TypeScript. 기존 FastAPI는 변경하지 않는다. 추가 의존성 및 Docker 없음.

## 요청 및 구현 선택

- R26 자동 슬라이드: 화면보다 많은 카드가 있을 때만 동작. PC 4개/모바일 2개 기준, 약 5초 간격 순환, 이전/다음·일시정지 제공. hover/focus·터치 조작·숨겨진 탭·화면 밖·동작 줄이기 환경에서 자동 동작 제한. 상품 상세와 카테고리 필터 유지.
- R27 푸터: 회사·대표·사업자·주소·연락처·운영시간 입력 자리, 쇼핑/회사 소개, 이용약관·개인정보·배송·교환/반품 안내. 미제공 정보는 등록 예정, 정책은 미확정 안내로 표시. 실제 회사/정책을 꾸며내지 않음.
- R28 작업 보드: /admin/workboard, 완료/검증 중/다음/결정 필요, 담당·우선순위·완료 기준·의존성과 갱신일 표시. 고객 메뉴에 개발 보드 링크를 넣지 않음. 실시간 에이전트 감시나 웹 편집 기능으로 표현하지 않음.

## 작업 분담 및 수용 기준

- carousel: storefront-view.tsx, product-carousel.tsx와 분리 CSS, 관련 테스트. 필터 후 스크롤 초기화와 수량이 적을 때 자동 동작 없음 확인.
- footer_board: shop-shell.tsx, footer CSS, 정책 페이지, /admin/workboard 및 apps/web/src/data/workboard.json. 링크가 실제 열리고 미정/완료 상태를 구별하는지 확인.
- 조정: 문서·통합 브라우저 검증. 모바일 가로 넘침, 자동 전환·일시정지·reduced motion·상품 상세, 정책 및 보드 경로 확인.
- 독립 검증: 변경 소스 확인, 웹 테스트/lint/typecheck/build 실행. 구현자와 분리.
