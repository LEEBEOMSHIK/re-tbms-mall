# 판매 가격·할인 표시 계획 — WB92

**Goal:** 판매 가격 라벨을 명확히 하고 관리자 할인 설정→고객 실제 표시를 검증한다.
**Architecture:** 기존 기본가price 유지, 선택 discount_price 저장, 서버에서 effective_price/discount_rate 계산. 공개/관리/이력 동일 계약. 공통 가격 컴포넌트로 홈/목록/상세를 통일한다.
**Tech Stack:** 기존 Next.js/FastAPI/SQLite, 새 의존성 없음.

- 요구: R05/R99. 담당 root 문서·통합, public_catalog_api services/api/**, public_catalog_web apps/web/**, public_catalog_review 독립검증.
- 사용자 승인: 판매 가격 명시와 관리자 할인 기능/고객 표시 확인. 쿠폰/예약/옵션별 할인·주문결제는 범위 밖.
- 기본 판매가격 price는 기존값 유지. discount_price null이면 할인 없음. 할인은 price>0이며0<=discount_price<price인 정수만 허용. bool/소수/음수 금지.
- effective_price=discount_price가 있으면 해당 값, 아니면price. 할인율은 과장 방지를 위해 정수 내림, 할인없으면null.0%로 내림될 작은 할인은 퍼센트 배지 생략하고 원가/최종값으로 표시.
- PUT 생략 할인값은 기존값 보존, 명시null이면 할인 해제. 최종가·할인율은 클라이언트에서 저장하지 않는다.
- 가격이력에 기본·할인 값을 함께 보존. schema15→16 추가형 마이그레이션·백업.
- 고객: 라벨 판매 가격, 할인시 기본가취소선/할인율/최종가 강조.0원과미입력구분, 색상만으로 정보구분금지.
- 관리자: 기본가·할인토글·할인가·고객표시 미리보기, 저장후상품상세복귀/일회성 결과, 실패입력보존/409재조회. 이력은별도화면.
