# 관리자 대시보드 실제 재고 연결 — WB13

**Goal:** 입고·출고가 반영된 실제 SKU 잔고와 부족 옵션을 관리자 홈에서 확인하고 해당 재고 목록으로 이동한다.
**Architecture:** 기존 관리자 인증과 재고 원장을 사용하며 전용 GET /api/v1/admin/inventory/overview를 추가한다. 현재 재고는 SKU.on_hand이며 부족은 on_hand <= reorder_point이다. 별도 샘플 예약/가용 재고를 실제 잔고로 혼합하지 않는다. 실제 집계 영역은 샘플 운영 영역과 분리한다.
**Tech Stack:** 기존 Next.js / FastAPI / SQLite. 새 의존성·마이그레이션 없음을 우선한다.
**Spec:** 사용자 최신 승인 / workboard.md WB13 / docs/requirements.md R95

## 범위·담당·수정 경계
- inventory_dashboard_impl: dashboard-view.tsx와 관련 UI/집계/재고 목록 필터, 필요시 서버 조회, 회귀 테스트. 기존 미커밋 변경 보존.
- inventory_dashboard_verify: 독립 테스트·브라우저 확인, docs/reviews/dashboard-inventory.md.
- root: 문서·작업 보드·통합 검증. 실제 업무 DB 변경·외부 연동·커밋/푸시는 범위 밖.

## 집계 및 화면 계약
- 보유 총수량과 부족 옵션 수를 서로 다른 단위로 표시한다. 사용 안 함 옵션도 기존 재고 목록과 동일하게 포함한다.
- 데이터 원본은 서버 저장 SKU이며 화면 진입·명시적 새로 조회 후 최신값을 표시한다. 조회 실패를 0이나 샘플값으로 대체하지 않는다.
- 전체 요약은 전체 재고 목록, 부족 요약은 부족 조건의 재고 목록으로 연결한다. 필터 변경은 첫 페이지로 복귀한다.
- 완제품 발송·수령·검수만으로 재고가 늘지 않고 입고 확정 후 증가한다. 샘플은 늘지 않는다. 기존 서버 규칙을 유지한다.
- 현재 보유량을 판매 가능량/예약 차감량으로 표현하지 않는다. 주문 예약 기능은 이번 범위가 아니다.
- 대시보드는 요약, 재고 전체 목록·등록·수정은 기존 별도 URL을 유지한다.
