# 관리자 홈·로그인 구현 계획

날짜: 2026-10-26 / 요구 R29
목표: /admin을 관리 메뉴의 시작점으로 만들고 /admin/login 및 로컬 테스트 바로 로그인으로 진입한다.

## 구현 선택과 경계

기존 FastAPI 관리자 키 인증을 유지하고 Next 서버가 검증된 키를 서버 세션에 보관한다. 브라우저에는 무작위 세션 ID를 HttpOnly·SameSite 쿠키로 전달한다. 유효기간 8시간, 로그아웃 시 서버 세션 폐기. 운영용 다중 계정/역할/복구 시스템은 여전히 미정이며 이번 구현은 로컬 관리자 진입 흐름이다.

테스트 로그인은 NODE_ENV=development 및 루프백 주소에서만 허용하며 서버에 설정된 기존 키로 API 연결을 확인한다. 운영 빌드에서는 버튼과 서버 기능을 모두 비활성화한다. 모든 변경 요청은 같은 Origin을 확인한다. 키는 응답·HTML·브라우저 저장소·로그에 노출하지 않는다.

## 화면·계약

- /admin/login: 기존 관리자 키 입력, 개발 환경에서 테스트 계정으로 바로 로그인, 오류·처리 중 상태.
- /admin: 로그인 필수, 진열 관리·작업 보드 메뉴. 상품·SKU/재고/시안은 준비 중 표시.
- /admin/merchandising: 별도 키 재입력 없이 로그인 세션으로 조회/편집.
- /admin/workboard 및 /source: 로그인 검사. 공개 화면에 관리자 메뉴를 넣지 않는다.
- /api/admin/session GET/POST/DELETE: 상태/로그인/로그아웃. POST {mode:key,key} 또는 {mode:test}.
- /api/admin/storefront GET/PUT: 로그인 세션 검사 후 기존 FastAPI 관리자 API로 전달.

## 분담

admin_session: 서버 세션·로그인/로그아웃·진열 프록시·권한 테스트.
admin_ui: 홈/로그인/공통 관리자 메뉴·페이지 보호·기존 진열/보드 통합.
조정: 문서/보드 갱신과 브라우저 전체 흐름 검증.
독립 검증 담당: 소스·권한 경계·테스트·빌드 확인.
