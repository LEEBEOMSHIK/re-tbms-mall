# WB48 관리자 폼 폭·간격 전수 점검

R58. 사용자 승인: 전체 등록·수정 화면 감사, 항목 많은 화면은 본문폭 활용, 모바일 1열과 간격 검증, 디자인 시스템 반영 및 독립 에이전트 검증.

## 적용 분류

| 화면 | 방식 | 이유 |
|---|---|---|
| 상품 등록/수정 | 본문폭·관련 필드 2열 | 분류·계절·두 이름·설명 그룹 |
| 색상·사이즈 조합 등록 | 본문폭 | 다중 선택·일괄도구·조합 표 |
| 재고 입고/출고/조정 등록 | 본문폭·그룹 배치 | 업무 선택·대상·수량·예상재고 |
| 공급처 등록/수정 | 본문폭·관련 필드 2열 | 기본·연락처·국가주소·메모 |
| 진열 등록/수정 | 본문폭 유지·필드/선택 간격 정리 | 상세필드·상품선택·정렬 |
| 카테고리 등록/수정 | compact 유지 | 짧은 단일 기준정보 폼 |
| 색상/사이즈 기준정보 등록/수정 | compact 유지 | 짧은 단일 기준정보 폼 |
| 로그인 | compact 유지 | 인증 단일 입력 |
| 대시보드/작업보드/목록/설정대화상자 | 별도 목적 유지 | 등록·수정 폼이 아니거나 작은 대화상자 |

## 책임·계약

inventory_ui는 catalog 폼과 CSS·supplier를 소유한다. admin_ui는 merchandising 전용 파일과 CSS만 소유한다. 조정은 계획·디자인·보드·브라우저를 소유한다. inventory_review는 독립 검증한다. 전역 globals 변경 필요 시 조정과 협의한다. API/DB/업무 규칙·재시도·완료 계약은 변경하지 않는다. 다른 작업의 미커밋 변경 보존.

wide는 본문 100%이며 본문 자체의 최대 너비는 기존 1320px을 유지한다. compact는 760px 이하, 화면폭을 넘지 않는다. 넓은 폼은 관련 필드를 묶고 긴 설명·주소·조합표·오류·저장행은 전체 열 사용. 모바일<=767px은 입력/선택그룹 1열, 데이터 표는 내부 스크롤 예외다. 그룹 space6/필드 space4/label-input space2, 저장행 앞 space6을 기준으로 한다.

## 검증

전체 등록/수정 경로 inventory 확인 후 실제 브라우저에서 1440/768/390px, 라이트·다크/확대글꼴 검증. wide 패널 본문폭 일치, compact 상한, 모바일grid1col, 문서overflow없음 및 내부표scroll, 그룹간gap 측정. 합성조회로 수정화면을 확보하고 실제쓰기 없이 검증한다. 대표 폼의 입력/저장 실패보존/완료 회귀는 모의응답으로 확인한다. 독립 웹tests/lint/type/build, 전체API는 불변이므로 반복하지 않는다. 복구는 이번 레이아웃클래스/래퍼/CSS만 되돌린다.
