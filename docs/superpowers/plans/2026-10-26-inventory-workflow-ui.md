# WB42 재고 업무 흐름 UI

## 요구·설계

R52. 이미 구분한 입고, 고객 판매 출고, 기타 출고·조정을 실제 작업 진입과 입력에 일관되게 적용한다. 기존 통합 등록 버튼만 유지하는 방식보다 업무별 바로가기를 제공하면 유형을 다시 고르는 실수를 줄일 수 있다. 별도 재고 DB나 공장·배송 시스템을 만드는 방식은 범위가 아니므로 도입하지 않는다.

이력 페이지에 흐름 설명과 등록 바로가기를 둔다. `/inventory/new?flow=receipt|customer|other`는 해당 업무를 선택해 진입하며 잘못된 값 또는 값이 없는 경우 업무 선택을 제공한다. 입고는 receipt, 고객 판매 출고는 sale로 명확히 고정하고 기타는 증정·폐기·기타 출고·증감 조정을 선택한다. 선택 업무와 버튼·수량 라벨이 일치하며 현재 수량, 증감, 예상 수량을 함께 제시한다. 등록과 목록을 분리하고 저장 확인 후 실제 원장을 조회하는 기존 완료 동작을 유지한다.

## 책임·계약

- inventory_ui: catalog-manager/forms/list/css, inventory/new/page. 공통 컴포넌트·토큰 재사용.
- 조정 담당: 요구·디자인·작업 보드·브라우저 통합 검증.
- inventory_review: 변경 소스와 독립 웹 검증. 빌드는 브라우저 종료 후 수행.
- 기존 API, 서버 사유 코드·재고 범위·버전·멱등 계약 불변. 외부 의존성 없음.

## 수용·검증

업무별 진입/정확한 사유 및 부호, 알 수 없는 flow, 선택 변경, 수량 미리보기, 저장 실패 입력 유지·동일 요청 재시도, 저장 후 실제 원장 안내, 모바일 화면과 키보드 동작을 확인한다. 웹 테스트·lint·타입·빌드와 별도 검증자 리뷰를 수행한다. 브라우저 쓰기는 합성 데이터로 검증한다. 기존 미커밋 작업은 보존하며 복구 시 이번 UI 변경만 되돌린다.
