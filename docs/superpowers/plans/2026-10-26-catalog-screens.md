# 상품 관리 용어 및 목록·등록 화면 분리

WB14 / R03·R18·R29·R31 / 2026-10-26

사용자 요청: 초안 등록은 상품 등록, SKU 등록은 색상·사이즈 등록으로 표시하고 등록과 목록을 분리한다.
구현 선택: URL을 나눠 목록에서 각 양식으로 이동한다. 단순 접기/펼치기는 별도 화면 요구를 충족하지 않는다. API·DB와 미게시 상태는 유지한다.

## 화면 계약

- /admin/catalog: 상품 목록, 색상·사이즈별 재고 목록, 변경 이력. 등록/수정/재고 변경 양식 없음.
- /admin/catalog/new: 상품 등록.
- /admin/catalog/options/new: 색상·사이즈 등록. SKU 코드는 옵션 관리 코드로 표시한다.
- /admin/catalog/[id]/edit: 상품 수정. 없는 상품은 안내하고 잘못된 대상으로 저장하지 않는다.
- /admin/catalog/inventory: 재고 변경. 기존 중복 재시도·충돌 보호를 유지한다.

각 페이지는 기존 관리자 세션으로 보호한다. 목록→등록/수정→저장→목록 확인과 취소/복귀가 가능해야 한다. 입력 실패 시 입력값을 유지한다. 상품 없는 경우 먼저 상품 등록으로 안내한다. 고객 미게시 안내는 쉬운 용어로 유지한다.

## 담당·파일·절차

1. 조정 담당: workboard.md WB14 진행 기록, 계획·요구사항·결정·디자인·README 문서 갱신.
2. inventory_ui: apps/web/src/app/admin/(protected)/catalog 하위 페이지와 공통 화면·스타일. Next 설치 문서의 페이지/동적 params 계약 확인 후 구현. API와 DB 수정 없음.
3. inventory_review: 독립 소스 검토, 웹 테스트·lint·타입 검사·빌드. 목록에 양식 없음, 직접 접근 인증, 잘못된 수정 ID, 상태 초기화/재고 재시도 유지 확인.
4. 조정 담당: Edge 목록/등록 분리, 생성·수정·옵션·재고 흐름, 취소/오류·모바일 확인. 통합 검증 후 보드 완료 및 기록.

## 수용 기준

- 화면에 초안 등록/SKU 등록 대신 상품 등록/색상·사이즈 등록을 사용한다.
- 목록과 각 등록 화면 URL이 분리되고 목록에는 입력 양식이 없다.
- 저장 후 목록에서 결과를 확인하고 새로고침/직접 접근 시 정상 동작한다.
- 기존 인증·재고 버전 및 재시도 보호가 유지된다.
- 좁은 화면에서 문서 가로 넘침 없이 조작 가능하다.

복구: 이번 화면·문서 변경만 이전 상태로 되돌린다. DB·등록 데이터는 삭제하지 않는다. 운영 배포·커밋/푸시는 이번 범위가 아니다.
