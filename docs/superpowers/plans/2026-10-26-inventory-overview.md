# WB43 입고처·보유 재고·입출고 내역

R53 / 사용자 정정: 작업 버튼 구분만으로 재고 흐름을 보여준다는 이전 구현은 요구에 부족했다. 현재 상품별 보유 수량과 공장 입고 상품·수량을 분리한다. 사용자는 공장·공급처 등록 후 입고 시 선택 방식을 명시 승인했다.

## 계약과 책임

- inventory_api: 공급처 목록(catalog.suppliers)/등록/수정, 재고 원장 supplier_id/supplier_name, schema6 이관과 테스트.
- inventory_ui: 현재 보유/입고/출고/조정·기존 화면, 상품 옵션 명시, 집계 helper와 테스트. 현재 보유량의 권위는 SKU.on_hand이며 원장 합계로 대체하지 않는다.
- 조정: 프론트 계약·프록시, 별도 공급처 목록/등록/수정, 입고 공급처 필수 선택, 문서·통합.
- 독립 검증: inventory_review. 공유 파일 catalog-manager는 UI 작업 후 조정에 인계.

공급처는 id/name/is_active/version. 이름 trim 1~120자, 중복 충돌, 버전 수정. 입고 원장에 당시 공급처명 보존. API의 nullable supplier_id는 구클라이언트·기존 초기입고 호환을 위한 것으로 신규 입고 화면에서는 필수다. 비입고에 공급처를 연결하지 않는다. null 공급처는 기존 멱등 payload를 바꾸지 않으며 공급처 변경 요청은 다른 요청이다.

## 수용과 검증

상품별 입고누계/판매·기타출고/조정/실제보유/부족상태, 상품검색, 입고처별 입고 조회, 미기록 공급처 보존을 확인한다. 기간 표기는 전체 기록 기준이며 초기 입고 포함, 미분류는 입고로 추론하지 않는다. 공급처 등록·수정·비활성·권한·중복/경계·멱등·이관 보존을 테스트한다. 합성 브라우저로 입력/저장/리다이렉트/필터/모바일을 검증하고 독립 API/웹/lint/type/build를 수행한다.

## 백업·복구

실제 schema5 DB 온라인 백업: .local/catalog-before-v6-20261026-112048.sqlite3 (integrity_check ok). 공급처 table 및 nullable columns 추가, 기존 데이터 보존. 실패 시 서버 중지 후 백업 복원과 이번 코드 롤백을 함께 수행해야 한다. 백업 후 신규 운영 데이터가 생겼으면 무조건 덮어쓰지 않고 별도 보존·재적용한다. 실제 공장 API/발주/검수/배송 자동화는 범위가 아니다.
