# 고객 쇼핑 디자인 시스템

적용: 고객 홈 `/`, 상품 목록 `/products`, 상세 `/products/{id}`, 고객 공통 헤더·푸터. 공통 토큰·접근성은 [공통 디자인 시스템](design-system.md), 업무 화면은 [관리자 디자인 시스템](design-system-admin.md)을 따른다.

## 시각적 방향
의류 이미지와 상품 자체가 먼저 보이는 편집형 쇼핑 화면이다. 큰 이미지·명확한 타이포그래피·여백·절제된 강조색으로 브랜드 분위기를 표현한다. 시각적 강조는 실제 상품과 컬렉션에 사용한다. 관리 코드·개발 상태·가짜 할인·검증되지 않은 판매 문구를 넣지 않는다.

- 헤더는 브랜드와 핵심 탐색을 간결하게 배치한다. 상품 탐색에 불필요한 반복 메뉴/복귀 버튼을 큰 박스로 나열하지 않는다.
- 목록은 상품 카드 이미지가 주정보다. 상품명·입력된 가격·품절 상태만 간결하게 이어진다. 긴 상품명은 읽을 수 있게 줄바꿈한다.
- 상품 사진 영역의 일관된 비율과 충분한 크기를 유지한다. 중요한 의류 부분을 가리지 않는다. 상세 이미지는 전체 형태를 볼 수 있어야 한다.
- 고객 전용 클래스/토큰으로 범위를 제한한다. 고객용 변경으로 관리자 폼·재고 표·공장 메뉴의 크기/간격을 바꾸지 않는다.
- 모바일 일반 글자 크기는 상품 비교가 가능한 카드 배치를 우선하고, 큰 글자에서는 폭을 확보하기 위해1열 전환을 허용한다. 텍스트를 작게 줄여 억지로2열을 유지하지 않는다.
- 짧은 hover 전환은 선택 가능성을 보조한다. 키보드 포커스가 동등하게 명확해야 하며 reduced-motion을 존중한다.

## 검색·상세 필터 — WB89 / R97
상품 검색과 필터 토글을 기본 탐색 도구로 제공한다. 상세 설정은 **기본 닫힘**이다. URL에 조건이 있어도 자동으로 전체 설정을 펼치지 않는다.

1. 검색창과 검색 실행 동작은 항상 보인다. 상세 필터 토글은 아이콘+이름·적용 개수로 식별한다.
2. 카테고리·색상·사이즈·재고·정렬·페이지당 개수는 접힌 상세 설정 안에 둔다. 결과 개수는 목록 위에서 간결하게 유지한다.
3. 선택한 필터는 접힌 상태에서도 작은 조건 칩으로 보여주고 각 조건 해제와 상세 필터 초기화를 제공한다. 검색/컬렉션 문맥을 의도치 않게 지우지 않는다.
4. 검색·필터·정렬·페이지 크기 변경은 첫 페이지로 돌아간다. 열기/닫기만으로 URL·선택값·페이지가 바뀌지 않는다. 상세 복귀 시 URL 조건을 유지한다.
5. 토글은 실제 button, aria-expanded와 aria-controls로 상태와 대상을 연결한다. 접힌 영역의 컨트롤은 탭 순서에서 제외한다. 패널을 키보드로 닫으면 토글로 포커스를 돌려준다.
6. 드롭다운이 열린 상태에서 Escape는 먼저 드롭다운을 닫는다. 패널과 드롭다운이 동시에 예상 밖으로 닫히지 않도록 검증한다.
7. FormSelect는 공통 스타일 범위와 실제 라벨 연결을 유지한다. native select와 커스텀 trigger의 중복 표시를 허용하지 않는다.

## 상태와 상품 상세
로딩·검색결과 없음·게시중지/없는 상품·통신 실패를 구분한다. 고객에게 기술적 API 정보나 재고 원장을 표시하지 않는다. 가격 미입력을0원으로 바꾸지 않는다. 옵션은 실제 활성 조합만 제공하며 품절을 문구로 표시한다. 주문·결제가 미정인 현재 동작하지 않는 구매 버튼을 넣지 않는다.

## 검증 기준
기본/조건있는URL에서 접힘, 조건 칩·해제·초기화, 검색 입력 유지, 페이지 초기화, 키보드/포커스, 실제 상품 링크를 검증한다. 1440px/390px·밝음/어두움·실제16px/24px 글씨에서 이미지·값·간격과 가로 넘침을 확인한다. 화면 캡처를 직접 검토하며 단순 DOM 테스트만으로 시각 품질 통과를 선언하지 않는다.

## 고객 전용 구현 토큰 — WB89
범위는 `.shop-home`, `.shop-products`, `.shop-detail`, `.customer-header`, `.customer-footer`다. `--shop-accent`와 `--shop-tint`는 공통 글자/표면색에 따뜻한 중성색을 소량 섞어 테마를 따른다. `--shop-image-radius:8px`은 이미지, `--shop-control-radius:999px`은 간결한 탐색 도구에 적용한다. 서로 다른 목적의 이미지/컨트롤 모서리를 구분하되 같은 종류 안에서는 통일한다. 관리자 전역 토큰은 변경하지 않는다.

상품명·가격·필터의 읽어야 할 텍스트는 기본14px 이상에 해당하는 rem을 사용한다. 상품 색상 등의 짧은 보조 정보는 최소12px, 모바일의 장식용 브랜드 부제는 작게 압축하기보다 생략할 수 있다. 폰트 설정을 키우면 이 값들도 함께 커진다. 여백과 접힘 구조로 밀도를 줄이고 필수 정보를 지나치게 작게 줄이지 않는다.

## 가격·리뷰·평점 — WB91
상품 카드·상세 상단은 `리뷰 0건`으로 간결하게 표시하며 빈 평점을0.0점으로 만들지 않는다. 리뷰가 있으면 별 아이콘과 평균/리뷰 건수를 함께 표시하고 상세 상단 요약에서 하단 리뷰 영역으로 이동한다. 상세 빈영역은 긴 안내를 허용한다. 가격은 입력된 금액만 강조하고 가격 없음과0원을 구분한다. 로딩/실패를 리뷰0건으로 대체하지 않으며 재시도 경로를 제공한다. 별점은 숫자로도 읽을 수 있어야 한다. 구매 인증을 할 수 없는 상태에서 동작하지 않는 작성 버튼을 보여주지 않는다.

## 판매 가격·할인 — WB92
고객 홈·상품 목록·상세의 가격에는 판매 가격 라벨을 명시한다. 할인시 기본 판매가격은 취소선과 기본가격명으로 구분하고, 할인율/최종 판매가격을 가장 눈에 띄게 표시한다. 숫자만 나열하거나 색상만으로 차이를 표현하지 않는다. 작은 할인에 정수할인율0%를 노출하지 않으며 금액으로 차이를 전달한다.0원과 가격 미입력은 다르다. 공통 가격 컴포넌트를 사용하며 모바일·큰글씨에서 라벨/취소선/최종금액이 겹치지 않아야 한다.

## 의류 소재·실측·세탁 안내 — WB88
상품 상세의 소재·혼용률/사이즈 실측/세탁 안내는 관리자가 저장한 값만 표시한다. 빈 섹션을 추정 문구로 채우지 않는다. 실측표는 단위 cm·사이즈 행·측정 부위 열, 없는 조합은 —로 표시하고 가로 스크롤 영역에 접근성 이름을 제공한다. 줄바꿈/긴문자와 모바일·다크·확대 화면을 지원한다. 배송/교환 정책과 실측 정확성 인증은 이 기능에 포함하지 않는다.

## 고객 로그인·장바구니 — WB100
고객 헤더에 로그인/로그아웃과 장바구니를 제공한다. 로그인 화면은 구글·카카오 두 선택지를 동일한 위계로 표시하며 공급자 설정이 없으면 비활성·준비 중을 표시한다. 조회 실패는 준비 중과 구별하고 다시 확인을 제공한다. 관리자/공장 로그인 메뉴와 인증 쿠키는 분리한다.
상품 옵션·수량 선택 후 담기 완료는 공통 SaveResult에 확정 상품/옵션/수량과 장바구니 보기·계속 선택/쇼핑 동작을 표시한다. 로그인 복귀는 선택 옵션·수량을 보존하되 외부/관리자 경로로 이동하지 않는다. 장바구니 수량/삭제는 고객 쇼핑 목록에서 직접 조작하며 관리 목록·입력 분리 규칙의 대상이 아니다. 변경 완료는 확정 수량·현재 합계와 후속 동작/모바일 포커스를 제공한다. 응답 불확실 시 동일 요청 확인, 충돌 시 입력 보존 후 명시 재조회, 비공개/품절/가격미정은 합계 제외 안내를 표시한다. 현재 합계는 배송비/주문 확정금액과 구별한다.


## 로그인 화면 구성 — WB102
로그인 카드는 브랜드·목적 안내→동일 크기의 Google/Kakao 버튼→비밀번호 불필요 안내·정책 링크 순으로 구성한다. 공급자 아이콘은 장식으로 숨기고 버튼 텍스트로 접근성 이름을 제공한다. Google 공식 G 이미지와 흰색/#747775 경계, Kakao 말풍선과 #FEE500 버튼은 브랜드 식별을 위한 색상 예외이며 주변 카드/텍스트는 공통 테마 토큰을 사용한다. 로고 비율을 유지하고 동작명은 항상 보인다. 연결 중에는 상태 문구와 양 버튼 비활성으로 중복 제출을 막고 브라우저 복귀 시 해제한다. 다시 확인은 조회 실패·연결 준비 중에 제공하며 정상 화면의 주 동작을 방해하지 않는다. 정책 링크를 제공하되 임의의 동의 문구를 만들지 않는다. 비회원 둘러보기는 실제 상품 탐색으로 연결한다.


## 모바일 화면 기준 — WB103 / R106

고객 화면은 767px 이하에서 전용 탐색 구조를 사용한다. 헤더는 브랜드·장바구니·메뉴의 한 줄(최소64px)이며 데스크톱 메뉴를 줄바꿈하지 않는다. 브랜드 부제는 생략하고 44px 아이콘 조작 영역·접근성 이름을 유지한다. 메뉴는 오른쪽 패널(88vw, 최대360px)로 열리며 닫기/Escape/링크 이동 시 닫는다. 닫은 뒤 트리거로 포커스를 돌리고 768px 경계 전환에서는 열린 하위 설정까지 닫는다. 양쪽 계정 표시의 로그아웃 상태를 동기화하고 늦은 계정 조회가 로그아웃을 덮지 못하게 한다.

고객 설정창은 화면 하단 패널이다. 높이는 최대90dvh, 제목/닫기는 고정하고 내용만 내부 스크롤한다. 바닥 safe-area 여백, 배경 스크롤 잠금, 중첩 모달에서 Escape로 최상위만 닫기와 포커스 복귀를 확인한다. 관리자/공장 설정창에는 이 변형을 적용하지 않는다.

| 항목 | 모바일 기준 |
|---|---|
| 좌우 여백 | 공통 space-4(16px), 본문과 헤더·푸터 정렬 |
| 구역 간격 | 24~32px, 페이지 하단40px |
| 본문·입력 | 1rem(기본16px), 입력을 작은 글씨로 압축하지 않음 |
| 제목 | 페이지1.5rem, 섹션1.125rem, 긴 제목 줄바꿈 |
| 보조 문구 | .875rem 중심, 정책/푸터 .8125rem, 카드 색상 .75rem 하한 |
| 조작 영역 | 최소44px, 주요 담기 버튼48px·한 줄 전체 폭 |
| 상품 목록 | 최소9rem 카드 폭과 남는 너비에 맞춘 열 수; 좁은/큰 글씨에서1열 |
| 홈 캐러셀 | 일반 모바일2장, `larger`(현재20px)에서는1장; 태블릿768~1023px3장 |

모바일 로그인은 카드 테두리와 과도한 안쪽 여백을 제거한다. 상세는 이미지→정보→옵션→수량→넓은 담기 버튼 순이며 이미지 높이는 최대62dvh, 설명은1rem/1.7줄높이다. 장바구니는72px 이미지와 유연한 본문, 이미지 없으면 전체 폭을 사용하고 수량/저장/삭제는2열로 정리한다. 소개·정책·푸터도 같은 여백/글자 위계를 따른다. 실제 정책 문구·API/저장 규칙을 디자인 변경으로 확정하지 않는다.

검증은 단순 가로 넘침뿐 아니라 제목 줄바꿈·버튼 문구·이미지 대비 텍스트 비율·한 화면의 정보량을 육안 확인한다. 폭320/390/768/1440px, 기본16px 및 실제 `larger`20px, 테마 양쪽을 대표 화면에 적용한다. 과거24px 목표와 현재 설정20px는 구분하고 실기기/iOS 가상키보드 검증을 데스크톱 뷰포트 검증으로 대체했다고 표현하지 않는다.


## 모바일 푸터 — WB104
브랜드/짧은 소개→주요 쇼핑·정책 링크→고객 문의 안내→사업자 정보 접기→저작권 순서를 적용한다. 영문 구역 제목과 중복 저작권 설명을 모바일에서 생략하며 링크는2열·44px 터치영역·.875rem을 사용한다. 더 크게20px 설정에서는 링크1열로 전환해 긴 정책명이 한 글자만 줄바꿈되지 않게 한다. 개인정보처리방침은 굵기로 구분한다. 사업자6항목은 native details/summary로 접근 가능하며 기본 닫힘이다. 실제 연락처가 없는 현재 초안에서는 등록예정3줄 대신 준비 안내 한 문단을 표시한다. 데스크톱 푸터는 기존 구역을 유지한다. 실제 운영 정보·정책을 임의로 생성하지 않는다.

## 계정 메뉴·빈 장바구니 (WB105)

## WB137 색상칩·옵션 미리보기
공통 ColorChip은 고객·관리자 모두26px 원형, 표면색2px 간격·테마 기반1px 외곽링·약한 그림자로 통일한다. 고객 카드 칩 간격은10px이다. 현재 색상명 기준 대표색이며 실물 색상 보장이 아니다. 알려진 이름만 매핑하고 미지정은 사선 칩과 이름을 표시한다. 관리자에서는 색상명을 항상 병기한다. 고객 홈/목록 카드에는 가격 아래 등록 색상과 중복 제거한 사이즈를 표시하며 구매 가능한 조합/품절은 상세에서 확인한다. 색상칩 자체는 선택/재고 변경 동작이 아니다.

WB137 최신 카드 옵션 기준(사용자 참고 이미지 반영): 고객 카드 색상칩26px·표면색2px 간격·1px 외곽링·약한 그림자, 아래12px 영문 색상명. 알려진 대표색만 영문명을 표시하며 사용자 정의 이름은 보존한다. 사이즈는 S/M/L 등 알파벳을30px 사각 배지에 표시한다. 적은 옵션은 한 줄에 배치해 카드 높이를 줄이고 옵션이 많으면 줄바꿈한다. 관리자도 같은26px 링 칩을 사용하고 옆에 기존 색상명을 병기한다.

WB137 모바일 검증: 기본 글자 크기의 상품 목록은 2열을 유지하여 상품1개가 전체 너비로 확대되지 않게 한다. 큰 글자 설정의1열 예외는 유지한다. 색상·사이즈는 flex wrap으로 넘침 없이 표시하며 다수 옵션의 추가 높이는 자연 줄바꿈으로 허용한다.

## WB142 상품 상세 선택 옵션
상품 상세도 공통26px ColorChip과 카드의 사이즈 표시 helper를 사용한다. 칩 아래 영문 대표색, 사이즈는 S/M/L 등34px 사각 배지(표시전용 카드30px보다 큰 선택용), 버튼 터치영역 최소44px. 선택 색상은 바깥 링과 굵은 이름, 선택 사이즈는 반전 채움, 키보드 포커스는 별도 outline. 품절은 점선·취소선·품절 문구로 구분하고 선택하여 안내를 읽을 수 있지만 구매/담기는 기존 검증으로 차단한다. SKU 선택·OAuth 복귀에는 원래 색상/사이즈 값을 유지한다. 미지정 색상/사용자 사이즈는 임의 번역하지 않는다. 현재 고객 상세만 변경하여 관리자 가이드 영향 없음.


### 고객 주문 필터 (WB150)
주문 목록 상단에 진행 상태와 조회 기간을 공통 FormSelect로 제공한다. 기본 전체 상태·전체 기간, 최근1/3/6개월·1년은 한국시간 주문일 기준. PC는 선택상자2개와 조회/초기화 한줄, 모바일은 선택상자2열·동일폭 버튼 다음줄. 조건 변경 안내를 표시하고 조회 시 첫 페이지로 돌아간다. 빈 결과는 조건 변경/초기화를 안내한다. 관리자 연락처·수령인/내부 상태 조합 입력은 고객 화면에 노출하지 않는다.


### 계정 메뉴 상호작용 (WB151)
계정 팝오버의 링크와 로그아웃은 전체 행44px 이상 터치 영역·동일12px 좌우 패딩·6px 모서리를 사용한다. 포인터 hover는 subtle 배경, 키보드 focus-visible은 동일 배경+포커스 외곽선, 누름은12% text 혼합 배경. 140ms 색상 전환, reduced-motion에서는 제거. 로그아웃 구분선은 별도 그룹에 두어 강조 배경과 분리한다. 비활성 로그아웃에는 hover를 적용하지 않는다.

### 쇼핑몰 계정 메뉴 구성 (WB152)
계정 팝오버는264px 너비·10px 내부 여백·12px 모서리. 상단36px 아바타와 이름/12px 로그인 제공자 요약, 아래18px 선 아이콘+배송 정보/주문 내역/작성 중인 주문서 링크, 구분선 아래 작은 로그아웃을 둔다. 긴 계정 안내와 이메일은 마이페이지 로그인 계정 카드에서 확인한다. 각 링크는44px 이상이며 현재 정확한 URL에 aria-current=page와 subtle 배경을 적용한다. hover/focus/active는 WB151 기준 유지. 모바일 계정 위치/팝오버는 아래 WB153 기준을 따른다. 링크 이동 시 계정 메뉴 닫기, Escape 시 트리거 포커스 복귀. 프로필 이미지가 없으면 기존 이니셜 아바타 사용.

### 모바일 계정과 사이트 메뉴 분리 (WB153)
767px 이하 헤더는 로고와 별도 계정·장바구니·햄버거 도구를 제공한다. 계정은 사이트 메뉴에 포함하지 않는다. 로그인 전 사람 아이콘(접근가능 이름 로그인), 로그인 후 기존 아바타(내 계정 정보)를44px 영역으로 표시하고 이름/화살표는 트리거에서 숨긴다. 계정 팝오버는 도구 영역 오른쪽 아래280px/화면여백 제한, 높이는 화면 범위내 스크롤. 햄버거는 상품·브랜드 소개 및 화면설정만 포함한다. PC는 기존264px 드롭다운 유지. 로딩/재시도는44px compact 영역, 로그아웃 오류는 팝오버 안에서 안내한다. 바깥클릭·Escape·링크이동 시 닫힘 유지.

### 고객 주문 상품명 검색 (WB154)
진행상태·기간과 상품명 입력을 함께 제공한다. PC4열(상태/기간/상품명/동작),767px 이하는 선택상자2열·상품명 전체폭·버튼행. 입력44px, 모바일16px 글자, 명시 label과 placeholder, 최대100자. 조회/Enter 적용, 초기화 시 검색어/조건 모두 지운다. 주문 당시 상품명을 검색하며 빈결과는 조건변경 안내.

WB156: 주문번호 형식과 별개로 is_demo 주문은 목록에 “테스트 주문 · 실제 결제 없음”, 상세에 실제 결제·배송 아님을 표시한다. 번호로 테스트/실주문 여부를 추측하지 않는다.
