# 요구사항 정의서 v0.3

상태 표시는 [결정 기록](decisions.md)을 따른다. 아래 세부 동작과 우선순위는 별도 확정이 없는 한 제안이다.

## 목표·사용자·사업 모델

목표는 의류 정보를 이해하고 상품을 선택할 수 있는 모바일 친화적 웹, 운영 가능한 SKU 재고 관리, 제작 전 의류 시안 작성이다. 거래 기능을 선택하면 주문부터 사후 처리까지 연결한다.

대상은 의류 구매 고객과 상품·재고·출고·CS·재무 운영자다. 시안 사용자는 미정이다. 단일 판매자 B2C 상품 판매 수익을 작업 가정으로 하며 브랜드·가격대·상품 조달·국가·배송은 확정하지 않았다.

성과 지표 후보는 상품 탐색 성공률, 재고 불일치 건수, 시안 작성·수정 소요시간이다. 판매를 도입하면 전환율·품절 취소율·정시 출고율·반품률·환불 소요시간을 추가한다. 목표 수치는 운영량 확인 후 결정한다.

방송형 홈쇼핑·가족 회계는 범위 밖이다. AI·네이티브 앱·생산용 패턴 CAD·원단/부자재 재고는 확정 범위가 아니다.

## 고객 흐름과 예외

거래 도입 시: 카테고리·검색·필터 → 상세·실측·색상/사이즈 → 장바구니 → 주문서 → (도입 시 결제) → 주문·배송 조회 → 교환·반품·환불.

결제 없는 주문 접수의 확정 조건·재고 확보·취소·대금 처리 방식은 미정이다. PG 없는 상태를 자동으로 무통장입금 판매로 간주하지 않는다. 전시만 선택하면 장바구니·주문 버튼은 노출하지 않는다.

검색 결과 없음, 품절 조합, 변경된 가격, 배송 불가 주소, 쿠폰 만료, 외부 처리 결과 확인 중, 배송 예외, 교환품 품절, 환불 지연을 별도 상태로 제공한다. 실패 시 입력을 보존하고 다음 행동을 안내한다.

## 가격·프로모션·사후 처리 정책 제안

금액은 통화 최소 단위 정수로 저장한다. 세금 포함 여부는 시장 확정 후 결정한다. 제안 계산은 기본가+옵션금액 → 상품 할인 → 주문 쿠폰 → 배송비다. 중첩 할인·주문 쿠폰 개수·쿠폰 복원·무료배송 조건 상실 시 비용·귀책별 반품비는 미정이다.

주문 할인은 품목별로 배분해 저장하고 잔여 최소 단위의 배분 순서를 고정한다. 부분 환불은 구매 당시 배분액을 기준으로 한다. 예: 30,000원/20,000원 상품에 5,000원 비례 할인 시 배분은 3,000원/2,000원이며 배송비 조정 없는 첫 품목 환불 기준액은 27,000원이다. 정책 예시이지 승인된 행사 규칙은 아니다.

취소는 출고 작업과 경합 제어가 필요하다. 동일 금액 옵션 교환을 초기 후보로 하며 차액·선출고·재고 확보 시점은 미정이다. 법정 권리는 자동 화면 제한만으로 거절하지 않고 CS 예외 접수를 제공한다.

## 권한

방문자는 공개 상품, 고객은 자신의 주문·주소·문의만 접근한다. 상품 담당은 상품·가격, 재고 담당은 입고·조정, 출고 담당은 필요한 수령 정보, CS는 주문·클레임·문의, 재무는 환불 실행·대사를 담당한다. 권한 관리자는 역할 부여를 담당하되 업무상 민감정보 권한과 분리한다. 시안 작성·검토·내보내기·상품 전환 권한도 구분한다.

겸임은 허용하되 기록한다. 고액 환불·계좌 변경·대량 내보내기의 추가 검토 기준은 미정이다. 시스템 작업 계정과 사람 계정을 분리한다.

## 상품 우선 홈·맞춤 진열 보완 (2026-10-25)

- R23: 홈은 상품 카드와 카테고리 탐색을 먼저 보여준다. /about으로 브랜드 소개를 분리하며 두 고객 화면에 개발 상태·API 진단을 노출하지 않는다. 임시 상품임을 간결히 표시한다.
- R24: 관리자 진열 섹션은 카테고리형과 기획전형을 지원한다. 제목·설명·공개 여부·섹션 순서·상품 선택·상품 순서를 편집·추가·삭제하고 저장 결과가 고객 홈에 반영된다.
- R25: 관리자 변경 API는 접근 키로 보호하고, 기존 버전과 다른 저장 요청은 충돌로 거절한다. 허용하지 않는 상품 참조·중복·과도한 필드/수량은 서버에서 검증한다. 저장된 진열은 API 재시작 후에도 유지한다.

수용 기준: 공개 중인 섹션만 고객 API에 포함, 관리자가 숨긴 섹션은 홈에서 제외, 빈 구성을 허용하되 빈 상태 표시. 고객은 카테고리를 선택하고 샘플 상품 상세를 확인할 수 있다. 실제 구매·장바구니·회원 로그인은 이 작업 범위가 아니다.

## 자동 진열·푸터·공동 작업 보드 (2026-10-25)

- R26: 상품 수가 가시 범위를 넘으면 자동 순환과 수동 이전/다음·일시정지를 제공한다. 키보드·포인터 조작, 동작 줄이기 환경을 고려한다.
- R27: 공통 하단에 회사 정보·메뉴·정책 안내를 배치한다. 실제 미제공 사업자 정보와 미확정 정책은 사실로 만들지 않는다.
- R28: 내부 작업 보드에서 완료·진행·다음·결정 필요 상태와 담당·완료 기준을 함께 확인한다. 초기 보드는 저장소 원본의 읽기 전용이며 채팅에서 합의 후 갱신한다.

R28 보완: 루트 workboard.md를 단일 작업 원본으로 관리한다. /admin/workboard에 보드와 Markdown 원문을 제공하며 저장 후 새 요청에 반영한다. 원문 파일 누락이나 필수 작업 필드 오류를 정상 빈 보드로 숨기지 않는다. 프로젝트 지침의 작업 시작·검증·완료 절차와 연결한다.

## 관리자 홈·로컬 로그인 (2026-10-26)

- R29: /admin을 관리자 홈으로 사용하고 /admin/login에서 로그인 후 메뉴별 화면에 접근한다. 로컬 테스트 바로 로그인 버튼을 제공한다. 관리자 키 로그인도 유지한다.
- 관리 홈·진열·작업 보드와 원문은 미로그인 접근을 차단한다. 세션 유지와 로그아웃을 지원하며 키를 브라우저 응답/저장소에 남기지 않는다.
- 테스트 로그인은 개발 환경의 루프백에서만 허용하고 운영 빌드에서는 서버에서도 거부한다. 운영용 계정·역할·복구 체계는 별도 범위다.

## 관리자 업무 현황 (2026-10-26)

R30: /admin 홈은 처리 업무·접수 Q&A·의류 입고·배송 상태·재고 부족을 요약과 목록으로 제공한다. 메뉴 접근을 유지하고 상태 필터와 영역 이동을 지원한다. 연동 전 데이터는 고정 시점 샘플로 명시하고 실제 답변/입고/출고 처리 완료로 표현하지 않는다. 요약 집계와 가용 재고 계산은 FastAPI에서 수행하며 관리자 인증을 적용한다.

## 로컬 상품·재고 관리 기반

/admin/catalog에서 초안 상품 등록·정보 수정, 색상/사이즈별 SKU등록, 사유가 있는 수동 재고 증감과 이력 조회를 제공한다. 모든 변경은 관리자 인증을 요구한다. SKU코드 및 같은 상품의 옵션 조합 중복, 음수 재고, 0변경, 오래된버전, 서로 다른내용의 재전송 ID를 서버가 거부한다. 고객 게시·주문예약·격리·배송 연동·개인 계정 감사·가격 이력은 후속이다.

R31: 상품·재고 관리에서 목록과 등록 양식을 별도 화면으로 제공한다. 상품 등록·색상/사이즈 등록의 쉬운 용어를 쓰고 목록에서 등록/수정으로 이동 및 복귀할 수 있다. 상품 등록이 고객 게시를 의미하지 않는다는 안내를 유지한다.

R32: 내부 관리명과 고객 표시명을 구분한다. 내부 관리명은 카테고리와 등록 순번을 기반으로 서버가 자동 생성하며 고객 표시명은 관리자가 입력한다. 카테고리는 서버의 분류 목록을 선택하는 방식으로 제공한다. 기존 데이터 보존과 동시 등록의 번호 유일성을 검증한다.

R33: 대분류→세부 카테고리와 착용 계절을 관리한다. 관리자는 카테고리를 추가하고 이름·순서·사용 여부를 수정한다. 신규 내부명은 대분류-세부분류-계절-조합별순번으로 발급한다. 계절은 복수 선택 또는 사계절이며 정규화한다. 기존 내부명은 변경하지 않고 미지정 세부 분류·계절을 보존한다. 계절/분류 변경은 발급명 변경을 뜻하지 않는다.

R34: 관리자 상품·옵션·재고·카테고리 양식에 필수/선택/자동 생성 항목을 구분한다. 펼친 옵션 목록에도 공통 디자인을 적용하고 키보드·포커스·비활성·오류 상태를 지원한다. 기존 미지정 상품의 이름 수정 예외는 유지한다.

R35: 사용자가 글자 크기를 조절할 수 있으며 같은 브라우저에서 선택을 유지한다. 작은 기본 안내문도 가독성을 개선한다. 확대 후 고객·관리자 화면의 메뉴/입력/옵션이 잘리지 않게 구성한다. 계정별 원격 동기화는 포함하지 않는다.

R35 표시 방식 보완: 글자 크기를 상단에 항상 펼쳐두지 않고 톱니바퀴의 사이트 설정 패널에서 조절한다. 고객·관리자·로그인 화면에 설정 진입을 제공한다.

R35 설정 구조 보완: 사이트 설정은 분류별 항목을 확장할 수 있는 공통 구조다. 글자 크기는 화면 및 접근성 분류의 하위 항목으로 제공하고 공통 설정 셸과 기능 코드를 분리한다. 후보·권한·저장 범위는 docs/site-settings.md를 따른다.

R36: 신규 상품 등록이 성공하면 입력 폼을 완료 화면으로 전환하고 저장된 상품 표시명·내부 관리명을 보여준다. 완료 제목으로 포커스를 이동하며 해당 상품의 색상·사이즈 등록과 상품 목록 이동을 제공한다. 색상·사이즈 등록 후 옵션별 재고를 관리한다는 다음 단계를 안내한다. 다른 상품 등록은 명시적으로 시작하며 실패 시 입력을 유지한다. 기본 정보 등록이 고객 화면 게시나 판매 준비 완료를 의미하지 않는다.

R37: 등록 상품 목록에 수정·색상/사이즈·삭제 작업을 일관된 공통 스타일로 제공한다. 삭제 확인에는 상품명과 내부명을 표시하고 명시적 확인 후 요청한다. 현재는 연결된 색상·사이즈가 없는 상품만 삭제하며 서버에서 권한·버전·연결 상태를 다시 검증한다. 재고0이어도 옵션이 있으면 삭제하지 않는다. 성공 후 목록을 갱신하고 실패 시 행을 유지한다. 내부 관리명 발급 순번은 재사용하지 않는다.

R38: 상품 등록 완료의 색상·사이즈 등록/상품 목록/다른 상품 등록을 같은 작업 그룹에 배치한다. 등록 상품 목록에는 서버가 계산한 옵션·현재고 준비 상태, 재고가 있는 옵션 수/전체 옵션 수, 총 재고를 표시한다. 옵션 없음/현재 재고 없음/일부 옵션만 재고 있음/모든 등록 옵션에 재고 있음으로 구분하고 소진 시 갱신한다. 실제 고객 게시 상태는 별도로 표시하며 재고 준비를 자동 게시나 전체 판매 준비 완료로 표현하지 않는다.

R39: 게시 상태는 준비 상태와 별도 컬럼으로 제공하고 게시 불가 배지·짧은 사유를 표시한다. hover 시 상세 사유를 보여주며 키보드 포커스와 모바일 탭으로도 접근할 수 있다. 현재 게시 기능 미연결을 명시하고 옵션/현재고 준비 부족과 구분한다. 일부 옵션 품절을 새로운 전체 게시 차단 정책으로 확정하지 않는다.

R40: 관리자 색상·사이즈 기준정보를 이름·코드·순서·사용여부로 관리하고 옵션 등록에서 콤보박스로 선택한다. 생성 후 현재 화면에서 바로 반영하고 다른 화면/창에서 돌아올 때 최신 목록을 불러오되 작성 중인 입력을 보존한다. 옵션 등록 중 기준값 빠른 추가를 제공한다. SKU 코드는 상품 내부명과 선택한 색상·사이즈 코드로 서버에서 자동 생성한다. 신규 SKU는 ID참조만 허용하고 활성·종류·중복을 서버에서 검증한다. 기존 SKU코드·이름·재고·원장은 이관 시 보존한다.

## R41 다중 옵션 조합 등록

관리자는 상품 하나의 여러 색상과 여러 사이즈를 선택해 조합을 미리 보고 한 번에 등록할 수 있어야 한다. 기존 조합은 중복 생성하거나 재고를 변경하지 않는다. 서버는 신규 조합을 원자적으로 저장한다. 완료 화면은 실제 신규/기존 개수와 등록 조합을 표시하며 재고 입고·목록·추가 등록 경로를 제공한다. 입력 실패 시 선택값을 보존한다. WB31 계획 및 검증 기록을 따른다.

## R42 선택 조합과 옵션별 초기 입고

관리자는 조합별 등록 제외·복원을 할 수 있고 등록할 신규 조합마다 초기 입고 수량을 입력한다. 제외한 조합은 생성하지 않는다. 초기 수량은0도 허용하며 양수는 재고 원장에 기록한다. SKU 생성과 초기 입고는 한 트랜잭션으로 처리한다. 기존 조합은 재고를 덮어쓰지 않으며 동시 요청/재시도도 이중 입고하지 않는다. 완료 화면은 실제 신규 조합별 수량과 합계를 표시한다. R41의 신규 재고0 고정 흐름은 이 사용자 요청으로 확장한다.

R43: reorder_point를 재고 부족 표시 기준으로 표시한다. 현재 재고가 기준 이하이면 확인 필요,0은 재고 없음만 표시한다. 신규 조합 공통 적용/기존 옵션 불변을 안내하고 실제 입고나 자동 발주와 구분한다. 관리 표 중앙 정렬을 옵션 입력/작업 표까지 기본 적용하며 원장 상단 예외를 명시한다.

R44: 신규 조합마다 재고 부족 표시 기준을 별도로 입력하고 공통값을 등록 대상 신규 조합에 한 번에 적용할 수 있다. 공통값 편집과 실제 적용을 구분하며 적용 후 개별 수정 가능하다. 제외/기존 조합은 적용하지 않고 신규 추가 조합은 기본0이다. 초기 입고와 기준값을 혼동하지 않으며 실패/새로고침 시 입력을 보존한다. R43의 공통 기준 입력은 이 기능으로 확장한다.

R45: 재고 입고·조정 성공 시 대상 옵션·실제 변경 전후 재고·증감·사유·기록시각이 있는 완료 화면으로 전환한다. 완료 제목에 포커스를 주고 다음 조정/목록/이력 확인을 제공한다. 실패/불확실 응답은 입력·재시도 정보를 보존한다. 저장 성공과 목록 갱신 실패는 구분하며 최신 조회 없이 추가 조정을 시작하지 않는다. 이 완료 피드백 원칙은 모든 향후 저장·수정 화면의 공통 디자인 및 검증 기준이다.

R46: 재고 변경 이력 목록과 입고·조정 입력을 별도 URL로 분리한다. 목록에는 등록 진입, 입력/완료에는 이력 복귀를 제공한다. 입력 아래 전체 이력을 함께 표시하지 않는다. 이 원칙은 모든 향후 관리 목록·등록·수정의 필수 디자인/검증 기준이다.

R47: 관리자 전체 화면을 점검하여 카테고리·색상/사이즈 기준정보·진열 섹션 목록과 등록/수정 화면을 분리한다. 대분류 및 세부 카테고리 등록 진입을 명확히 제공한다. 상품 수정 및 기준정보/진열 저장은 서버 확정 결과를 명확한 완료 패널로 표시한다. 읽기 전용 대시보드/작업 보드, 인증 화면, 즉시 적용 개인 설정은 목적에 맞는 구조를 유지하며 예외 이유와 검증 범위를 기록한다.

R48: 조합별 초기 입고 수량에 공통값 일괄 적용을 제공한다. 실제 초기 입고와 부족 표시 기준은 별도 제목·설명·입력·버튼으로 구분한다. 입고 일괄 적용은 현재 신규 등록 대상의 초기수량을 같은 값으로 바꾸며 기준값은 보존한다. 기존/제외 조합 불변, 적용 후 개별 수정 가능. 적용은 입력 편집이며 실제 저장은 일괄 등록으로 수행한다.

R49: 공통 입고/부족 기준 도구는 상품·색상·사이즈 선택 다음, 조합별 입력 표 이전에 둔다. 상세 설명은 제목 옆 물음표 도움말로 제공하고 적용 대상·오류·적용 결과는 항상 표시한다. hover·포커스·터치 및 닫기 지원, 미적용 공통값의 검증은 최종 저장과 분리한다.

R50: 재고 입고·출고·조정 구분과 판매/증정(지인제공포함)/불량폐기/기타출고 사유를 구조화해 저장한다. 수량은 양수로 입력하며 유형에 따라 증감을 결정하고 서버가 사유-부호·재고범위·버전을 검증한다. 원장 목록은 사유별 조회를 제공하고 기존 자유기재 원장은 미분류로 보존한다. 판매 출고는 수동재고기록이며 주문/실결제/정산 자동연동을 의미하지 않는다. 기존재시도·불변원장·완료피드백 원칙을 유지한다.

R51: 상세사유는 선택입력이고 처리유형/사유코드는필수다. 등록확정후이력목록으로자동이동하고실제조회원장과대조한결과를안내한다. 이력은입고(공장·공급처등에서보유재고로),고객판매출고,기타출고/조정,기존미분류로구분해조회한다. 이구분은기존사유기반관리보기이며발주/생산/배송자동화나거래처정보확정을뜻하지않는다.

R52: 재고 입고·고객 판매 출고·기타 출고 및 조정은 업무별 진입과 입력 화면 문구를 제공한다. 선택한 흐름에 맞는 사유만 제공하고 현재 수량·증감·예상 결과를 보여준다. 이력의 세부 사유 필터도 선택 흐름과 일치해야 한다. 기존 목록/등록 분리, 선택 메모, 확정 후 이력 이동 및 실패 재시도 계약은 유지한다.

R53: 재고 첫 화면은 상품·색상·사이즈별 현재 보유 수량과 입고·판매·기타출고·조정을 비교하는 현황이다. 입고/출고/조정·기존 기록은 분리된 읽기 화면으로 제공하고 상품 식별 정보를 표시한다. 공장·공급처는 별도 목록/등록/수정 화면에서 관리하고 신규 입고 시 사용 중인 공급처를 선택한다. 입고 원장에는 당시 공급처명을 보존하며 기존 미기록은 추정하지 않는다. 초기 입고와 미분류의 집계 범위를 명시한다.

R54: 공급처 목록의 작업 버튼·안내·결과 사이에 공통 토큰 기반 세로 간격을 적용하고 빈 상태를 별도 영역으로 구분한다. 빈 목록/데이터 목록/모바일/확대 글꼴 상태를 검증한다.

R55: 사이트 설정의 화면 및 접근성에서 라이트·다크·시스템 테마를 선택한다. 기본 시스템, 브라우저 저장, 명시 선택 우선, 시스템 선택 시 OS 변화 반영. 고객/관리자 공통 적용과 초기 표시·잘못된 저장값·저장 차단·탭 동기화를 검증하고 글자 크기 설정은 독립적으로 유지한다. 상품 이미지 색상은 변경하지 않는다.

R56: 공장·공급처에 영문명, 대표자명, 대표전화, 사업자등록번호, 담당자명·연락처, 이메일, 우편번호·주소·상세주소, 메모를 선택 입력한다. 기본정보/연락처/주소·메모로 그룹화하고 목록 요약을 제공한다. 기존 입고 원장과 공급처 snapshot은 유지한다. 이전 클라이언트 수정에서 누락한 추가 필드를 삭제하지 않으며 명시한 빈 값만 비운다. 연락처는 관리자 권한으로 조회·수정한다.

R57: 주소는 국가를 먼저 선택한다. 대한민국은 주소검색·직접입력, 해외는 국가/지역/도시/주소1·2/우편번호를 직접 입력한다. 국가 미지정과 기존 주소는 보존하며 국가변경·검색 취소·실패로 주소를 자동삭제하지 않는다. 국내 검색 선택은 우편번호와 기본주소만 갱신하고 상세주소는 보존한다. 외부 검색은 사용자 클릭으로만 로드하고 직접 입력 대안을 유지한다.

R58: 전체 관리자 등록·수정 화면을 감사해 상품·옵션조합·재고·공급처·진열 등 복합 입력은 본문폭을 활용한다. 짧은 기준정보/인증폼은 적정너비를 유지하고 이유를 기록한다. 모바일 입력그룹은 1열이며 표의 내부스크롤만 예외다. 간격토큰과 다크/확대글꼴/입력상태·저장 동작을 함께 검증한다.

R59: 공급처 등록·수정 성공 후 목록으로 자동 이동하고 조회 결과와 대조한 저장 안내를 제공한다. 대표전화/담당자 연락처는 선택이며 국내형식 숫자 최대11, 선두 + 국제형식 최대15로 화면·서버에서 검증한다. 구분기호는 숫자 길이에 제외한다. 기존값을 자동삭제·변환하지 않고 수정에서 누락된 전화는 보존한다.

R60: 전화번호 자리수·문자 제한은 입력 단계에서도 적용한다. 초과 타이핑·붙여넣기는 이전값을 보존하고 거절 안내하며 잘라서 다른 번호로 만들지 않는다. 거절 뒤 해결 전 저장을 막아 이전 일부 번호가 실수로 저장되지 않도록 한다. 기존 초과값은 삭제·교정 가능해야 한다.

R61: 재고 등록의 공급처 보조작업 링크·버튼은 동일한 컨트롤 스타일과 정렬을 사용한다. 라벨/입력/보조작업은 필드로 그룹화하고 옵션명이 길어도 수량과 입력 높이가 맞아야 한다. 전체 옵션 정보는 선택목록 또는 별도 상세에서 읽을 수 있어야 하며 모바일1열·확대글꼴을 검증한다.

R62: 재고 요약카드가 현재보유/입고/출고/조정기존 목록 전환을 담당하며 중복 보기버튼을 제거한다. 선택상태·키보드접근을 제공하고 조정기존은 기록건수로 표시한다. 전체누계 의미·검색유지·보기별 필터초기화 계약은 유지한다.

R63: 상품 관리와 재고 관리를 메뉴/화면으로 분리한다. 상품목록에는 상품별 실제SKU 재고요약과 해당상품 재고보기만 제공하고 전체재고/입출고원장을 중복출력하지 않는다. 재고보기는 정확한상품ID로 현황/카드/내역을 제한하며 해제·없는상품 안내를 제공한다. 공급처는 재고관리 소속이고 기존저장/옵션등록 계약은 유지한다.

R64: 재고 목록 검색·사유·공급처 필터를 하나의 반응형 도구영역으로 묶고 긴설명은 접근가능 도움말로 제공한다. 목록이 앞에 보이도록 데스크톱은 가로나열, 모바일1열을 사용한다. 라벨/필드/결과요약/표/하단작업간격은 디자인토큰을 적용하며 필터 의미와 상품범위를 유지한다.

R65: 입고/출고/재고조정 등록작업은 목록 위에서 접근한다. 고객판매·기타출고는 출고등록 내부사유(판매/증정/폐기/기타출고)로 통합한다. 재고조정은 증감별도업무로 유지하며 기존원장사유/재시도/수량검증을 보존한다. 기존고객/기타URL은 출고유형으로 호환한다.

R66: 재고 현황/입고/출고/조정 목록은 페이지당10/20/50/100건(기본20) 선택과 페이지이동을 제공한다. 검색/필터/보기/상품범위/표시개수 변경시첫페이지, 결과축소시유효페이지 보정. 필터전체 결과수/수량합계와 요약카드 의미는 페이지와 독립이며 빈결과·모바일·키보드를 검증한다.

R67: 상품/공급처/카테고리/색상·사이즈/진열/대시보드업무목록/작업보드상태열에도 공통페이지네이션과10/20/50/100표시선택을 제공한다. 기존검색/필터변경시첫페이지,집계/진열순번/폼참조/인증/Markdown단일원본은 유지한다. 등록폼선택영역과원문등 예외는감사기록에 명시한다.

R68: 재고현황 부족상태는 빨강 배지·경고아이콘·부족 문구, 양호는 초록 배지·확인아이콘·양호 문구로 표시한다. 기존 현재수량<=옵션별기준 판정을 유지하고 라이트/다크에서 구분한다.


R69: 재고 현황과 입출고/조정 내역의 상품명은 해당 ID의 관리자 상품 상세로 연결한다. 상세는 기본정보와 재고 요약을 읽기 전용으로 제공하고 수정·옵션등록·재고보기로 연결한다. 관리자 인증과 없는 상품 안내를 제공한다.


R70: 상품 상세 이미지를 내부 시안(design), 고객용 모델 착용(model), 고객용 의류 단독(garment)으로 나눈다. 별도 이미지 등록 화면에서 파일·설명 입력과 미리보기, 상세 복귀 후 저장 확인을 제공한다. 이미지 삭제는 확인과 결과 안내를 제공한다. 서버 인증·파일 검증·상품별 소유관계를 검사하고 시안은 고객에게 노출하지 않는다. 고객용 분류는 자동 게시가 아니다.


R71: 상품마다 담당 공장을 한 곳 연결한다. 기존 입고처에서 임의 추정하지 않으며 내부 관리자가 설정한다. 공장은 배정된 상품만 본다.
R72: 내부 관리자가 공장 계정을 발급·중지·비밀번호 변경한다. 공장 계정은 소속 공장 범위만 조회/변경하며 관리자 전체 정보·API에 접근할 수 없다. 계정 중지·비밀번호 변경 시 기존 세션 폐기.
R73: 내부 시안은 비공개 기본이며 관리자가 선택한 해당 상품의 시안만 담당 공장에 공유한다. 소속·상품 배정·자료 공유 권한을 서버에서 확인한다.
R74: 내부 관리자가 담당 공장에 SKU별 추가 제작 수량/희망 완료일/공개 요청 사항을 등록한다. 공장은 자기 요청을 접수·제작 중·제작 완료로 처리하고 이력을 유지한다. 제작 상태는 실제 재고에 영향을 주지 않는다.


R75: 상품별 담당 공장과 시안·샘플 작업 상태를 내부 상품 목록/상세 및 공장 목록/상세에 표시한다. 작업대기·디자인시안확인중·샘플작업중·시안완료와 변경메모/이력을 제공한다. 내부관리자와 배정 공장만 변경하며 상품버전 충돌을 검사한다. 재고·제작요청·공개 상태와 분리한다.

R76: 상품 상세는 공장·작업 상태 요약과 전용 관리 연결만 제공한다. 시안·샘플 관리 목록/조회·이력/변경 입력을 분리하고 저장 후 조회로 복귀한다. 빈이력의 페이지 조작부를 숨기며 공통 간격·버튼·접근성·모바일 기준을 적용한다.

R77: 버튼·입력창·카드의 모서리를 공통 반경 토큰으로 통일한다. 배지·도움말 등 용도별 형태는 구분하며 테마·모바일·포커스에서도 유지한다.

R78: 상품 목록 관리 열은 수정과 더보기로 정리하고 색상·사이즈 등록/삭제는 더보기 안에 배치한다. 기존 삭제 확인·검증, 키보드·모바일 조작과 포커스 복귀를 유지한다.

R79: 상품 상세 공장 요약은 공장명 링크와 진행 상태로 제공하고 공장명 클릭 시 해당 상품의 시안 상세로 이동한다. 중복 관리 버튼을 제거한다. 내부 시안 이미지는 시안 상세에서 관리하고 고객용 모델/의류 이미지는 상품 상세에 유지한다. 이미지 등록/취소/완료 복귀도 종류별 화면으로 연결한다.

R80: 담당 공장과 시안 상태는 상품 정보 항목으로 통합하고 이름/동작/상태를 명확히 구분한다. 모든 이미지 종류의 등록 화면은 파일 선택과 드래그앤드롭을 지원하며 기존 검증·미리보기·저장 절차를 유지한다.

R81: 상품 운영 상태와 시안 진행 상태를 별도로 표시한다. 상품 상세의 상품명 오른쪽에 운영 상태를 명확하게 배치한다. 게시기능 미구현 현재는 미게시로 표시하며 판매가능을 추정하지 않는다.

R82: 공장 협업 메뉴를 누르면 시안 관리 목록을 우선 표시하고 시안·샘플 관리 명칭을 시안 관리로 통일한다. 제작 요청 목록은 별도 하위경로로 제공한다.

R83: 시안 등록의 고정 이미지종류 선택을 제거한다. 이미지 이름은 필수, 설명은 선택으로 UI·서버 검증을 일치시키며 설명없는 이미지도 이름으로 식별 가능하게 표시한다.

R84: 기존 옵션의 재고 부족 표시 기준은 재고현황에서 별도 수정 화면으로 이동해 저장한다. 실제재고·입출고이력은 변경하지 않으며 버전충돌을 검증한다. 저장확정 결과·후속목록링크, 실패입력보존/재조회, 신규등록화면 목적 안내를 제공한다.


R85: 상품 상세에서 기본정보·색상/사이즈·재고를 조회하고 별도 등록·수정 화면으로 이동한다. 상품 문맥에서 저장한 뒤 확정 결과를 확인하고 해당 상품 상세로 복귀한다.


R86: 옵션별 사용 중/사용 안 함을 표시하고 별도 옵션 수정 화면에서 사용 여부와 부족 기준을 함께 저장한다. 비활성 전환과 재활성 시 재고·입출고이력·옵션 식별값을 보존하며 서버 버전 충돌을 검사한다.


R87: 중요한 상태·수량·저장 변경값을 제목/숫자/배경/간격으로 강조하고 라벨·설명·코드와 위계를 구분한다. 우선 옵션 수정/저장 결과와 상품 상세 재고에 적용하며 모바일·다크·확대에서도 유지한다.


R88: 구현된 관리자 전체 화면군의 핵심값 위계를 점검하고 공통표현으로 통일한다. 화면별 변경/유지 근거와 실제 검증경로를 기록하며 업무규칙·샘플표시·페이지네이션·저장피드백·권한을 유지한다.


R89: 카테고리 경로는 > 문자로 구분한다. 상품 목록은 상품명/내부명, 카테고리/계절을 묶고 설명은 상세에서 제공하여 6개열로 단순화한다. 게시사유·재고링크·관리동작·페이지네이션 유지.

R90: 다른 관리자 목록에서도 이름·현재 수량·상태·기한 등 판단 정보를 직접 표시하고, 같은 대상의 코드는 같은 셀에 묶는다. 누계 세부·기록자·상세 사유는 접근 가능한 펼침 또는 기존 상세 화면에서 제공한다. 검색·필터·페이지네이션·관리 동작은 유지한다.

R91: 로컬 개발에서 공장 테스트 계정으로 바로 로그인한다. 전용 합성 공장·담당 상품·공유 시안·제작 요청으로 공장 업무를 확인하며 기존 공장 인증/권한을 우회하지 않는다. 내부 관리자와 공장 세션을 역할 전환 시 분리하고, 공장 화면·상태 변경·접근 차단을 사전 검증한다.

R92: 공장 홈은 배정된 담당 상품·시안 상태·제작 요청 대시보드로 제공한다. 내부 관리자 디자인 토큰/위계와 통일하고 업무 항목에서 정확한 상품/시안/제작 요청 상세로 이동한다. 완료/취소와 진행중을 구분하며 전체 목록은 별도 화면에서 검색·필터·페이지네이션으로 조회한다.

R92 후속: 공장 보호 화면의 GNB를 왼쪽 사이드바로 배치하고, 상단 로그아웃 옆에 현재 로그인한 공장 담당자의 프로필을 제공한다. 모바일 메뉴는 열기/닫기와 키보드 복귀를 지원한다. 프로필 수정 기능을 이 요청으로 확정하지 않는다.

R93: 공장 관리자는 본인 계정 이름·비밀번호를 수정할 수 있다. 아이디·소속 공장·권한·활성 상태는 서버에서 변경 불가로 검증한다. 비밀번호 변경은 현재 비밀번호 확인과 다른 세션 만료를 적용한다.

R93 후속: 프로필 저장 성공 시 완료 화면 없이 대시보드로 이동하고 일회성 저장 알림을 제공한다. 홈 제목은 대시보드로 표시한다. 실패 시 수정 화면을 유지한다.

R94: 공장은 샘플과 완제품 발송을 구분한다. 내부 담당자는 실수령·누락·합격·불량을 기록하고 완제품의 입고 확정시에만 합격 수량을 SKU 재고에 반영한다. 샘플은 판매 재고에 반영하지 않으며 검토 승인/수정요청을 별도 기록한다. 역할별 업무 화면, 분할 발송, 중복 입고 차단과 감사 이력을 제공한다.

R95 (WB13): 관리자 대시보드는 서버 저장 SKU의 현재 보유 수량·전체 옵션 수·부족 옵션 수를 실제 데이터로 제공한다. 부족 판정은 재고 목록과 동일한 on_hand <= reorder_point이며 사용 안 함 옵션도 포함한다. 입고·출고 후 진입/새로 조회 시 최신값을 반영하고 요약에서 전체/부족 조건의 재고 목록으로 연결한다. 조회 실패와 0건을 구분하고 예약·판매 가능 수량을 임의로 추정하지 않는다.

R96 (WB87): 내부 등록 상품의 준비 중/게시/게시 중지를 별도로 관리하고 고객 홈·목록·상세에 실제 게시 상품을 연결한다. 고객용 이미지·사용 중 옵션·품절을 표시하고 카테고리/검색/색상/사이즈/재고 조건을 같은 SKU 조합 기준으로 탐색한다. 기존 상품은 자동 게시하지 않으며 내부 시안·공장·정확한 재고·관리 정보는 공개하지 않는다. 시즌·커스텀 진열도 실제 상품을 선택한다. 결제/주문 도입은 미정으로 유지한다.

R97 (WB89): 고객 상품 검색은 기본 화면에 남기고 상세 필터·정렬·표시 개수는 기본 접힌 토글로 제공한다. 선택 조건은 접힌 상태에서도 확인/해제할 수 있어야 하며 URL·페이지 초기화·키보드 접근을 유지한다. 고객은 상품 이미지 중심의 간결한 디자인, 관리자/공장은 업무 정보 중심으로 기준을 나누되 공통 토큰·접근성은 공유한다.

R98 (WB91): 가격관리 경로와 가격 변경 이력을 제공한다. 해당 상품 구매 고객만 리뷰 작성, 본인만 수정·삭제할 수 있으며 서버에서 인증/구매/소유권을 확인한다. 공개·미삭제 리뷰만 평균/건수에 반영하고 목록·상세 상단은 리뷰 0건, 평균 없음으로 표시한다. 내부 관리자는 사유를 남겨 숨김/복원과 답변을 관리하며 별점/본문을 대필하지 않는다. 회원/주문 연동 전 실제 고객 쓰기는 차단한다.

R99 (WB92): 고객 가격은 판매 가격 라벨과 함께 명확히 표시한다. 관리자가 기본 판매가격 및 선택 할인 판매가격을 저장하면 서버가 최종 판매가격/할인율을 계산하고 홈·목록·상세에 일관되게 표시한다. 할인시 기본가취소선·할인율·최종가로 구분하고 변경이력을 보존한다. 할인금액은 기본가미만 정수, 기본가없는할인은 거부한다.

## R19–R20 관리자 통합 범위 — WB93
사용자 승인에 따라 검토한 티셔츠·후드 3D 샘플을 관리자 의류 디자인에 통합한다. 원단·핏·사이즈·앞뒤 다중 나염·후드 둘레 배치와 서버 저장/재조회가 대상이다. 기존 문서는 호환한다. 목록/신규/편집/상세를 분리하고 상품 SKU·가격·재고를 자동 변경하지 않는다. 실제 제작 치수·물성 및 샘플 브라우저 작업 자동 이관은 별도 범위다.

## R100 (WB95) 상품 상세 편집 통합
사용자 확정: 상품 수정 내용을 상품 상세 한곳에서 수정한다. /admin/catalog/{id}에서 기본정보와 가격·할인·공개 설정을 편집하고 저장 후 같은 화면에 결과를 표시한다. 구역별 저장은 해당 구역만 저장하며 다른 구역 초안을 보존한다. 기존 두 수정 URL은 인증 후 상세 해당 구역으로 연결한다. 상품 목록·신규 등록·재고 원장 업무 분리는 유지한다.

## R101 (WB96) 상품 상세 선택 탭
기본정보·가격/할인·색상/사이즈·재고·리뷰 관리에서 활성 탭을 명확히 표시하고 해당 패널만 아래에 표시한다. 탭 왕복에서 입력·저장 결과를 보존하고 가격 바로가기/기존 해시 진입은 일치하는 탭을 선택한다. 키보드와 모바일 사용을 지원한다.

## R102 (WB98) 관리 목록 줄무늬 배경
모든 관리자·공장 관리 목록에서 표시 순서의 2·4·6·8번째 행에 옅은 배경을 적용한다. 행 간격은 변경하지 않고 밝은/어두운 테마에 맞춘다. 홀수 행·고객 화면 및 기존 경고/선택 표시는 유지한다. 헤더는 후속 R103의 전용 배경·구분선을 따른다.

R103 (WB99): 관리 표 헤더는 짝수행 줄무늬와 구별되는 전용 배경·하단 경계선·글자 굵기를 사용한다. 공통 및 관리자 디자인 시스템과 실제 공통 CSS를 함께 유지한다.

## R104 (WB88) 상품 상세 정보
관리자 상품 기본정보에 선택 입력으로 소재·혼용률, 세탁·관리 안내, 사이즈/측정부위별 실측(cm), 측정 방법·참고사항을 제공한다. 기존 기본정보 저장·버전·권한 계약으로 함께 저장하며 고객 상품 상세에는 입력된 정보만 표시한다. 구 클라이언트가 상세정보를 생략한 수정은 기존값을 보존한다. 정보 입력이 SKU/가격/재고를 변경하거나 새 게시 필수조건이 되지 않는다. 서버 경계·마이그레이션 보존·공개범위 검증을 수행한다. 상세 docs/contracts/product-details.md. 실제 회사/배송/교환/결제 정책은 이번 승인 범위 밖이다.

## R105 (WB100) 고객 소셜 로그인·장바구니
사용자 확정: 자체 가입/비밀번호 대신 구글·카카오 OAuth 로그인과 고객별 장바구니를 구현한다. 소셜 최초 로그인으로 계정을 생성하고 공급자 고유ID로 구분하며 이메일로 자동 병합하지 않는다. 장바구니는 선택 SKU/수량을 고객별 저장하고 현재 공개상태/가격/재고를 서버에서 확인한다. 주문/결제/재고예약은 이번 범위 밖이다. 개발자 앱 등록·키 설정은 사용자 담당이며 실제 연동 성공은 별도 검증한다. 계약 docs/contracts/customer-shopping.md, 설정 docs/customer-login-setup.md.


## R106 (WB103) 고객 모바일 화면
사용자 확정: 고객 사이트 전체의 헤더/nav/모달/폰트/여백을 모바일에 맞게 다듬고 디자인 시스템과 작업 보드에 반영한다. 홈·상품 목록/상세·로그인·카트·소개/정책·푸터를 함께 점검한다. 터치 영역, 메뉴/모달 키보드·포커스·스크롤, 작은 화면/큰 글씨와 데스크톱 회귀를 검증한다.

## R107 고객 계정 정보·장바구니 표현
로그인 계정의 이름·공급자·제공된 확인 이메일과 로그아웃을 계정 메뉴에서 확인한다. 선택 프로필 부재에도 로그인을 유지하고 기존 고객/세션/카트를 보존한다. 빈 카트는 아이콘·안내·쇼핑 CTA로 표현하며 정상 상태에 조회 재시도 버튼을 노출하지 않는다. WB105.

R107 후속(WB107): 로그인한 고객에게 제공된 소셜 프로필 사진 표시. 사진이 없거나 로드 실패하면 이름 첫글자 표시, 사람 아이콘은 로그인 전만 사용한다.

## R108 브랜드 소개 콘텐츠 관리
사용자 확정: 옷과 사이트의 중심은 나의 개성과 관심사를 보여주는 독특한 디자인이다. AI와 전문 분야의 개념·문화를 주제로 의류 디자인을 소개한다. 브랜드 소개에 생성한 의류 콘셉트 예시를 넣고, 관리자가 문구·대표이미지/대체텍스트·주제별 소개/이미지를 편집·초안저장·미리보기·게시한다. 실제 판매상품과 예시를 구별한다. AI 이미지 생성 자체의 관리자 내 서비스 연동은 제외한다. WB108, docs/contracts/brand-about.md.

R108 후속(WB109): 사용자 요청으로 AI 관련 디자인 예시 1장을 추가한다. HUMAN × AI 그래픽 티셔츠를 기본 소개와 관리자 이미지 선택에 제공한다.

R108 후속(WB110): 소개 텍스트는 의류 판매 브랜드임이 먼저 읽히도록 옷·프린트·스타일링 중심으로 작성한다. AI는 의류 그래픽의 모티프로만 소개한다.

WB111: 관리자 계정/탐색을 왼쪽에 배치하고 UI 크기를 점검한다. 사이트 확대설정과 브라우저 배율을 구분하며 접근성 글자 설정은 보존한다.

## R109 관리자 메뉴 그룹/표시 관리 (WB112)
관리자 메뉴를 그룹화하고 그룹명·순서·메뉴배치·순서·표시 여부를 관리한다. 기본 운영/제작·협업/사이트·고객/프로젝트. 관리자 공통 저장, sidebar 그룹 접기, 전체숨김에도 고정 메뉴관리 진입. 표시와 서버 접근권한은 별개. 상태/편집 화면분리·SaveResult·충돌/실패입력 보존. docs/contracts/admin-menu.md.

## R110 관리자 사용 가이드 (WB114)
WB115: 실제 관리자 화면 캡처에 클릭 위치와 번호를 표시하고 확대해서 확인한다. 업무별 집중 보기와 단계 설명을 함께 제공하며 모든 업무에 캡처를 포함한다. UI 변경 시 캡처·클릭 표식도 동기화한다.
관리자 내부에서 업무별 준비사항·진행 순서·완료 확인·주의사항·관련 화면 링크를 제공한다. 검색/목차로 찾고 메뉴를 숨겨도 고정 사용가이드 진입을 유지한다. 기능 수정 때 관련 설명도 같은 작업에서 수정하도록 원문 단일화·작업규칙·검증템플릿·링크검증을 적용한다. 읽기전용이며 관리자 인증을 따른다.

## R111 상품 상세 구매 동작 (WB118)
사용자는 옵션 미선택 시 무반응 차단 대신 필요한 선택 안내를 요구했다. 담기 클릭으로 유효 색상/사이즈 재선택을 안내한다. 바로 구매는 주문서 및 실제 주문·결제까지 별도 설계 후 구현하는 방향을 사용자 선택. PG 미정이며 후보 비교부터 진행한다. PG 계약·실결제·재고확보/취소 정책은 아직 승인되지 않았다. 판매·기본배송비는 아래 부분 확정을 따르며 나머지 배송정책은 미정이다.

## R112 PG 견적 문의 준비 (WB119)
사용자 요청: 견적 문의 내용과 준비정보를 별도 관리자 메뉴에 남기고 견적 비교 후 PG 선정 방침을 작업 보드에 반영. /admin/payment-preparation에 공통 문의문·업체별 요청·준비정보·카드/간편결제 안내 제공. 메뉴 표시/숨김 지원, 관리자 직접URL 인증 유지. 사이트에 사업자정보/견적서 저장이나 외부문의발송/계약 기능은 추가하지 않음. 사용가이드 pg-preparation 및 캡처 동기화.

### R111 판매·배송 정책 부분 확정 (2026-10-30)
초기는 완제품 재고판매. 배송비는 할인 적용 후 상품금액50,000원 미만3,000원,50,000원 이상 기본배송비0원. 제주·도서산간 추가비는 미정이며 무료배송 임계값과 별도 확정 필요. 향후 검증 경계49,999원/50,000원/50,001원. 실제 금액계산·운영반영은 후속 구현으로 분리. 출고기한 등 미정은 사용자 확인 후 주문서 시안에 반영한다.

R111 출고기한 사용자 확정: 결제 확인 후1~3영업일 이내 출고. 배송 완료 예상일과 구분하여 주문서에 표시한다. 합배송·배송지수 등 나머지 운영정책은 별도 확정 필요.

R111 배송지·합배송 사용자 확정: 주문당 배송지1곳, 동일 주문 합배송. 판매자 사정으로 분할발송할 때 추가 배송비는 판매자 부담하며 고객에게 추가 청구하지 않는다. 다른 주소는 별도 주문. 서로 다른 주문의 합배송이나 고객 요청 분할배송은 별도 미정.

R111 구매자격·소유권 사용자 확정: 로그인 고객만 구매, 비회원 구매 없음. 주문 소유자는 서버 인증 고객ID로 확정하며 본인 주문 조회/취소/반품 요청 권한을 서버에서 검사한다. 고객입력ID/수령인/연락처로 소유자를 대체하지 않는다. 관리자 처리는 관리자 권한으로 분리. 기존 소셜계정 자동병합 없음. 검증 시 비인증/타고객 주문 접근·변경 거부가 필수다.

R111 결제재고 사용자 확정: 결제하기 실행 시10분 임시확보, 승인 시 판매확정. 장바구니/주문서 작성은 확보없음. 취소/실패/미완료 만료시 해제, 결과불명확은 PG확인 후 처리. 서버시간·원자적확보 기준으로 마지막1개 동시요청, 중복클릭, 만료경계, 승인/만료경합, 늦은승인, 승인응답유실을 후속 설계·검증한다. 물리적 보유재고와 판매가능/확보수량을 구분하며 실제 차감·출고 원장처리는 후속 계약에서 명시한다.

R111 배송 전 취소 사용자 확정: 상품 준비 중 전에는 본인 주문 직접 취소, 이후에는 관리자 확인 후 처리. 택배사 인계 후 반품 접수. 서버에서 주문 소유권과 현재 상태를 검증하며 취소/준비 전환 경합 및 PG 취소 실패·응답 유실·중복 요청은 후속 설계와 검증에 포함한다. 반품/교환 비용·기간·부분취소 정산은 별도 미정.

R111 반품·교환 부담 주체 사용자 확정: 단순 변심/고객의 색상·사이즈 변경은 고객 부담, 불량·오배송은 판매자 부담. 편도/왕복 금액 및 무료배송 주문 전체·부분 반품 정산은 미확정으로 분리한다.

R111 일반 지역 반품·교환 정산 사용자 확정: 편도3,000원/왕복6,000원. 고객사유 유료배송 반품은 기존배송비 환급 제외+회수3,000원, 무료배송 전체반품6,000원, 부분반품은 남은 주문당시 할인후상품금액50,000원 이상3,000원/미만6,000원. 고객사유 교환6,000원. 합회수 개수별 부과 및 최초배송비 중복청구 금지. 불량/오배송 고객부담0원·해당사유 부분반품의 무료배송혜택 유지. 제주·도서산간 미정. 후속 검증은 남은금액49,999/50,000/50,001원·기납부배송비·합회수·반복반품 중복청구·판매자귀책을 포함한다. 신청기간은 별도 미정이며 정산 구현 완료 아님.

R111 신청기간·교환품절 사용자 확정: 법정 청약철회 기간과 기산일/예외 보장, 일괄3일 차단 없음. 단순변심 원칙7일, 계약불일치 상품은 공급후3개월 이내이면서 인지/인지가능일부터30일 이내. 색상·사이즈 교환 운영기간7일. 교환 옵션 품절 시 고객 안내 후 반품·환불 전환하며 미발생 재배송비를 청구하지 않고 반품 사유별 정산한다. 후속 검증은 신청일 경계·사유별 기간·옵션 품절 전환 및 비용 중복청구 방지를 포함한다. 정책 기록만 변경, 관리자 UI/가이드·캡처 영향 없음.

R111 회수방식 사용자 확정: 반품·교환은 판매자가 지정 택배사 방문 수거를 접수한다. 회수주소 확인/수정 및 관리자 접수 확인 흐름을 후속 설계에 반영한다. 택배사·반품주소·자동연동은 미정. 교환 발송시점은 별도 결정하며 실제 수거 기능 구현 완료 아님.

R111 교환 출고 사용자 확정: 회수·검수와 필요한 배송비 결제 확인이 모두 끝난 후1~3영업일 이내 출고. 고객 부담금이 없으면 결제를 전제조건으로 두지 않는다. 도착 보장과 구분하며 교환 품절 시 고객 안내 후 반품·환불 전환. 후속 검증에 검수 미완료·필요 배송비 미결제·부담금0원·영업일 경계·품절 전환을 포함한다. 실제 교환/추가 결제 기능 구현 완료 아님.

R111/WB120 국내배송·제주/도서산간 운임확정 전 결제제한 확정. 합성상품 주문서 시안 /checkout/preview, 입력 비저장·실결제 없음. 실제 계정귀속·금액계산·지역판별·재고예약은 후속 서버 구현이다.
R111/WB121 실제 연결: 상품 바로 구매와 장바구니에서 인증 고객 소유 주문서 초안을 만들고 배송지를 저장·재조회한다. 서버 현재 가격/재고 및 소유권을 검증한다. PG 제외, 초안은 구매 확정/재고 확보 아님. 지역 판정 자료 미설정 시 검증대기로 두며 결제는 차단한다. 계약: docs/contracts/customer-checkout.md / 검증: docs/reviews/checkout-live.md.

R111/WB122 회원별 기본정보와 배송지 주소록을 등록·수정·삭제하고 기본 배송지를 지정한다. 소셜 로그인 프로필은 읽기 전용이며 입력 기본정보는 재로그인에도 유지한다. 새 주문서 기본주소 복사 및 다른 주소 선택, 명시적 주소록 저장 선택을 제공한다. 소유권·CSRF·중복/경합·실패보존·주문서 사본독립 검증이 필수. 계약 docs/contracts/customer-account.md.
R111/WB127 배송지 이름·받는 분·연락처·우편번호·기본주소·상세주소 필수. 요청사항은 선택. 누락/공백·형식 오류 시 필드 안내와 입력 보존, 첫 오류로 포커스/스크롤 이동. 서버도 상세주소 필수 검증하며 주소록과 주문서에 공통 적용한다.
R111/WB130 고객 기본정보 편집 화면을 배송 정보 관리로 통합. /account에서 배송지별 받는 분·연락처·주소 및 기본지정 관리, 로그인 계정 읽기전용. 기존 저장 이름·연락처·주소 보존, 구URL 호환 및 신규 배송지 보조 입력 유지.

R111/WB134: 주문서 작성 중 별도 저장/완료 단계를 제거한다. 입력은 같은 탭에서 새로고침 후 복원 가능하며 세션 변경 시 재사용하지 않는다. PG 연결 전 비활성 결제 준비 중 표시. 주소록 등록은 배송 정보 관리에서 수행, 기존 정보 유지.

R111/WB143: PG 제외 고객 본인 주문 목록·상세와 관리자 주문 목록·상세를 조회 전용으로 제공한다. 주문 상태/결제 상태/배송 상태를 구분하고 상품·금액·배송지 사본을 보존한다. 합성 데이터는 격리 검증 DB에만 저장한다. 계약 docs/contracts/sales-orders.md.

R111/WB144 사용자 요청 예외: 현재 로컬 3100 로그인 계정에 합성 주문을 명시적으로 추가해 직접 검토한다. 사전백업·가상배송지·합성표시·중복보존을 적용하고 상품/재고/실결제는 변경하지 않는다. 운영 자동시드 없음.

R111/WB155: 운영용 주문번호 발급 내부기반을 준비한다. 동일 주문 재시도 불변·중복방지·한국시간 날짜·개인정보 미포함·주문생성과 동일트랜잭션. 실제주문 생성/PG 연결은 후속, 합성 기존번호 보존.

R111/WB156: 현재 로컬 기존 합성 주문에 운영형번호를 적용하고 테스트임을 표시한다. 운영 주문이나 기존 상품/재고/계정/주문 UUID는 변경하지 않는다.
