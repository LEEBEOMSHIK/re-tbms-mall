# WB196 · 장바구니 선택 주문

대상은 R105·R107·R111 고객 쇼핑 흐름이다. 참고 시안 A의 카드 배치와 라벤더 표면을 사용하고, 실제 상품 사진과 기존 RE:TAG 서체·색상·옵션 컴포넌트를 적용했다.

## 개발 전 확인과 변경 범위

| 항목 | 기존 상태 | 적용 내용 |
|---|---|---|
| 장바구니 저장 | 고객 세션별 SQLite 장바구니, SKU 단위 조회·PUT·DELETE, 버전·요청 ID 검사 | 기존 API를 유지하고 선택 삭제와 동일 상품 옵션 교체를 원자적으로 수행하는 POST 두 개 추가 |
| 수량 | 숫자 입력 뒤 별도 저장. 화면의 입력과 주문 가능 상태가 달랐다. | 현재 보유 가능 수량과 99개 제한을 적용한 스테퍼. 행과 요약을 함께 미리 반영하고 실패 시 서버 확인값 복원 |
| 주문서 | 장바구니 전체 또는 단일 SKU 바로 구매 | 선택 SKU와 장바구니 버전으로 초안 생성. 미선택 행, 다른 계정, 오래된 버전을 구분. 기존 전체 주문·바로 구매 경로 유지 |
| 금액 | 판매가·상품 할인·가용 재고는 서버에서 제공. 장바구니에는 배송 정책 필드가 없었다. | 서버의 할인 후 금액으로 운임 계산. 일반 지역 기준 정책을 장바구니 응답에 제공하고 정책이 없는 응답은 배송지 확인 후로 표시 |
| 표시·기능 | 상품별 브랜드, 관심상품, 쿠폰, 개인화 추천의 카트 연동 없음 | 실제 상품 사진·옵션과 상품 할인 표시. 외부 기능을 암시하는 버튼은 추가하지 않음 |
| 배송·결제 | 배송비는 주소에 따라 달라질 수 있고 PG 미연결 | 일반 지역 예상과 확정 금액을 구분. 주문서로 이동하며 실제 승인 기능은 PG 선정 후 연결 |

## 검증 근거

- 실제 Chrome에서 합성 카트로 선택·선택 해제, 단일 SKU 주문서 이동, 수량 즉시 반영, 422 복원, 409 재조회, 응답 유실 후 동일 요청 재시도, 옵션 변경과 삭제 확인·취소를 확인했다. 35,000원 한 상품 선택 시 일반 지역 배송비 3,000원, 할인 후 합계 53,000원에서는 배송비 0원을 확인했다.
- PC·태블릿·모바일 6개 뷰포트와 라이트·다크 화면에서 가로 넘침이 없었다. 320px 화면에서도 키보드로 전체 조작에 접근했다. 재현과 캡처는 `.local/wb196-{interactions,layout,keyboard}.cjs`, `.local/wb196-{pc,mobile,tablet-dark,mobile-dark}.png`에 있다.
- 격리 DB의 실제 FastAPI와 웹 프록시 처리 함수를 연결해 48,000원 장바구니에서 24,000원에 해당하는 선택 SKU만 초안에 저장되는 것을 확인했다. 장바구니 변경 후에도 초안의 SKU가 보존됐다. 같은 요청 재시도·계정 분리·옵션 합산·선택 외 SKU 제외·재고 경계는 API 테스트로 검증했다.
- 로컬 8100에 신규 API를 반영했다. 실제 고객 계정의 장바구니, PG 승인, 실배송 운임은 테스트에 사용하지 않았다.

복구 시에는 웹을 먼저 이전 장바구니로 되돌릴 수 있다. 추가 필드 없이 호출하는 전체 카트와 단일 상품 주문서 요청을 서버가 계속 지원하며 기존 DB를 변환하지 않는다. 관리자 가이드 영향은 없다.

## WB198 — 수량 저장 영향 범위 (2026-11-05)
- 요구 R105 / 담당 고객 UI. 기존 blocked가 체크박스·옵션 열기·삭제 확인까지 묶는 문제를 지연 응답 재현에서 확인했다.
- 범위/파일: customer-cart.tsx, use-shopping-cart.ts, cart-option-editor.tsx, cart-layout.module.css. 로컬 선택·옵션 탐색·닫기·삭제 확인/취소는 저장 상태와 분리. 실제 옵션 적용·삭제 확정·주문 진입은 공통 장바구니 버전 경합을 방지하기 위해 서버 확정까지 보호한다. API·DB 계약 변경 없음.
- 수량 상태는 해당 행에만 표시하고 높이를 미리 확보한다. 상품별 합계와 선택 요약은 동일한 미리보기 수량을 사용한다. 서버가 확정한 수량은 행에 ‘수량 저장됨’으로 확인한다. 실패는 기존 전역 오류와 복구 안내를 유지한다.
- 수용 기준: PC·모바일 지연 저장 중 선택 변경/합계/응답 후 선택 보존, 옵션 열기·닫기, 삭제 취소, 실제 쓰기 경합 차단, 수량 연타·실패 복원. 합성 응답을 쓰는 실제 Chrome 화면으로 확인하며 고객 데이터는 변경하지 않는다.
- 자체 검증: 수정 전 체크박스 활성 assertion 실패 → 수정 후 Chrome 1440·390 통과. 저장 중 다른 상품 해제 시 선택 2개·70,000원, 응답 후 선택 유지. 삭제 확인/취소 시 추가 쓰기 없음. 타입 검사·관련 lint·단위/계약 9건 통과. 캡처 .local/wb198-pc.png, .local/wb198-mobile.png.
- 관리자 가이드 영향 없음: 고객 장바구니의 저장 중 조작 범위만 변경. 복구는 이 절의 4파일 변경만 역적용하며 기존 WB196/197·사용자 변경은 유지한다.

- 독립 검증: 다른 검증자가 실제 소스 검토와 Chrome PC1440·390 touch 재실행. 저장 중 옵션 선택/닫기 허용, 적용은 응답 후 새 version8로 요청, 옵션 저장 중 체크 해제 유지, 422 롤백 후 선택 유지와 합계 일치. 무관 행 opacity 1, 상태문구 미표시, 저장 전후 행 높이 불변, 가로넘침 0. .local/wb198-independent.cjs. 연타 5/5·최대 동시 PUT 1 및 422/409/503 복구 회귀도 재실행 통과. 보드 파서 5건 통과.
