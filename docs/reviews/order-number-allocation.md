# WB155 운영용 주문번호 발급 기반
- 요구 R111 / root 구현 / 2026-11-01.
- 목적: 추후 실제 주문 생성에서 재사용할 운영 번호 발급. 사용자 승인: 운영 발급 로직 준비·합성 검증. 실제 결제/운영배포/실주문 생성 아님.
- 구현 선택: 한국시간 YYYYMMDD-무작위10자(혼동문자 제외32자). 개인정보/순번 노출 없는 문자열. 내부 UUID와 분리.
- 대안: 일별순번은 추측/매출량노출, UUID전체는 가독성낮음. 날짜+난수와 DB UNIQUE/충돌재시도로 구성.
- 계약: 인증·소유권 검증을 마친 서버 주문 UUID에만 내부 함수 사용. 같은 order_id 동일번호. 번호 할당과 주문INSERT는 동일 DB 트랜잭션. 번호는 인증수단 아님.
- 파일: app/order_numbers.py, sales_orders.py, tests/test_order_numbers.py, 계약/결정/요구/보드. API·화면 변경 없음.
- 수용: KST자정/윤년, 충돌재발급/횟수제한, 재시도, 재시작영속, 롤백, 동시연결·기존조회 회귀. 임시DB만 사용.
- 가이드/디자인 시스템 영향 없음: 고객/관리자 화면·절차 변경 없음. 저장 UX 해당없음. 의존성 없음. 복구는 코드되돌림, 추가 할당테이블은 보존(삭제금지).


## 실행 결과
- root: API39개 통과(번호11 + 기존조회28), 최초 실행의 테스트INSERT 컬럼 수 오타2건을 수정한 뒤 전부 재통과. 제품코드 오류가 아닌 테스트 데이터 구성 오류였다.
- 독립 customer_account_review: 코드/계약 차단 이슈 없음, API39 직접 실행 통과, 임시DB preview 정상.
- 동시 연결8개에서 신규60건 중복없음, 같은UUID20회 재시도 동일값. KST자정·윤년·연말/재시작/롤백/충돌10회한도/기존번호 충돌/동일트랜잭션 주문INSERT 검증.
- 실제 preview 출력: 20261101-5KYML3HQTB, 20261101-GTTAXYJ3GL, 20261101-WVAJ5LJXL4. 실제 발급함수에서 무작위 생성되며 다음 실행 결과는 달라진다. 동일UUID 재시도 동일값 확인.
- preview는 TemporaryDirectory 내 별도DB만 생성·자동정리한다. 기존로컬DB/운영DB·합성번호·재고·결제는 변경하지 않음. 서버 재시작/배포 없음.
- 남은 연결: 실제 주문생성 서비스에서 인증·요청키 멱등매핑 후 같은트랜잭션으로 호출. 현재 운영 자동발급 API가 연결된 것으로 표현하지 않는다. PG 미선정 유지.
- UI 변경 없음으로 화면 캡처 해당없음. 새 테스트 생성DB는 운영자료가 아니다.
