# 필수 입력과 옵션 목록 검증

2026-10-26 / WB19 / R18·R31·R34
계획: docs/superpowers/plans/2026-10-26-required-select.md

inventory_ui는 공통 FormLabel·FormSelect와 상품/옵션/재고/카테고리 폼을 구현했다. inventory_review는 구현과 실행 결과를 독립 검토했고 조정 담당은 브라우저 통합과 문서를 확인했다.

필수·선택·자동 생성 표시를 실제 검증 조건에 맞췄다. 필수 선택은 숨겨진 native select의 검증과 연결하고 첫 오류의 보이는 컨트롤로 포커스를 이동한다. 기존 미지정 상품의 분류·계절을 유지한 이름 수정 예외를 보존했다. 옵션 팝업은 공통 토큰, 활성 배경, 선택 체크, 비활성 상태, 스크롤과 위쪽 펼침을 사용한다. API·DB·업무 규칙은 변경하지 않았다.

독립 검증에서 웹 테스트 33개, lint·타입 검사·프로덕션 빌드가 통과했다. 이후 브라우저에서 모바일 자동 스크롤 이벤트가 늦게 도착해 새 팝업을 닫는 문제를 발견했다. 열 때 측정한 위치와 실제 위치가 바뀌었을 때만 닫도록 수정했으며, 목록 자체의 스크롤은 유지한다. 최종 변경의 독립 lint·타입 검사를 별도로 수행했다.

조정 담당이 Edge에서 전체 스모크를 재실행해 exit 0을 확인했다. 필수/선택/자동 생성 표시, 빈 상품명과 빈 분류 제출 시 첫 오류 포커스, 필수 선택 오류 해제, 화살표·End·Enter·Space·Escape·Tab·바깥 클릭, 처리 중 fieldset 비활성화, 계절 누락 차단을 검증했다. 320/390/1440px에서 목록 경계와 가로 넘침을 확인하고 390/1440px 캡처를 직접 검토했다. 기존 상품의 이름만 수정하는 요청과 수정 시 부모 분류 비활성도 통과했다. 상품 쓰기는 브라우저 route 모의 응답만 사용했으며 실제 상품 데이터를 변경하지 않았다.

브라우저 재현 스크립트는 로컬 산출물 .local/required-select-smoke.cjs이다. 전체 스크린리더·모든 모바일 기기 인증이나 실제 서버 저장 검증을 주장하지 않는다. API 변경이 없어 API 테스트는 반복하지 않았다. 디자인 시스템 v0.3에 컴포넌트 계약과 적용 범위를 기록했다. 복구는 해당 UI·문서 변경만 되돌리며 데이터 복구가 필요하지 않다. 커밋·푸시·배포 없음.
