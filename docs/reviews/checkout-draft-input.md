# WB134 / R111 주문서 작성 흐름 정리

2026-10-31 root 구현 / customer_account_review 독립 검토.

사용자 승인 범위: 주문서 저장 버튼·완료 화면 제거, 입력 유지, PG 연결 전 결제 준비 중 표시. 수정 대상 live-checkout.tsx, 입력 보관 helper/test, 디자인 시스템·계약·결정·요구사항·보드. WB133 후속.
입력은 같은 탭의 sessionStorage에 주문서 ID 및 서버 세션 식별값으로 격리한다. 불완전한 입력도 유지하며 새로고침 때 인증된 주문서 조회 이후에만 복원한다. 로그아웃/계정변경은 제거하며 저장소 사용 불가 시 현재 화면 상태는 유지한다. 서버 자동저장/주소록 자동저장/결제/재고 확보는 하지 않는다. 기존 서버 초안·배송지 데이터와 API는 보존한다.
수용 기준: 저장 CTA/완료 화면 없음, 결제 준비 중 비활성, 입력/배송지 선택 및 새로고침 복원, 세션 분리/잘못된 보관값 복구. 검증: helper 경계 테스트, 타입/lint, PC·모바일 실제 UI, 독립 검토. 관리자 가이드 영향 없음(고객 주문서에 한정). SaveResult 예외가 아니라 명시적 저장 동작 자체를 제거한다. 복구는 이번 UI/helper 변경만 되돌리며 서버 데이터 변경 없음.

- 관련 입력 보관/계정/주문서/보드 테스트14 통과, 변경 TSX 및 helper ESLint·TypeScript 통과.
- 독립 검토에서 삭제된 상태 함수 잔여 호출 및 변경 주소와 기존 배송지역 안내 불일치를 발견. 잔여 호출 제거, 일반 지역 기본 배송비 정책과 최종지역 확인 안내로 수정. 재검토 차단 이슈 없음, 입력 보관 테스트2 재실행 통과.
- 브라우저 진입은 성공했으나 debugger 동기화 및 접근성 캡처 오류, DOM 명령 시간초과가 반복되어 PC/모바일 입력·새로고침/로그아웃 UI 검증을 완료하지 못함. helper 경계 검증과 실제 브라우저 검증은 구분한다. WB134는 in-progress(화면 검증 대기) 유지.
- 서버 API/실결제/재고 변경 없음. 전체 API 회귀 생략. 다음: 브라우저 연결 복구 후 동일탭 복원·주소선택·비활성 결제버튼·모바일 넘침 확인 후 완료 판정.
