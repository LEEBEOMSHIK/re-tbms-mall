# 내부 관리명·고객 표시명 및 카테고리 검증

2026-10-26 / WB15 / R03·R18·R31·R32
계획: docs/superpowers/plans/2026-10-26-product-names.md

## 구현·책임

inventory_api는 services/api/app/inventory.py와 tests/test_inventory.py·test_product_naming.py를 수정했다. inventory_ui는 apps/web/src/lib/catalog.ts, tests/catalog.test.ts와 catalog 폼·목록·공통 화면을 수정했다. inventory_review가 별도 소스 검토와 실행 검증을 수행했다. 조정 담당은 백업·통합 브라우저·문서·작업 보드를 담당했다.

고객 표시명은 기존 name 필드를 유지한다. 내부 관리명은 서버가 카테고리 코드+최소 6자리 순번으로 발급한다. 카테고리별 카운터와 상품 저장은 BEGIN IMMEDIATE 트랜잭션에서 처리한다. 분류 또는 고객 표시명을 수정해도 내부명은 그대로다. 카테고리는 API 제공 select이며 내부명 직접 입력이나 자유 분류 입력을 서버가 거절한다.

## 검증 결과

- 독립 API: 전체 pytest 93개 통과. v1→v2 이관, 원래 이름·버전·UUID·옵션·원장 보존, 이관 도중 실패 시 DDL/데이터 롤백, 알 수 없는 스키마 보호, 4개 스레드 번호 발급 유일성, 카테고리별 순번·재시작·삭제 후 번호 미재사용·6자리 초과, 고객명/분류 변경 시 내부명 유지, 요청 조작과 미등록 분류 거부를 검증했다. 기존 재고 경계/실패/동시성 테스트 포함.
- 독립 웹: npm test 31개 통과, npm run lint·typecheck·build 모두 exit 0. 분류 참조 무결성, 두 이름의 응답 파싱, 레거시 분류와 원래 발급 접두사 유지, 재고 재시도 테스트 포함.
- 검토 중 영어 ID처럼 보이는 기존 자유 분류를 표준 표시명으로 바꾸는 문제가 발견됐다. 기본 한국어 분류명과 정확히 일치할 때만 연결하고 tops/TOPS 등은 각각 원문을 보존하는 이관 분류로 수정했다. 최종 93개 테스트에 해당 회귀가 포함된다.
- Edge 실제 로그인 및 웹 중계 catalog v2 조회 성공. 실제 DB user_version=2 확인, 이관 전 백업과 기존 products의 원 필드 및 skus/movements 전체 행이 같은 것을 확인했다. 이번 로컬 DB는 앞선 합성 데이터 정리 후 상태이며, 비어 있지 않은 DB의 이관 보존은 API 테스트에서 별도 검증했다.
- 브라우저 쓰기는 실제 상품 번호를 소비하지 않도록 분리된 모의 API 응답으로 검증했다. 카테고리 select와 레거시 선택지, 읽기 전용 내부명, 저장 전 코드-자동 생성 안내, 422 입력 보존, category_id만 전송, 서버 응답 내부명 표시, 목록 두 이름, 고객명/분류 수정 후 내부명 유지, 옵션 대상 선택의 두 이름 표시를 확인했다. 목록/등록/수정을 320·390·1440px로 확인해 문서 가로 넘침과 JavaScript 오류 없음. 모바일 캡처 시각 검토 완료.
- 최초 브라우저 실행은 Next 경로 안내의 alert와 앱 alert가 중복 선택되어 실패했다. 테스트를 main 내부 alert로 한정한 뒤 전체 통과했다. 제품 코드 오류로 오인하지 않았다.

## 제한·복구

백업: .local/catalog-before-v2-20261026-010319.sqlite3. 해당 파일과 테스트 도구/캡처는 Git 제외다. v1 코드는 v2 DB를 지원하지 않으므로 API 중지 후 현재 DB도 백업하고 호환 코드/백업을 함께 복구한다. v2 이후 등록분을 버리지 않도록 별도 보존/재적용한다. 자동 다운그레이드·DB 삭제는 제공하지 않는다.

초기 카테고리는 시작용이다. 카테고리 관리 UI, 고객 상품 게시, 운영 DB, 개인 계정, 실결제는 후속/미정이다. 내부명 접두사는 최초 발급 분류를 뜻한다. 기존 상품의 등록 시각이 없어 이관 순번은 rowid 순서를 사용한다. 스크린리더 전면 인증·운영 성능 부하·외부 연동은 미실행이다. 새 의존성·Docker·커밋/푸시·배포 없음.
