# WB165 · 미결제 주문 직접 취소

R111 / WB162 후속. 고객이 자신의 결제 대기 주문 상세에서 취소를 확인하면 서버가 주문·결제·출고·확보 상태와 기한을 재확인한다. 실결제 취소나 환불은 별도 PG 계약 범위다.

담당은 주문 서비스, 고객 화면과 프록시, 통합 및 독립 검증으로 구분한다. 수정 대상은 sales_orders, order_reservations, 고객 요청 프록시·주문 상세·테스트·디자인 시스템·관리자 가이드 sales-orders·작업 보드다. API 계약은 docs/contracts/sales-orders.md에 기록한다.

수용 기준은 같은 트랜잭션에서 확보 해제와 기록 확정, 즉시 재구매 가능한 수량, 중복/기한 직전·정각 처리, 인증·소유권·결제 결과 미확정 차단, 관리자 원인 구분과 실제 고객 화면 확인이다. 합성 데이터와 격리 DB에서 검증한다.

## 검증 결과 · 2026-11-04

- 구현 테스트는 단일 주문의 취소·조회 경합, 599.999/600/601초, 출고 준비·결제 결과 불명확·타 고객·미인증 차단, 원인이 확인되지 않은 기존 종료 주문을 다뤘다. 기존 주문과 함께 42개 통과.
- 독립 검증 역할이 이후 주문 시작 포함 API 44개를 임시 DB에서 실행했다. 실제 HTTP로 동일 키 취소를 두 번 보낸 결과 요청 기록 1개, 취소 이력 1개였다. 물리 보유 수량·SKU 버전·수동 재고 원장과 다른 주문 상태에 변화가 없었다.
- 실제 Next·FastAPI·별도 합성 계정 주문으로 모바일 확인→취소 실행→서버 200→완료 제목 포커스 및 관리자 동일 주문 원인 확인. 타임아웃, 응답 실패 후 같은 키 재시도, 계정 전환 중 지연 응답 무시와 경계 만료 완료 안내는 합성 응답 브라우저 테스트로 확인. 완료 화면의 중복 안내를 제거한 뒤 재진입 시 이력이 유지되는 것도 확인했다. 웹 전체 테스트 230개, 타입·관련 ESLint 통과.
- 관리자 주문 가이드 sales-orders에 해제 사유 단계와 실제 인증 캡처/표식 추가. 증거 .local/wb165/edge-customer-confirm-mobile.png, edge-customer-cancelled-mobile.png, edge-admin-cancelled.png, edge-admin-expired.png 및 apps/web/guide-assets/sales-order-release.jpg.
- 복구 시 신규 취소 경로를 차단하고 취소 요청·주문 이력은 보존한다. 실제 PG 승인 후 취소와 환불, 준비 이후 관리자 취소 요청 처리는 별도 작업이다.
