# WB218 재고 가용 수량
요구 R107/R111. 기존 주문 확보 서버 계산을 관리자 조회에 노출한다. 담당: API·UI 구현 및 별도 검증자.

## 설계 및 계약
관리자 CatalogStore.get의 같은 읽기 트랜잭션에서 SKU와 held_quantities를 읽는다. reserved_quantity는 미만료 확보 및 결과 미확정 등 해제되지 않은 보호 수량이다. available_quantity=max(0,on_hand-reserved_quantity). 단일 일괄 쿼리를 사용한다. DB 변경 없음.
표 수량 셀은 판매 가능 큰 숫자, 보유·주문 확보 작은 숫자 순서로 구성한다. 사용 중지/미게시도 수량 자체는 유지하며 실제 판매 노출을 의미하지 않음을 안내한다. 부족 알림은 기존 보유 기준 유지.
기존 개별 SKU 쓰기 응답에는 두 필드가 없을 수 있어 타입은 선택 속성이다. 필드 쌍·정수·공식을 검증하며 누락은 0으로 추정하지 않고 조회 필요로 표시한다.

## 수용·검증 계획
격리 DB에서 확보 전/후, 취소, 만료 직전/정각, 결과 미확정 만료 후 계산 검증. 브라우저 합성 응답으로 PC/390/320 및 0·일부확보·전체확보·누락 비교. 기존 재고 쓰기나 PG 변경 없음.
가이드 inventory:0 설명·캡처 동기화. 복구는 WB218 코드·문서 변경만 되돌림, 데이터 영향 없음.
