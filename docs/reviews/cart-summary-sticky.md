- 현황: PC1440×900 다품목에서 top24px 고정 정상, 높이650px 이하에는 static으로 해제. 현재 고객 헤더는 static이다.
- 구현: PC 2열(901px 이상)에서 요약 높이를 관찰해 viewport보다 긴 요약은 아래까지 읽은 후 하단24px 기준으로 고정한다. 작은 요약은 상단24px 기준. 부모 상품 영역 끝에서는 멈춘다. 별도 내부 스크롤이나 스크롤 이벤트별 React 렌더링은 추가하지 않는다.
- 모바일/태블릿 900px 이하: 본문 요약은 문서 흐름 유지, 기존640px 이하 하단 결제바 유지.
- 계약/의존성: API·금액·재고·인증·경로 변경 없음, 신규 패키지 없음. 기존 장바구니 합성 fixture로 검증.
- 수용/검증: 1개/다품목, PC900/600 높이, 중간·끝 스크롤, 리사이즈, 큰글씨, 모바일390/320의 본문·CTA·가로 넘침·안내 모달을 확인한다.
- 가이드 영향 없음: 고객 장바구니 위치 동작만 변경하며 관리자 메뉴·절차·표식 변경 없음.

## 자체 검증 (2026-11-05)

- Chrome 합성8행 PC1440×900: scrollY450/650 모두 요약 y24px 유지. PC1440×600: 높이581.84px 카드의 y−5.84px, 하단576px(화면 아래24px) 유지. PC1024×700도 y24px 유지.
- 부모 끝까지 스크롤 시 상품 영역 아래로 넘지 않고 푸터와 겹치지 않는다. 단품은 부모 높이 안에서만 고정되는 정상 동작. 리사이즈와 큰글씨로 카드 높이가 바뀌어도 새 고정 시작점 반영.
- 모바일390×844/320×740: 본문 요약 static·하단 결제 버튼 viewport 안 유지, 가로 넘침 없음. 모든6조건에서 구매 안내 모달 열기/ESC 닫기 통과.
- `.local/wb205-before.cjs` 기존 배치 측정, `.local/wb205-check.cjs` 최종 브라우저 검증 종료0. `.local/wb205-sticky-1440x900-8.png`, `.local/wb205-sticky-1440x600-8.png`, `.local/wb205-mobile-390.png` 실제 화면 시각 확인.
- `npm run typecheck`, `npx eslint src/components/customer-cart.tsx` 종료0. 장바구니 계산·선택/가이드·보드 테스트18 통과. 가격·재고·API 로직 변경 없으므로 전체 서버 테스트는 재실행하지 않았다.
