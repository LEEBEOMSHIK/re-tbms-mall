# 상품 삭제와 목록 작업 검증

2026-10-26 / WB25 / R37
계획: docs/superpowers/plans/2026-10-26-product-delete.md

inventory_api는 삭제 모델/트랜잭션/API/CORS와14개 검증을 추가했다. inventory_ui는 목록 작업 버튼·삭제 모달·목록 동기화를 담당했다. 조정 담당은 BFF DELETE/응답 파서·웹 계약 테스트2개/문서/실제 브라우저를, inventory_review는 독립 검토 및 실행을 담당했다.

독립 API118개·웹35개, lint·타입 검사·프로덕션 빌드 통과. API는 인증, strict version의bool/string/float/음수/범위/추가필드 거절, stale/missing, SKU연결(재고0/원장 포함) 차단, 번호 재사용 방지와 재시작 보존, 삭제 대 SKU생성/상품수정 경합을 분리된 임시 DB에서 검증했다. 운영/실제 로컬 상품을 삭제하지 않았다.

BFF 브라우저 검증(.local/product-delete-bff.cjs)은 존재하지 않는 임의UUID만 대상으로 세션401, 외부/누락Origin403, 잘못된version422, 없는상품404를 확인했다. 전체 catalog의 전후 일치를 비교했다. 처음에는 로컬 uvicorn reload가 멈춰405를 반환했으며 확인된 쇼핑몰8100 프로세스만 재시작한 뒤 전체 통과했다. 다른 프로젝트 프로세스는 변경하지 않았다.

UI 모의 검증(.local/product-delete-ui.cjs) exit0: 수정/옵션 링크, 취소 시요청0, 연결SKU 재고0도삭제차단,409/503후행유지와취소/재열기에도재삭제차단,최신조회후버전갱신,중복클릭한번요청,삭제확정후조회503에도행제거와삭제완료/조회실패구분을 확인했다. 최대글자크기로320/390/1440px패널경계/페이지넘침과포커스복귀를 확인하고1440목록·390확인창캡처를 직접 검토했다. 초기 mock데이터의 내부명 중복으로 파서가 거절한 테스트 준비 오류를 고친 뒤 재실행했다. UI쓰기 요청은 모두 mock이었다.

요구/API/결정/디자인문서를 갱신했다. 현재는 옵션 미연결 상품만 삭제하며 연결상품 보관·복원·일괄삭제는 구현하지 않았다. API/스키마 마이그레이션은 없고 코드 복구는 이번 변경을 되돌린다. 사용자가 실제로 삭제한 상품은 UI되돌리기가 없으므로 데이터복구에는 별도백업이 필요하며 번호 카운터를 낮추지 않는다. 커밋·푸시·배포 없음.
