# WB177 디자인 시스템 사용처 색인 조사

2026-11-04 · R109 · 관리자 디자인 시스템

## 범위와 결과

관리자 디자인 시스템의 사용처 색인은 공통 UI, 고객 쇼핑·계정, 관리자 상품·재고·주문, 관리자 사이트·제작·프로젝트, 공장 포털의 다섯 그룹을 제공한다. 업무 32개마다 원본 경로와 대표 열람 경로를 표시한다. 코드상 사용처와 조작 조건을 기록하며 시각 검증은 갤러리 통합 검증에서 별도로 기록한다.

| 조사한 영역 | 대조 결과 |
|---|---|
| `apps/web/src/components/**/*.tsx` | 46개 중 사용처가 확인된 45개를 색인화했다. 8개 공통 UI 모듈의 개별 export와 호출 예를 확인했다. |
| `apps/web/src/app/**/*.tsx` | App Router 페이지 96개에서 공개·고객·관리자·공장 경로를 조사했다. 페이지·레이아웃·갤러리 자체를 제외한 경로 전용 TSX 42개가 모두 색인 원본에 포함된다. |
| `apps/web/src/features/**/*.tsx` | 의류 시안의 목록, 편집기, 재질 정보, 스튜디오, 3D 미리보기 TSX 5개 모두 포함한다. |
| 스타일과 복합 화면 | 공통 토큰, 관리 목록 스타일, 푸터를 포함한 대표 스타일 원본을 기록했다. 각 컴포넌트가 import하는 세부 CSS와 재질 계산·API 클라이언트 같은 비표시 모듈은 해당 원본에서 추적한다. |

## 검증

- `apps/web/src/app/admin/(protected)/design-system/pattern-index.tsx`의 원본 경로 97개가 실제 파일로 존재함을 확인했다. 고정 열람 경로 28개를 App Router 페이지 목록에서 경로 그룹을 제거한 URL과 대조했다. 누락 경로는 0개다.
- 공통 디렉터리, 경로 전용 컴포넌트, 기능 전용 TSX 파일 목록의 집합 차이를 검사했다. `components/api-status.tsx`는 API 연결 진단용 export가 있으나 현재 화면에서 호출하는 곳을 찾지 못해 사용처 링크를 만들지 않았다.
- 해당 TSX 파일을 웹 프로젝트 ESLint로 검사해 통과했다. 색인 열람은 데이터 쓰기, 세션 생성, 외부 서비스 호출을 직접 실행하지 않는다. 링크는 실제 목록·소개·설정·합성 미리보기부터 시작하며, 탐색 전 네트워크 요청을 줄이기 위해 링크 prefetch를 껐다.

## 남은 범위와 갱신 방법

실제 계정의 주문 취소·재고 확보, 소셜 로그인, 주소 검색 업체의 팝업, 수령·검수·발송, 이미지 게시 및 WebGL 렌더링은 세션·기록·외부 서비스·브라우저 조건에 의존한다. 색인은 진입 위치와 조건을 제공한다. 모든 상품·모든 주문 상태의 화면 캡처나 해당 업무의 정상 처리까지 이번 경로 대조에서 검증한 것은 아니다.

공통 컴포넌트·라우트·시안 편집기가 바뀌면 사용처 색인의 해당 업무에서 원본과 열람 경로를 함께 갱신한다. `rg --files apps/web/src/components apps/web/src/app apps/web/src/features -g '*.tsx'`로 신규·이동 파일을 확인하고 원본 존재, 고정 page 경로, 권한 조건을 다시 검증한다. 중복되는 page 래퍼와 개별 유틸리티는 같은 업무의 대표 사용처로 묶는다. 운영 기능이나 외부 제공자가 추가된 경우 합성 예시의 범위와 실화면 검증 기록도 별도로 갱신한다.
