# WB146 상세 필터 접기·펼치기 및 추가 조건 검토

- 요구 R111, 사용자 요청: 상세 필터를 열고 닫고 빠진 조건 검토. 담당 root/독립 customer_account_review. 변경 admin-order-search.tsx, sales-orders.css, admin-guide/captures, 디자인 문서·보드.
- 기본 검색 대상·검색어·검색/초기화는 유지, 기간·3종 상태만 기본 접힘. aria-expanded/controls와 hidden으로 숨긴 입력의 탭 접근을 제외. 날짜 범위는 적용 조건1개로 세며 상태별1개씩 센다. 접기 동작은 필터를 해제하지 않는다.
- 실제 Chrome 127.0.0.1:3100: 기간 적용6건→접기→날짜값/결과 유지·1개 적용 확인. 역전 날짜를 접은 뒤 검색하면 펼쳐 오류 안내 확인. 부분 입력 native invalid는 onInvalid에서 펼치고 포커스를 복원하도록 보완했으며 부분날짜 자체는 도구 키 입력으로 재현되지 않아 코드 검토 근거로 남긴다.
- 앱 내 브라우저 연결 오류로 이미 열린 동일 주문관리 Chrome 탭에서 검증. 신규 DB/API 변경 없음. 복구는 UI 변경 되돌림.

## 추가 필터 후보 — 이번에는 검토만, 미구현

| 우선순위 | 후보 | 이유와 데이터 조건 |
|---|---|---|
| 높음 | 실제/합성 주문 | 현재 is_demo 존재. 운영 목록에서 테스트 자료를 제외/분리하는 데 필요. 현재 기본 조회는 기존처럼 전체 유지 |
| 중간 | 총 주문금액 최소~최대 | grand_total 존재. 고액 주문 점검 등에 사용. 취소/환불 후 실수납액과 구분해야 함 |
| 중간 | 송장 등록 여부·송장번호 | shipments 존재. 발송 레코드와 송장 존재는 출고 완료와 다름. 여러 발송 건 중 하나라도 없는지/모두 없는지 기준 정의 필요 |
| 중간 | 색상·사이즈 또는 SKU | 주문행 사본 존재. 상품명만으로 옵션을 구분하기 어려운 경우 유용. 서로 다른 행의 조건이 섞이지 않게 같은 주문행 기준 필요 |
| 후속 | 취소·반품·교환·환불 진행 | 현재 클레임 데이터/처리 기능 미구현. 단순 cancelled 필터로 대체하지 않음 |
| 후속 | 결제수단·PG | PG 선정 및 결제 데이터 연동 후 가능 |
| 후속 | 출고 지연·결제완료일·배송완료일 | 현재 필요한 상태별 기준시각 없음. created_at만으로 지연 판정 금지. 영업일·기준시각 계약 필요 |

최종 독립 코드검토 차단 이슈 없음. 새 가이드 이미지/원문은 반영했으나 브라우저 도구 중단으로 가이드 최종 렌더 시각 재검증은 남아있다. 작업 보드는 verification 유지.
