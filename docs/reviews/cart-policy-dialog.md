# WB201 · 장바구니 배송·교환 안내 모달

- 요구 R107/R111. 목적: 안내를 확인해도 장바구니를 떠나지 않고 구매를 이어간다.
- 담당: root 구현/통합, hold_ui 독립 검증. 선행 WB200.
- 계약: 배송비는 기존 cart.shipping_policy를 표시. API·금액 계산·주문 경로·데이터 저장 변경 없음. 기존 확정 R111 정책을 안내하며 접수 기능을 새로 제공하지 않는다.
- 설계: 기존 native dialog 방식. PC 중앙 42rem, 모바일 하단 최대90dvh, 본문만 스크롤하고 제목/닫기/확인 고정. ESC·바깥영역·닫기·확인으로 종료하며 원래 버튼에 초점 복귀. 선택/수량/금액/URL 보존.
- 수정: customer-cart.tsx, cart-layout.module.css, purchase-guidance-dialog.tsx/module.css, lib/purchase-guidance.ts, app/policies/[slug]/page.tsx. 정책 페이지는 같은 원문을 사용해 오래된 '정해진 배송 조건 없음' 안내를 제거한다. 신규 의존성 없음.
- 수용·검증: PC1440/모바일390/320에서 두 모달 열기/본문 스크롤/닫기, 제목 초기초점·ESC·Tab·opener복귀, URL·선택·수량 보존 및 선택 주문서 진입 통과. 390x667 다크·동작줄이기 및 공개 두 정책 페이지 확인. 타입·수정파일 ESLint, 장바구니 관련/보드21 테스트 통과.
- 가이드 영향 없음: 고객 장바구니와 공개 안내만 변경. 관리자 메뉴·버튼·업무 순서·가이드 캡처는 영향 없음.
- 복구: WB201 관련 변경만 되돌린다. 기존 미커밋 변경과 사용자 데이터는 보존. 운영 배포·실결제 없음.

## 실제 검증 · 2026-11-05

로컬3100 실제 Chrome에 합성 장바구니 응답을 주입해 확인했다. `.local/wb201-check.cjs` 1440/390/320 모두 통과, `.local/wb201-dark.cjs` 다크/짧은높이/공개 페이지 통과. 선택을 일부 해제하고 수량을 2개로 변경한 뒤 두 모달을 반복해서 닫아도 체크·수량이 동일하며 선택 SKU로 주문서에 이동했다. 서버 가격/재고 정책은 변경하지 않았다.

독립 검증자는 X·ESC·확인·배경 클릭으로 종료, 초점 복귀, 추가 API 쓰기 0건, 320/390/짧은 PC 본문 스크롤과 고정 헤더·푸터, 정책 기록 일치를 확인했다. 최초 개발 StrictMode에서 effect 정리가 close 이벤트를 발생시켜 즉시 닫히던 결함을 재현하고 정리 시 close 호출을 제거하여 독립/통합 재검증했다. 치수 검사는 열림 애니메이션 종료 후 측정했다.

캡처: `.local/wb201-shipping-1440.png`, `.local/wb201-returns-390.png`, `.local/wb201-returns-dark-mobile.png`. 고객 개인정보·실제 배송지 없음. 최종 판정: 통합 완료(root). 가이드 영향 없음 기준은 위와 같다.
