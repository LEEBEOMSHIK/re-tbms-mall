모바일<=767px에서 입력 및 선택그룹은1열로 전환한다. 데이터표는 내부스크롤 예외다. 본문 자체 최대1320px는 유지한다. 폭 관련 opt-in 클래스와 라벨/입력 묶음만 조정하고 submit/state/retry/API/DB는 변경하지 않았다.

## 실행 검증

Edge+합성 조회에서 등록·수정 16개 경로를1440/768/390px 및 라이트/다크+확대글꼴로96조합 확인했다. wide패널과 본문너비 차이2px미만, compact760px이하, 모바일grid1열, 문서overflow없음. SKU색상/사이즈를 선택해 조합표가 있는 상태도 확인했다. 각 필드 라벨→입력 실제 간격8px이상 측정 및 공급처 전체폭 시각 확인.

상품수정·진열저장 실패시 입력보존을 모의응답으로 확인했다. 별도 공급처 시나리오에서 등록/수정완료·값복원·빈값삭제·422입력보존 및 그룹/필드간격·다크·확대글꼴을 다시 확인했다. 실제데이터 쓰기 없음.

독립 웹61개 테스트, lint(경고0)·typecheck·production build 모두 exit0. 작업 보드 파서5개 통과. API·DB가 변하지 않아 백엔드 테스트는 반복하지 않는다. 모든 화면의 전체 접근성·모든 브라우저를 인증한 것은 아니다.
