# 상품 홈·진열 관리 검증 기록

상태: 완료 / 2026-10-25
계획: [작업 계획](../superpowers/plans/2026-10-25-category-storefront.md)

## 역할 및 결과

- storefront_api: 샘플 상품·진열 API, 인증·검증·파일 저장 및 테스트 구현.
- storefront_web: 상품 중심 홈, /about, 진열 관리 UI, 12개 상품 SVG와 클라이언트 테스트 구현.
- storefront_review: 독립 소스 검토 및 API 44개·웹 10개 테스트 통과. lint, 별도 typecheck, production build 모두 종료 코드 0. 차단 결함 없음.
- 조정 담당: 로컬 관리 키 생성·setup 연동, 요구/API/디자인 문서 정합성, 실제 Edge 브라우저 통합 검증.

## 브라우저 검증

- 기본 5개 섹션과 12개 상품, 카테고리 선택 시 해당 분류 상품만 노출.
- 상품 상세 dialog 열기·Escape 닫기·원래 카드로 포커스 복귀.
- About 이동 및 /about 제목 표시.
- 320·390·1440px 고객 화면 가로 넘침 없음. 390px 관리자 화면 가로 넘침 없음.
- 전체 상품 이미지 로딩 성공. 고객 화면의 개발 상태/API 설명 제거.
- 잘못된 관리자 키 거절, 올바른 키로 진열 로딩.
- 시즌 기획전 추가·상품 선택·상품 순서 변경·섹션 순서 변경·기존 섹션 비공개 후 저장 성공.
- 저장 revision 증가 및 공개 홈의 제목·상품 순서·비공개 반영 확인.
- 브라우저 localStorage/sessionStorage에 키 저장 없음.
- 상품 API 실패 시 고객용 안내와 다시 보기 성공. 페이지 JavaScript 오류 없음.
- 테스트 종료 후 revision 충돌 여부를 확인하고 원래 샘플 섹션 복구.

## 제한과 인수인계

- 기본 분류와 상품 자체는 고정 샘플이다. 관리자가 추가·편집하는 대상은 카테고리형/시즌·기획전형 진열 섹션이다.
- 실제 상품 등록·재고 변경·회원 권한·주문·결제는 이번 범위에 없다.
- 로컬 키 인증과 .local/storefront.json 저장은 단일 API 프로세스용이다. 운영 인증/DB/다중 프로세스 지원은 후속 작업이다.
- .env 및 .local 저장 파일은 Git 제외 확인. 관리 키를 로그·문서에 기록하지 않았다.
- README의 admin-key.ps1 -Show 명령으로 본인 터미널에서 접근 키를 확인한다.
- 별도 브라우저 검증 스크립트와 캡처는 작업 환경의 검증 산출물이며 프로젝트 테스트 의존성은 추가하지 않았다.
