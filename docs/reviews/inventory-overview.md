# WB43 공급처·재고 현황 검증

- 요구: R53 / 날짜: 2026-10-26
- 구현: inventory_api(서버), inventory_ui(현황), 조정 담당(공급처 화면·계약·통합)
- 독립 검증: inventory_review
- 계획: docs/superpowers/plans/2026-10-26-inventory-overview.md

## 결과

현재 보유 재고를 기본 보기로 제공하고 입고/출고/조정·기존 기록을 분리했다. 상품명·내부명·색상·사이즈, 입고누계·판매/기타출고·조정·현재량·부족상태를 표시한다. 검색과 공급처별 입고 필터 및 조회 수량 합계를 제공한다. 현재량은 SKU.on_hand를 기준으로 하고 원장 누계로 재계산해 대체하지 않는다.

공급처 목록/등록/수정은 별도 URL이다. 신규 입고 화면은 활성 공급처 선택이 필수다. 과거 입고처명은 snapshot으로 보존하고 미기록을 추정하지 않는다. 서버의 null 허용은 구클라이언트와 옵션 초기입고 호환용이다.

## 검증 증거

- 독립 API 202개, 웹 55개 테스트 통과. 공급처 중복·권한·활성·이름 snapshot·재시도·이관과 집계 경계 포함.
- 독립 최종 lint/typecheck/production build 모두 exit 0. 작업 보드 파서 5개 통과.
- Edge 모의 API 브라우저: 현재량과 누계, 입고처 필터·미기록 조회, 출고 조회, 입고처 필수 선택, 선택 메모, 503 후 공급처 비활성화·재조회·동일 요청 재시도, 확정 원장 결과, 공급처 별도 등록/완료 화면 확인.
- 320/390/1280px 문서 가로 넘침 없음. 표는 내부 스크롤을 사용한다. 시각적으로 현황이 등록 바로가기보다 먼저 노출되는 것을 확인했다.
- 독립 검토에서 발견한 비활성 공급처의 동일 요청 재시도 차단을 수정하고 브라우저 재현 통과. 신규·변경 요청은 계속 활성 공급처만 허용한다.
- 공급처 BFF 경로 ID 검증과 응답 ID 일치 확인 추가.
- 로컬 FastAPI 자동 재시작이 반영되지 않은 상태를 확인해 해당 프로젝트 서버만 재시작했다.
- 실제 schema5 백업 후 schema6 적용 확인. products/skus/movements의 모든 이전 컬럼과 request_payload가 백업과 동일하다. FK 검사와 integrity_check 통과, 이전 공급처 필드는 모두 null. 실제 공급처·재고 테스트 쓰기는 하지 않았다.
