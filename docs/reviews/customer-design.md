## 범위와 방법

고객 검색 상시 표시, 상세 필터 기본 접힘, 적용 조건 표시·해제, 검색·컬렉션 문맥 유지, 이미지 중심 고객 디자인과 관리자 스타일 분리를 검증했다. 실행 중인 로컬 Next.js에 Edge Playwright로 접속하고 고객 API만 합성 31개 상품 응답으로 대체했다. 이미지는 저장소의 `public/images/products/p001.svg`~`p012.svg`를 사용했다. 실제 상품·재고·게시 데이터 쓰기는 0건이며 결제 기능을 검증 범위에 추가하지 않았다.

## 실행 결과

- `.local/wb89-review.cjs`: 정상 종료. `.local/wb89-review.json`에 실측 결과 저장. 브라우저 예외 0건, 쓰기 요청 0건.
- 최초 진입 및 조건이 있는 직접 URL 진입 모두 상세 필터 접힘. 검색은 표시되고 숨긴 패널의 입력은 DOM에서 제거되어 키보드 탐색 대상이 아님.
- 필터 버튼의 aria-expanded/aria-controls, 6개 콤보박스의 접근 가능한 이름 확인. Enter로 열기, 콤보박스에서 Escape 시 팝업만 닫힘, 다음 Escape 시 패널 닫힘 및 필터 버튼으로 포커스 복귀 확인.
- 색상 조건 제거 후 검색어·컬렉션·나머지 조건 보존, 첫 페이지 복귀 확인. 전체 필터 초기화 후 검색어·컬렉션 유지 확인.
- 페이지 2에서 페이지당 24개로 변경 시 첫 페이지와 24개 카드 표시 확인.
- 같은 SKU 조합 검증: 레드/M/재고 있음은 0개, 레드/S/재고 있음은 30개. 서로 다른 옵션의 조건을 합쳐 잘못 노출하지 않음.
- 검색 제출 시 기존 색상 조건 유지, 상품 상세 이동 후 목록 복귀 시 검색 조건 유지 확인.
- 독립 실행 `node --test tests/storefront.test.ts tests/public-catalog.test.ts`: 8개 통과, 실패 0개. API 구현 변경 없는 작업으로 서버 테스트를 반복하지 않음.
