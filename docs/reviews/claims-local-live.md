- 가이드: 기존 claims/sales-orders 경로를 실제로 확인한다. UI 변경 계획 없음.

## 실행 결과

- 현재 고객 주문 목록에 표시된 기존 합성 주문의 소유자에게 신규 합성 주문 2건 추가. 계정 ID/개인정보를 문서나 캡처에 기록하지 않았다.
- 반품 주문 `20261107-GN4AXU6Y8B`: 니트 S 2개 중 1개 신청, 고객 접수→관리자 검토→회수 대기.
- 교환 주문 `20261107-RE3MHYH3HY`: 데님 S 2개 중 1개를 M으로 교환 신청, 고객 접수→관리자 검토 중.
- 양쪽 모두 추가 신청 가능 수량 1개를 남겼다. 기존 주문/재고/배송지 주소록은 수정하지 않았다.
- 독립 검증: SQLite integrity_check ok, 기존 주문 6건 및 품목/주소/출하/이벤트/번호 할당 모든 열이 백업과 동일. SKU 33개 전체 행 동일. 신규 주문 is_demo=1·동일 계정 소유·수량 2, 유효 접수 1. 접수 2건·멱등 요청 5건·상태 이력 정상.
- 사용자 경로: 내 계정→주문 내역→주문 상세→반품·교환 신청. 상품/유형/수량/교환 옵션/수령일/사유/회수주소 입력 후 접수. 주문 내역의 반품·교환 내역에서 진행 상태 확인.
- 관리자 경로: 운영→주문 관리→반품·교환 내역→상세→접수 처리. 다음 처리와 고객 안내 내용을 저장하며 고객 상세에 표시된다. 실제 경로 이동과 저장 결과를 확인했다.
- 가이드 영향 없음: 기존 claims/sales-orders 안내와 실제 진입/처리 절차가 일치하며 UI·계약 변경 없음.

## 증거와 제한

실제 3100 화면 캡처: `.local/wb230-customer-success.jpg`, `.local/wb230-customer-list.jpg`, `.local/wb230-customer-detail-pc.jpg`, `.local/wb230-admin-list.jpg`. 합성 자료만 포함한다. 이번 검증은 PC 실제 세션에서 수행했다. 모바일 viewport 요청은 관측 폭이 1600px로 유지되어 모바일 재검증으로 인정하지 않았다(이전 WB229 합성 모바일 검증과 구분).

백업 `.local/wb230-before-claims.sqlite3.bak`, 신규 주문 식별 목록 `.local/wb230-orders.json`, 일회성 삽입 스크립트 `.local/wb230-seed.py`는 비공개 로컬 보존. 전체 DB 복원은 후속 변경을 잃을 수 있으므로 자동 실행하지 않는다. 정리 필요 시 이 작업의 신규 주문/접수만 식별하여 별도 승인·백업 후 처리한다.
