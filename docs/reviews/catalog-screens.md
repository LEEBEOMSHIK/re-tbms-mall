# 상품 관리 화면 분리 검증

2026-10-26 / WB14 / R03·R18·R29·R31
계획: docs/superpowers/plans/2026-10-26-catalog-screens.md

## 변경 및 분담

inventory_ui: catalog-manager.tsx, catalog-list.tsx, catalog-forms.tsx, catalog.css와 목록·상품 등록·옵션 등록·수정·재고 변경 페이지. 조정 담당: admin-navigation.tsx의 하위 페이지 메뉴 표시와 README·요구·결정·디자인·작업 보드. inventory_review: 별도 소스 검토 및 웹 검증.

목록 /admin/catalog에는 양식이 없고 상품 목록·색상/사이즈별 재고·이력을 표시한다. /new는 상품 등록, /options/new는 색상·사이즈 등록, /[id]/edit는 수정, /inventory는 재고 변경이다. 기존 SKU 코드의 화면 명칭은 옵션 관리 코드로 바꿨다. 등록이 고객 게시를 뜻하지 않는다는 안내를 유지한다. 등록 성공 후 목록 확인 또는 다음 단계 링크를 제공하며, 옵션 등록은 선택 상품을 미리 채운다.

## 실행 근거

- 독립 검증: apps/web에서 npm test 29개 통과, npm run lint·typecheck·build 모두 exit 0. 신규 4개 페이지가 빌드에 포함됐다.
- 소스 검토: 모든 새 페이지 requireAdminSession, async params/searchParams, 없는 수정 대상의 양식 미표시, 상품 수정 버전 갱신과 명시적 충돌 복구, 옵션 query 변경 시 key 초기화, 재고 같은 요청 재시도 보존 확인. 차단 이슈 없음.
- Edge: 신규 4개 경로 미로그인 직접 접근은 로그인으로 이동. 로그인 후 목록에 form 0개, 목록→상품 등록→저장, 목록 행→상품 수정→저장, 목록 행→색상·사이즈 등록(상품 미리 선택)→저장을 실제 API로 확인했다.
- 재고 변경은 서버 저장 후 응답만 503으로 끊고 같은 내용을 재시도했다. 원 UUID·버전이 유지되고 재고 10개·원장 1건으로 중복 반영되지 않았다. 입력값 보존 확인.
- 목록·상품 등록·옵션 등록·재고 변경을 320/390/1440px에서 확인해 문서 가로 넘침 없음. 하위 화면에서도 상품·재고 메뉴 활성 표시, 쉬운 화면 용어, 없는 상품의 안내와 수정 양식 없음, JavaScript 오류 없음 확인. PC 목록과 모바일 등록 화면 캡처를 시각 검토했다.
- 브라우저 합성 상품·옵션·원장은 이름/ID/내용을 검증한 뒤 해당 테스트 행만 정리했다. 사용자 데이터와 DB 파일은 보존했다. .local/catalog-screens-smoke.cjs 및 캡처는 Git 제외다.

## 제한·복구

API·DB·업무 규칙은 바꾸지 않았다. 따라서 이번에는 백엔드 테스트를 반복하지 않았으며 이전 WB06의 API80개 결과와 구분한다. 운영 계정/고객 게시/실결제/배송 연동은 미정 또는 미구현 상태를 유지한다. 전체 스크린리더·성능 부하 검증은 하지 않았다. 등록 성공 후 자동 이동 대신 성공 안내와 목록/다음 단계 링크를 제공한다.

화면 복구는 이번 catalog 하위 페이지/컴포넌트·탐색·문서 변경만 되돌린다. DB는 삭제하지 않는다. 커밋·푸시·배포는 하지 않았다. 다음 제안 WB13(대시보드 실제 재고 연결)은 별도 미구현 작업으로 유지한다.
