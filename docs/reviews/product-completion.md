# 상품 등록 완료 흐름 검증

2026-10-26 / WB24 / R31·R36
계획: docs/superpowers/plans/2026-10-26-product-completion.md

원인은 신규 저장 후 빈 폼을 유지하면서 상단 notice만 갱신하던 흐름이다. 조정 담당의 기존 구현 스모크는 모의503 시 입력 유지까지 통과한 뒤201 성공 후 완료 제목을 찾지 못해 실패했다. 첫 스크립트의 clipped checkbox 직접 클릭은 키보드 focus/Space로 보정했으며 애플리케이션 결함과 구분했다.

inventory_ui는 정상 파싱한 서버 응답을 완료 상태로 보관하고 신규 등록 폼을 교체했다. 완료 제목 포커스/스크롤, 표시명·내부명, 해당 상품의 색상·사이즈 등록/목록 이동과 명시적 다른 상품 등록을 제공한다. 저장 중 등록 중 표시, 기존 잠금과 성공 후 가드를 유지한다. 수정 저장과 실패 처리는 보존했다.

조정 담당 Edge .local/product-completion-smoke.cjs 재실행 exit 0:503 입력 유지, 성공에만 완료 화면/폼 제거, 서버 반환명·내부명·포커스, 연속 requestSubmit 두 번에 요청 한 번, 다음 링크의 정확한 상품ID 및 옵션 화면 자동 선택을 확인했다. 다른 상품 등록은 빈 입력과 포커스를 복원하며 직접 제출 전 새 요청이 없고 재등록도 통과했다. 최대 글자 크기로320/390/1440px 가로 넘침과390px 캡처를 확인했다. 쓰기는 모의 응답만 사용했다.

기존 .local/required-select-smoke.cjs도 전체 재실행 exit 0으로 필수 선택·키보드·모바일·기존 미지정 상품 이름 수정이 유지됨을 확인했다. inventory_review 독립 소스 검토와 웹33개·lint·타입 검사가 통과했다. 프로덕션 빌드와 API 테스트는 이번 UI 변경에서 반복하지 않았다.

요구사항과 디자인 시스템에 등록 완료/후속 작업 규칙을 반영했다. 기본 정보 저장은 고객 게시나 재고 등록 완료가 아니다. 복구는 이번 UI·문서만 되돌리고 등록된 상품 데이터를 삭제하지 않는다.
