# WB130 / R111 배송 정보 관리 통합

root 구현 / 독립 검증. 사용자 승인: 별도 기본정보 수정 화면을 없애고 마이페이지 배송 정보에서 받는 분·연락처·주소를 관리한다. 기존 주소/기본지정/이름/연락처를 보존한다. 로그인 계정은 읽기 전용.

설계·범위: /account에 로그인 계정 요약 및 배송지 목록/등록·수정·삭제 진입을 통합. /account/profile 및 /account/addresses는 /account로 redirect하여 기존 링크 호환. 주소 입력 URL은 기존 new/edit 유지하고 완료/목록 복귀는 /account. 신규 배송지 수령인 정보는 기본배송지 우선, 기존 별도 저장 이름·연락처 fallback. 기존 배송지를 덮어쓰거나 연락처만 있는 데이터를 불완전 주소로 자동 생성하지 않는다. 서버/DB/API 계약 변경·데이터 마이그레이션 없음, 기존 프로필 API는 호환 용도로 유지.

수정 대상: customer-account.tsx, customer-account.ts, 고객 계정/주문서 링크 및 account 페이지, 관련 테스트/디자인 문서/보드. 수용/검증: prefill 우선순위 테스트, 기존 프로필/주소 보존, 구URL 이동, PC/mobile 등록·수정과 SaveResult/목록 복귀·기본지정, 실패 입력보존 기존 경로 유지. 관리자 가이드 영향 없음(고객 메뉴만 변경). 복구는 이번 UI/redirect/prefill 변경만 되돌리며 DB는 그대로 유지.

## 검증 결과 (2026-10-30)
- 웹 account/checkout/shipping/workboard14 통과, ESLint·TypeScript noEmit 통과. 신규 단위 테스트로 legacy 연락처 fallback, 기본배송지 우선 및 원본 객체 불변 확인. 독립 customer_account_review 코드검토 및 웹6 직접 실행 통과.
- 합성 QA PC1280/mobile390: 구 profile/list URL 모두 /account로 이동, 로그인 계정 읽기 전용 및 기존 주소2개 표시, 기본정보 수정 링크 제거 확인. 기존 legacy 이름·연락처가 새 배송지 입력에 들어오고 안내 문구 표시됨 확인.
- 기존 주소 내용 그대로 기본지정 저장, 서버 SaveResult·완료 포커스·통합화면 복귀 확인. 모바일 신규 등록에서 상세주소 누락 오류와 입력보존, 보완 후 등록3개 및 서버 주소/완료 제목 포커스 확인. 모바일 가로 넘침 없음. 증거 `.local/wb130-delivery-pc.png`, `.local/wb130-delivery-mobile.png`.
- API/DB 변경·마이그레이션 없으므로 API 전체 회귀는 재실행하지 않았다. 사용자 실제 계정 데이터에 쓰기 요청하지 않았고 격리 합성 데이터만 사용했다. 삭제/충돌 API 정책은 기존 구현을 유지하며 이번 UI 검증에서 실제 삭제·경합을 재실행하지 않았다.
- 기존 profile 보존으로 기본배송지를 모두 없앤 뒤 새 등록 시에도 과거 연락처가 보조 입력될 수 있다. 자동 삭제하지 않으며 추후 보존정보 삭제/자동입력 중지 UX는 별도 범위. 디자인 시스템·계약·요구·결정·보드 동기화. root 통합 완료 판정. 관리자 가이드 영향 없음. 커밋/배포 없음.
